# 02 卡牌正背面、角标与机制表达

UIR v2｜2026-11-13｜对应UIR-005～010、031～033、045。当前实现问题见CUR-04/05/09；完整174卡的原字段路径见[audit](audit/README.md)。本文件给出本次设计决定，所有新组件与图标尚未实现。

## 1. 费用角标与效果徽标一起重做

采用**左上组合角标**：上方圆形“笔尖/专注数值”表示花费；紧邻其下的主效果徽标表示用途。放松用折纸盾，完成量用打勾的作业页，抽牌用叠页向上箭头。让玩家扫过费用区域就能认出用途，同时保留费用与收益两个独立数值。

```text
伸个懒腰                          小步实践
圆形笔尖 1  ← 花费专注             圆形笔尖 1  ← 花费专注
盾牌     5  ← 获得放松             勾选作业 6  ← 基础完成量
                                  链环 +3 [衔接时] ← 条件收益
```

**不能把盾牌中的“1”同时当费用和防御量。** 也不能因为牌属于“策略”就一律使用盾牌：整理书包是抽/弃，今日清单是能力，必须按当前有效效果选择标识。主类型、归属、稀有度各占自己的区域。

推荐布局是在同一左侧安全带内纵向排列费用和主效果，方便扇形手牌露出；副效果在图下摘要条显示。最多两个主要效果徽标同时突出，第三项及以后使用“复合”标记并保留短文顺序，不能用“+2”隐藏必须支付的代价。无即时效果的能力牌主标为“持续/次回合”，不会显示为立即获得盾5。

## 2. 统一牌框的文字规格

以下以196×284逻辑卡面为排版提案，不直接覆盖现有168×244命中尺寸；在1280×800、960×600、10手牌实机样板验证后冻结。

| 区域 | 建议位置与职责 | 约束 |
|---|---|---|
| 顶部 | 名称区x48～180、y12～42；费用徽章中心约(23,24)、直径38 | 费用数字始终清晰；长名可两行，不能压住角标 |
| 左侧效果带 | 主徽标中心约(23,68)，30～34像素；数量附于图形内/下缘 | 盾、勾页、叠页轮廓在32像素和灰度下可分；图与数字至少有一份可读文本释义 |
| 插画 | x12～184、y48～153；左侧预留徽标安全区 | 主动作和目标不能被徽标挡住；统一裁切规则和焦点元数据 |
| 图下语义行 | y158～181：主类型短标签、目标/群体、立即/条件/持续 | 类型不靠边框颜色独自承担；目标与时间标识不混入费用 |
| 规则正文 | y184～253，建议16逻辑像素；步骤与条件分行 | 优先显示主结果、代价、目标、条件、限次；不得为保插画而截掉强制弃牌或精力代价 |
| 底部 | y260～278：消耗/保留/固有、升级等级、角色小印章 | 删除重复专注费用；非零精力等额外代价放到费用组，不能藏底部 |
| 稀有度 | 边框纹样与小印章，使用原rarity标签 | 普通、进阶、稀有有不同纹样；短扫光只在揭晓或焦点变化时出现，不永久闪动 |

小窗口普通手牌仍按可用宽度压叠，保持左侧两枚标识露出。悬停卡在独立前景层放大，底层命中区保持原位；不通过卡面动画改变扇形排序。若150%字号不能容纳，使用“展开卡面＋相邻全文栏”，保留主摘要和全部关键代价，禁止缩到无法阅读。正文是否换行由实际中文字体测量，不用字符数猜高度。

卡牌图形风格是有体积的纸边、局部投影和墨线主体；纸纹对比弱于文字。空白不是主要素材，大面积泛黄不能代替动作插画。卡框、文字、图标、插画、可用性描边和光效必须分层。

## 3. 全效果词典与边界

此表覆盖盘点中49个不同op字段值。是视觉语义映射，不是新的规则处理器；嵌套的`then`、条件、章驻留与能力触发必须保留上下文。

| 实际字段/op | 图形语义 | 数值与文案约束 |
|---|---|---|
| `complete`、`status_complete` | 打勾的作业页；持续结算加对应状态小标 | 显示完成量；多段显示“4×2段”，不能折成8；全体附三目标标记 |
| `relax` | 青绿折纸盾 | 显示放松量；自身/伙伴归属明确；不与敌方屏障混用 |
| `remove_shield` | 破开的硬质挡板 | 表示削屏障；屏障采用横条挡板形，避免与我方放松盾同形 |
| `heal`、`lose_vitality`、`partner_heal` | 心形精力标配＋/−；伙伴有头像定位 | 实际可恢复量由预览提供，上限裁切不可忽略；损失不能用绿色收益徽标 |
| `draw`、`discard`、`exhaust_other` | 叠页＋入手箭头／纸页回收箭头／缺角页消耗印 | `draw2 → discard1`保留先后与“必须/至多”；不可画成净抽1 |
| `retain`、`retrieve`、`search_draw_for_type`、`shuffle_draw` | 书签／回钩／放大镜叠页／环形页 | 标明选牌范围、数量和目标限制；查找不能暗示抽牌顺序可见 |
| `work_bonus_next`、`add_work_bonus`、`cost_discount_next` | 下一张小旗＋勾页／笔尖减号 | “下一张”“首段”“每回合一次”等必须可读；不是本卡立即伤害或立即返还资源 |
| `gain_focus` | 笔尖＋专注 | 同资源形状，收益附＋；费用保持上方圆章，不混位置 |
| `apply_status`、`remove_status`、`extend_timed_debuffs` | 对应16状态符号＋叠层/擦除/计时附标 | 状态名称、层数/持续时间和目标分别标注；状态种类不靠颜色猜 |
| `trigger_erosion`、`trigger_induced`、`arm_erosion_on_next_draws`、`modify_erosion_window` | 侵蚀裂纹／诱发括号＋触发箭头 | “触发已有状态”“后续抽牌触发”“窗口修正”不能画成新施加同层数 |
| `source_stacks` | 从源状态取值的小链标 | 这是数值表达式；未知目标时显示变量/条件，不伪造固定值 |
| `paper_open`、`change_topic`、`paper_publish` | 开卷／换标题签／发表印 | 分别表示开启、换题与发表；资格和资源条件在可用性区说明 |
| `paper_progress`、`paper_citation`、`spend_citation` | 段落进度／引号票／引号票减号 | 引用获得与支付分开；额外专注支付显示在成本组 |
| `paper_amplify`、`paper_modifier`、`publication_cost_discount` | 批注括号＋增幅/修正/折扣 | 作用时点与范围必须写明，不把长期修正合并进本次基础盾值 |
| `chapter_deploy`、`chapter_return`、`chapter_run` | 章节书签＋入槽/回手/执行箭头 | 部署≠立即执行；准备阶段与次回合标记常驻可见 |
| `copy_chapter_to_hand`、`swap_chapter_slots` | 双书签复制／双向槽位箭头 | 复制面、临时性、原章节与副本区分；调序不暗示章节已发动 |
| `gain_synergy`、`spend_synergy`、`spend_synergy_up_to`、`spend_all_synergy` | 互扣回形针＋获得/支付方向 | “至多”“全部”保留，未知支付结果不固定显示收益；不能用本卡事后获得的协同付当前费用 |
| `summon_partner`、`partner_extra_action`、`partner_retreat` | 双人剪影＋入场/再次行动/退场 | 同屏容量与替换对象显式；考试替代面切换后不能继续显示召唤主徽标 |
| `establish_scene` | 展开的校园窗框 | 建立/替换场景；考试替代时显示实际抽牌/放松 |
| `generate_card` | 纸页＋星角 | 生成卡身份和临时去向；不与从牌堆抽牌共用无区别符号 |

为16状态分别设计独立符号；本轮优先样本含焦虑、拖延、困倦、脆弱、虚弱、侵蚀、诱发。其余状态必须在全量矩阵逐项补齐，不能都退化为感叹号。每个图标在词典有同名文字和一句准确说明。

数值来自当前生产基础面，用于说明设计；精准战斗预览还需考虑运行时修正。

第一轮美术/组件样本必须覆盖上述13张，含它们的有效升级、考试及延迟触发面。全174条在CSV逐条登记“主图标、次图标、插画裁决、基础/升级/考试/触发检查、证据”，不能凭公共攻击/防御两张通过就批量推广。

数据盘点发现 `R3-C-06 今日清单` 与 `R3-P02-40 有备而来` 的顶层 `exhaust` 均为 `true`，而嵌套 `flags.exhaust` 为 `false`。本轮不替内容/规则层裁决冲突。WP-02须追到当前运行时读取点，保留字段与实际有效面的对照；展示只依据 GameSession 返回的有效卡面，不能由 UI 挑字段、更正规则，或仅凭原始 JSON 宣称实际消耗行为。

## 5. 数据与组件迁移

拟新增`CardDisplayModel`与`CardFaceView`（名称为方案，不是现有文件）。BattleCard和UiOfferCard继续承担命中、焦点、预选、快捷键和本地草稿，通过适配层共用同一牌框、插画裁切及信息布局。

数据顺序：GameSession有效面/报价 → 展示模型整理结构 → 卡面/说明/徽标。模型输出费用资源、主/副效果、目标、时点、条件、限次、去向、稀有度与升级状态；不重新执行BattleEngine，不解析自然语言去猜效果。

`ActionPreview.known_effects`不能直接等同最终数值预测。需要目标修正或条件计算且当前预览未提供时，牌面保留基础数值＋明确条件；后续如补`resolved_display_effects`，必须由规则只读预览产生，并标明确定值、范围、公式或未知，附revision/target范围。未知结果不显示假精确数字，也不消耗随机流。

有效面变化时统一刷新正文、徽标、目标箭头和成本。局外基础/升级面与战斗考试面分别标明上下文；没有考试旗标的商店不能自行展示考试效果。当前不支持的临时修正仍按引擎拒绝，不为设计造“已支持”示例。

## 6. 卡背、牌堆和插画

主卡背采用深青封面的课程手册：中央为笔尖与回形针构成的无字校内标志，四角少量纸页折角，墨线具有方向但上下旋转不暗示牌身份。所有未公开牌使用同一版背面；角色皮肤只允许整副牌同一主题，不能按隐藏牌类型/稀有度/升级状态区分。不能给下一张牌加独有光色。

抽牌堆用封闭册页，弃牌堆用翻开的回收夹，消耗堆用缺角归档袋；数量为独立文本。洗牌表现为公开弃牌收拢成统一背面后入抽牌堆；翻面只发生在规则已经公开的时点。

插画逐张判定复用/局部修订/重画。判断标准是动作、目标和结果能否支持主效果：伸懒腰画放松姿态与展开的纸盾轮廓；整理书包画挑取与放回的动作；破题追问画注释持续蚀开任务纸面；伙伴牌画协同姿态。基础动作不统一画成“学生坐在桌前”；不把被作用的任务画成被攻击的同学。数值、牌名和状态符号由引擎绘制，不能烧进AI插画。

验收必须同时检查：同牌跨战斗/商店/奖励/牌组一致、混合效果不遗漏、延迟与即时不混淆、10手牌徽标可见、32像素灰度可辨、非法费用有原因，以及减少动态后仍可完整理解。对应AC-03～05、19、25、29。
