# 03 战场实体、交互与动态演出

UIR v2｜2026-11-13。参考R2-03/04/07及R2-08的连续采样；当前代码对应CUR-06～10。新动作、时长、接口均为本作设计提案，尚未实现。

## 1. 战斗画面由五层组成

1. **场景层**：前景桌角/纸屑、中景地面、后景教室/实验室等；少量独立循环。不再在背景之上覆盖巨大的通用浅色面板。
2. **实体层**：主角、伙伴、任务敌怪具有落脚点、轮廓和局部动作。图片卡框退出主要战场；原肖像继续用于详情、选角小头像和日志。
3. **附着信息层**：每个实体对应名字、精力或剩余工作量、放松或屏障、状态和意图；信息条不随受击抖动。选中目标用地面圈与轮廓双提示。
4. **操作层**：顶栏资源/DDL、下方手牌、两侧牌堆、结束回合；人物机制占独立小区。操作优先保持稳定位置。
5. **瞬态层**：源动作、轨迹、作用闪墨、跳字、状态入槽；不接收鼠标，不能遮住焦点或待选。

1280×800提案：全局条约56px，战斗信息在其下；主角锚点约宽度16%/高度55%，伙伴在28%～44%，敌方在58%～90%；手牌约占底部28%，意图放在敌方头顶但低于全局条。具体锚点须以4任务、最大伙伴和章节/状态组合验证。960×600切紧凑布局：缩背景与实体间距、收起次要说明，禁止靠整体缩小中文来塞满。任务超出首屏容量时使用明确切换/展开，不把有效目标丢掉。

`battle_layout.gd`与`battle_compact_layout.gd`负责排布；`battle_screen.gd`保留选择与命令协调，拟拆出ActorView、ActorHUD、EffectLayer。命中框用逻辑布局，视觉姿态和特效不改变可点击对象ID。

## 2. 四角色与任务敌怪的动作语言

| 对象 | 独立形态与行动设计 | 机制信息 |
|---|---|---|
| 林序P01 | 学生全身侧立，笔记本/笔分层；工作时书写并送出勾页，策略时整理页签；衔接用连续墨线，取回以回形针带回卡牌 | 前一牌类型、衔接可用、已用被动；当前自动取回事实保持，不画“可放弃”按钮 |
| 许知微P02 | 展开的论文册、标题签与独立章节页；部署入槽、引用票流向对应成本、发表加短印章动作 | 三章节槽按真实顺序排列；论文进度/引用/发表资格来自视图，未生效章节附时钟 |
| 沈见章P03 | 翻阅资料、圈注与划线；侵蚀用持续裂墨，诱发用括号连接，复合反应在目标处合并成局部印记 | 负面类型与层数属于具体任务；“首次复合可用”不是永久光环 |
| 唐以宁P04 | 手势和伙伴回应成对，接力用纸条/回形针轨迹；伙伴动作独立，主角不替所有伙伴重复攻击 | 协同槽、伙伴精力/行动和目标；同卡事后被动所得协同不能伪装为已支付费用 |
| 普通任务 | 从任务概念提取实体：讲座点名可为点名册/座位牌构成的小怪，作业为折页与夹板；细节要按真实任务审定 | 保留任务名称、剩余工作量、屏障、下一意图；可选任务加“非胜利必需”标记 |
| 精英/竞赛 | 更完整的机械/纸张结构；准备态明显改变姿态，技能用固定符号提示 | 精英状态、阶段或特殊规则可查；不能只加金边当精英 |
| 学年Boss | 围绕已有评测/终局身份设计多阶段形态；例如外层文件展开、印章或计时结构切换 | `task_advanced`切阶段；`battle_finished`才决定整战结果，二者不混用 |
| 伙伴与场景 | 7单位逐项核定用途与在场形态；场景以战场局部装置/环境层表达 | 入场、替换、耗尽、退场与考试禁用可辨；7场景定义不等于7张独立整屏背景 |

生产任务56个、遭遇53个仅是引用盘点。后续按“同一任务不同阶段、可共享骨架但不同轮廓、衍生单位、旧兼容内容”建资源映射；尚未做出唯一敌怪动画套数，不能报一个未经核对的生产订单。

每个主要实体至少有：入场、待机、行动准备、作用姿态、受作用、恢复/防护、退场；有特殊机制者增加召唤/换阶段。使用分层2D切片＋AnimationPlayer/骨骼或少量逐帧关键姿态的组合；具体技术先以样本验证GL Compatibility。动作可带局部纸张形变，不能只让整张立绘上下漂浮。

资源交付包含透明边缘、轴心、地面点、手部/笔尖/纸页作用点、头顶意图锚点和HUD安全区。动作轨与待机纸页/呼吸轨分离，受击后不会重置所有持续循环；这一点来自R2-07的明确开发说明。

## 3. 先补事件事实，再制作演出

现有链路：GameSession发布ActionResult/视图 → BattleScreen消费未见事件 → BattleEventAnimator串行 → BattlePresentation/Tween与AudioManager → 队列及实际动画完成后切页。保留其一次发布、一次消费与终局等待。

存在43类直接字面量事件，清单见[event-literals.json](audit/event-literals.json)，但它不是所有运行时分支的完整trace。逐条审计发现以下缺口：

| 缺口 | 当前事实 | 拟补方案与验证 |
|---|---|---|
| 获得放松 | `_execute_v3_card_effect::relax`直接改玩家值；伙伴支持也有直接分支。现有`relax_changed`的已查调用对应旧`reduce_relax` | 统一产出`relax_changed`，带before/after/delta、source、target、reason；覆盖牌、被动、伙伴、清零及抵消，禁止一个变化重复两次 |
| 专注与协同 | v3获得专注、协同获得/支付的若干函数不发对应独立变化事件 | 补全`focus_changed`；拟新增`synergy_changed`。支付与事后获得分别记录，不能只发净差值 |
| 论文细节 | 有章节与发表事件，但进度/引用等内部trigger字符串不等于已发布RuleEvent | 对各变动点核对；拟新增细分资源事件或同一结构的论文变更事件，标记旧值、新值、阶段与来源 |
| 动作归属 | source有时是卡实例、状态/饰品或空串，不能直接当Actor节点 | 建只读来源解析：卡实例→主人；单位→本单位；状态→状态来源或目标，未知时只做局部反馈，不瞎播主角攻击 |
| 多段与连锁 | 现有index支持顺序和去重，不能保证每个事件天然属于同一次视觉作用 | 如生产trace需要，事件data增加语义`effect_index/segment/cause_index`；字段为拟新增，不包含贴图/时长等美术配置 |

新增事件只报告已经执行的规则变化，不改变规则顺序、数值或RNG；新增数据字段先同步战斗/接口/存储相关契约。旧存档事件能缺省读取，动画队列不持久化；旧日志缺少因果信息时只展示已知结果。新事件数导致的快照/黄金文件差异要明确登记，不能为了旧测试通过而静默删事件。

本轮不修改以上代码。WP-02先做代表命令事件trace与模式终态对照，未补齐的机制不进入逐次演出验收。

## 4. 事件到画面的明确映射

| 当前事件/拟新增事件 | 来源动作 → 作用点 → 结果 | 收尾和例外 |
|---|---|---|
| `card_played`、`card_resolved` | 选牌离手，角色进入该效果族姿态；结算牌进入真实destination | 保留实际卡控件；不能card_resolved与discarded各飞一次 |
| `card_drawn`、`card_discarded`、`card_exhausted`、`card_retrieved`、`card_absorbed` | 各自从真实牌区到真实牌区；吸收强调敌方来源 | 公开前只用卡背；落位恢复焦点与命中；同牌实例飞行只有一份 |
| `completion_applied`、`shield_changed`、`work_restored` | 来源笔/纸动作→任务作用锚点→屏障挡板或工作量条变化 | 读事件before/after；屏障吸收与工作量变化分开；0实际变化不跳假伤害 |
| `pressure_applied`、`vitality_changed`、`unit_healed` | 敌方动作或恢复来源→玩家/伙伴→纸盾抵消或精力变化 | 防住只出现盾波；有精力损失才受伤/心−N；不重复播放两套数字 |
| `relax_changed`完整覆盖、拟`synergy_changed`等 | 来源图标亮起→对应实体/资源槽→实际增加/支付 | 同一指令先得后耗保留因果；不依据最终净差虚构每段 |
| `status_gained`、`status_changed`、`status_removed` | 短符号作用→对应对象状态槽入位/层数变更/擦除 | 数值变化归HUD；状态环不永久高频闪烁，状态名可查 |
| `passive_triggered`、`relic_triggered` | 对应被动印章或饰品抬亮，细线连到实际收益对象 | 被动不能一律让主角攻击；同窗连锁可并行呈现但有顺序记录 |
| `chapter_deployed`、`chapter_ran`、`chapter_returned`、`chapter_slots_swapped`、`paper_published` | 页入槽、当前页前移执行、回手、重排、发表印 | 部署不提前播准备效果；章节顺序不被动画改写 |
| `unit_summoned`、`unit_departed`、`coop_target_set` | 伙伴从舞台边入场、退场、目标线移至实际任务 | 替换先显示被换对象；伙伴耗尽不可继续待机；修正音频事件名不匹配 |
| `scene_established`、`scene_replaced` | 场景装置与低频环境层切换 | 不挡正在选择的牌；考试替代牌不能播不实际建立的场景 |
| `enemy_skill`、`task_summoned`、`task_transformed`、`task_self_destructed` | 先定位施术任务→新实体/替换形态/自毁作用 | 旧目标移除后用缓存锚点；不在空处伪造可选对象 |
| `task_advanced`、`task_completed` | 阶段外壳打开或任务归档退场；HUD按下一阶段更新 | 一项完成不等于战斗胜利，仍存在必需任务时保持战斗 |
| `round_started`、`phase_changed`、`ddl_ticked`、`ddl_adjusted` | 回合标签短切换；DDL钟面沿实际变化更新 | 不用重复大横幅遮挡；危险DDL用文字＋形状，颜色只是辅助 |
| `choice_requested`、`choice_confirmed` | 牌/实体演出在待选边界停下，待选面板获得焦点；确认后续算 | 关闭动画不会自动选牌；非法/过期确认不播放成功 |
| `battle_finished` | 根据真实结果完成必要退场与信息反馈，再交给Shell切页 | 沿用“队列结束且所有必要Tween结束”；结果只结算一次 |

未知事件保留可读日志与安全HUD同步，不播放猜测的攻击；生产可达但未映射的事件记缺陷，不能一直靠unknown兜底宣布全覆盖。

## 5. 动作时间线与速度策略

**保留现有基础×4与玩家倍速偏好。** 下表数字为页面1×、已计入基础×4后的可见时长提案；实现不能再除一次4，也不能取消4回到原来慢速。当前战斗临时切换1/1.5/2与设置0/1/2/4存在不同入口，迁移时统一解释并兼容既有值，不能悄悄重置偏好。

| 示例 | 并行关系与建议时间线 | 阻塞边界 |
|---|---|---|
| 写作业单次作用 | 0～45ms卡离手＋角色抬笔；45～95ms送出墨线；95ms作用点触发受作用/音效/数字；95～220ms工作量过渡＋角色收势；牌进入弃牌堆可与后段并行 | 普通动作目标约220～280ms，不把各事件原有等待简单相加 |
| 伸个懒腰 | 0～60ms伸展；60ms折纸盾成形，实际盾值更新；60～180ms光边消退 | 数值依放松事件；没有事件时不编造分段反馈 |
| 整理书包 | 已有逐张0.125s飞牌为初始基准；抽牌完成后建立必须弃1张的待选；确认后丢弃约0.115s | 玩家选择时间无上限，不将读牌时间算成动画性能问题 |
| 两段/群体完成 | 同源动作可复用；同目标各段分开作用点，建议间隔40～70ms；群体同一段并行显示各目标结果 | 不能把不同段合并；后段目标消失按规则跳过，不转移 |
| 章节/伙伴连锁 | 主因果按顺序；资源徽标、HUD条和小尾迹在同一作用组并行 | 边界为待选、阶段变更、终局；同一来源不为每个辅助事件重播起手 |
| 终局 | 必要作用结束后短退场约120～180ms，再切奖励；读字尾迹可留日志 | 不为装饰循环等待；禁用动态时立即落稳但仍展示结算信息 |

持续数字可在不锁操作的附着层保留350～650ms；高速下减少起手/尾迹/粒子，保持数字可查，不能用强制长停顿抵消用户倍速。建议时长需与当前构建相同命令录屏对照；若普通牌手感变慢，优先并行动作和缩减尾部。减少动态关闭位移、振动、闪烁及循环，保留静态图标、数值变化和简短文字。当前关闭动态路径仍需核对新音效是否被重复触发。

调度拟采用：按`run_id/revision/event.index`去重 → 语义动作组 → source/target/HUD三条局部轨 → 必要动作完成屏障。不能跨待选/阶段/终局边界乱序并行。视觉时钟仅控制已发布状态的展示投影，不能驱动规则结算。

## 6. 点击、拖牌及全局反馈

| 状态/事件 | 画面与声音提案 | 必须保护 |
|---|---|---|
| 悬停/键盘焦点 | 细墨轮廓＋局部抬起约70～100ms；键盘焦点额外角标；默认无悬停音 | 原命中框和布局不动，不能让邻牌反复抢焦点 |
| 按下 | 压纸阴影缩小，局部墨点扩散40～60ms | 只是输入反馈；未提交成功前不盖成功印 |
| 预选 | 持续折角/回形针标，确认区域显示对象与实际代价 | 不扣费、不抽随机、不把候选从列表移走 |
| 合法拖向目标 | 笔迹方向线、目标地面圈、已知效果提示 | 可用性来自预览；不对未知结果给保证数字 |
| 取消/拖回 | 约90～120ms回原位，清瞄准；无成功声 | Esc/右键保留；强制待选只能关闭说明不能撤销规则 |
| 禁用/拒绝 | 对应费用或条件处显示红划线＋具体原因；一次轻反馈 | 不弹错乱的卡牌详情，不播伤害，不改变状态 |
| 业务成功 | 购买/领取盖短印，物件飞向牌组/饰品槽；数值更新同一次结果 | 不以Tween回调再次扣钱、领奖或存档 |
| 空白点击 | 可选极弱墨点，减少动态时关闭；无音 | 不制造交互成功错觉或全屏粒子噪声 |

## 7. 音频与生命周期

音效设计与作用点对齐：纸张按压/飞牌、书写完成、盾吸收、精力受压、状态印记、章节翻页、协同接力、交易确认、退场/终局各有声音族。保留用户已要求的柔和风格、静音、五总线设置、3 SFX槽和节流；连续状态变化不逐个叠播。优先级为待选/胜负＞真实作用＞飞牌＞装饰；本轮未试听参考视频音轨，不将这些声音提案冒称二代原声特征。

为每次页面会话建立`presentation_epoch`；离页、重开、测试编辑、关闭动态时递增并取消旧回调。清理Tween/粒子/音频，真实卡落位、进度条落到权威值，清除残留瞄准与目标缓存。新布局重算后再绑定锚点，缓存只用于已经消失对象的短暂收尾。字号、窗口、动画设置的改变不能造成重复消费或新业务提交。

实际验证需录下正常/快速/减少动态/关闭四种路径，与相同输入的领域终态、RNG、revision比较；再覆盖多段、全体、最后一击、阶段转换、待选、中途重开与测试编辑。现有截图只能证明当前布局，不证明上述新演出已完成。
