## 需求登记

新增需求先登记唯一ID、来源、页面/组件、触发条件、要表达的信息/动作、禁用/失败状态及未决项，可用[单项模板](描述记录模板.md)。已有需求发生变化则同步原记录。ID不复用，v3视觉/交互使用R3-VIS/R3-ACT，保留旧VIS/ACT用于追溯v1；音频草案暂用R3-AUD，命名空间与阶段归属待G0确认。

需求状态依次为“需求已登记→资源已核对（适用时）→设计已确认→已实现→已验证”。无需图片可注明跳过资源环节；音频（如纳入）另记来源、授权、循环点与响度，不能以“有文件”代替核对。“设计已确认”不能冒称用户人工签字。实现和验证须链接实际文件、触发输入与结果，截图/音轨不能单独替代行为证据。
