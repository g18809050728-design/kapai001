# UI 图片与动作描述

本目录维护 UI 图片、视觉状态和交互/动画需求。G0–G5 已完成需求登记；G6 的 46 个素材已完成 AI 视觉核对及选定，实际文件与来源见[制作包](../assets/g6/README.md)。当前 G7 设计与实现见[界面与交互设计](G7界面与交互设计.md)、[需求台账](需求台账.md)及[执行记录](../docs/G7界面执行记录.md)，本期界面出口已通过，逐项覆盖及剩余边界见执行记录。图片资源不能替代 Markdown 需求；目录中的文字不改变规则、命令或状态归属。

## 登记规则

当页面、组件或交互需要以下任一内容时，先在[需求台账](需求台账.md)登记唯一 ID、关联契约、用途、触发状态、需要的内容和未决问题。新增需求可按[单项模板](描述记录模板.md)建独立记录，或在 G7 设计中按 ID 完整登记；当前本期条目的布局、动作和验收条件已统一链接 G7 设计：

- 人物立绘、卡图、场景图、背景、图标、状态插图或其他 UI 图片；
- 页面/组件的视觉状态，尤其是选中、禁用、加载、失败、空状态和待选状态；
- 战斗事件演出、页面转场、反馈动画或有先后顺序的交互动作。

纯规则动作且没有新增视觉/交互表现时无需登记图片或动作需求。既有 UI 需求变化时更新原记录；新页面、新资源或新动作使用新 ID，不复用旧 ID。`VIS-` 用于图片/视觉，`ACT-` 用于动画/交互动作，序号在本目录内唯一且递增。独立记录的文件名为 `<ID>-<简短主题>.md`；台账中的链接与记录 ID 必须一一对应。

需求记录应写明页面/组件、关联契约、触发条件、要表达的信息或动作、禁用/失败等必要状态，以及仍未解决的问题。G0–G5 的历史草案允许视觉细节待定；当前 G7 已按选定资源补齐本期布局关系、动作时序、异常呈现及可观察验收条件。新增条目不能把猜测写成已批准规格，也不能在没有实测证据时标记“已验证”。

## 状态与门槛

记录状态依次为“需求已登记 → 资源已核对（适用时） → 设计已确认 → 已实现 → 已验证”。当前本期条目标为“已验证（G7 范围）”，VIS-010/011 明确为本期 MVP 不适用。无需图片的动作记录跳过资源状态并注明理由。“设计已确认”表示依据契约落实实施设计，不冒称用户人工批准；“已实现”需链接实际实现；“已验证”需链接按[实施计划与验收基线](../实施计划与验收基线.md)保存的验收证据。

G0–G5 只核对需求台账覆盖，不要求图片、UI 代码或视觉验收。G6 核对选定图片与需求 ID 的映射；G7 对应 UI 实施开始前，需将该项记录细化至“设计已确认”，或标明“不适用”及理由。G7 验收时，已实施项须达到“已验证”，并能对应记录 ID、资源版本、实现位置、触发输入和实际结果；截图仅在需要证明视觉状态时补充，不能替代文字记录。

当前工作区已有 G0–G5 实现及实测证据、G6 实际图片与选定记录和 G7 界面代码。G6 核对属于 AI 视觉核对；G7 实测结果已记入执行记录，生产完整用户路径、性能和发布打包留 G8。提示词、格位示意、选定图片、实现代码与验证证据分别记录。
