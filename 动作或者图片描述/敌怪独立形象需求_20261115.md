# UIR-069 敌怪独立形象与正式接入

来源：用户要求“把不同的敌怪的建模也做好，并上线，每一种敌怪应当有其各自的形象”。本轮实施例外见[根计划§0.20.27](../实施计划与验收基线.md)，具体制作与验证见[设计记录](../docs/plans/2026-11-15-enemy-roster-design.md)。关联 UIR-011/013/051/052/054/057/059，角色已确认版本保持。

范围以 [campus_four_year](../data/four_year/manifests/campus_four_year.json) 启用的 60 个 task ID 为准，逐种名称、材质与提示词维护于[资源清单](../output/imagegen/enemy-roster-20261115/roster.json)。包含普通任务、精英、竞赛分工、召唤附属、四学年 Boss 和四条毕业路线终敌。N01复用已核对 V4，其他59种新绘；同一ID的阶段使用该怪自身形象与阶段动作，无须为每个阶段再次生图。

| 子项 | 必须可观察到的结果 | 证据与边界 |
|---|---|---|
| AC-01 独立形象 | 60个ID各有独立主体与资源路径，不能只换色、套N01或合并路线终敌 | 精确覆盖审计、原件/拆件hash及逐ID图鉴；自动去重不等于美术判断 |
| AC-02 画风与拆件 | 新主体完整可读，与既有精修资源协调；每种有同源的主体、攻击件和辅件，透明背景无品红底 | 原图、177张透明拆件与实际看图记录；部件源区与处理方法保留 |
| AC-03 原生动作 | 主体有实际加权网格，部件沿独立骨骼运动；待机、出手、受击、防御、入场、离场、阶段切换可渲染 | 每种7姿态和代表材质连续帧；二维局部形变不宣称三维模型或完整分肢IK |
| AC-04 正式默认 | 正常主菜单、创建、地图、战斗、保存继续和测试房间默认使用同一注册，按精确task ID先于旧alias解析 | 正常游戏入口与实际BattleScreen验证；不等于外部平台发行 |
| AC-05 生命周期 | 召唤、变身、阶段推进及已离场实体演出仍使用对应身份；同一事件只播放一次，终局只释放一次 | 公开隔离测试房间的真实规则命令与明确标记的受控恢复检查 |
| AC-06 输入与动态 | HUD和目标命中区稳定；两窗口、三字号、减少动态、关闭动画及基础×4/用户倍速可用 | 四人正常战斗尺寸矩阵和专项检查；不能靠改命中区容纳美术 |
| AC-07 领域与兼容 | 原规则、RNG、revision、存档schema和写命令边界保持，旧包/未知ID仍回退 | 正常局真实命令A/B、保存继续、完整规则/UI回归；正式档只读hash核对 |
| AC-08 来源与审美 | 提示词、服务/模型、尺寸质量、原件及派生hash、API中断/续批和累计数量可追溯 | CLI文字生成，未上传参考图；AI核图与用户最终签收分开记录，金额未知如实记 |

本轮状态以[结果与剩余边界](../docs/plans/2026-11-15-enemy-roster-design.md)和[验证汇总](../artifacts/verification/enemy-roster-20261115/verification-summary.json)为准；用户最终美术判断与整版G0/G6/G8出口独立保留。
