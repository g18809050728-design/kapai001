### 0.1.2 关键差距

1. 卡牌同时有 `_tip_label` 和原生 `tooltip_text`，容易出现两层提示；长文本只有一行，升级差异/限制/来源缺失。
2. 战斗任务、单位、玩家状态、资源没有独立悬停目标；当前只有任务/单位按钮的原生 tooltip 和一行状态文字。
3. v3 论文/章节/协同/能力未进入 `BattleView`，因此现有 UI 无法显示这些信息，悬停也无数据可查。
4. 饰品没有战斗内常驻入口，所谓“悬停饰品”只能在已有全文面板中发生，重复建设没有收益。
5. 奖励/商店/牌组/事件页已经展示全文，再加悬停详情会造成信息重复和焦点冲突。
6. 施工前没有音频子系统；音效/音乐不是“在成熟结果上微调”，而是从零新增。
7. 战斗是固定舞台缩放，不是响应式重排；130% 字号不能按局流程页面的方式直接套用。
8. 名词只有标签，没有定义、窗口、易误解和来源；卡面文本是生成字符串，没有 `[[关键词]]` 标记。

## 1. 体验目标

一句话：让玩家在 3 秒内看懂“刚刚发生了什么、为什么、下一步能做什么”，且不牺牲校园日常与纸面考试的题材感。

四条原则：

1. **规则优先**：任何演出都可关闭；关闭后终态、日志、RNG 与开启时逐项相同。
2. **因果分层**：先表现“因”（谁出牌、谁施压），再表现“果”（完成量、压力、状态、任务推进），不同时堆叠。
3. **纸面校园**：纸、笔、印章、时钟、教室、图书馆、宿舍的声音与材质优先；不做奇幻法术、重金属或原作仿制。
4. **可访问**：不依赖颜色单一通道；支持减少动态、字号、高对比、键盘全路径与音量分轨。

## 2. 分层与单一事实源

| 层 | 职责 | 禁止 |
|---|---|---|
| 规则层 | 产生事件、数值与合法集合 | 等待动画回调才继续结算 |
| 视图层 | 发布只读 `BattleView` / `SessionView` | UI 自行计算费用、伤害、候选或状态 |
| 演出层 | 消费事件，播放动画/音效/特效 | 改写状态、RNG、revision 或日志 |
| 帮助层 | 名词解释、预览、禁用原因、学习手册 | 另造一套与规则冲突的数值 |
| 设置层 | 动画/音量/无障碍/输入 | 改变当前 seed、人物、难度或存档 |

单一事实源：

- 事件：`RunStep.events` / `BattleStep.events`，按 `run_id/revision/index` 消费并去重。
- 视图：`BattleView` 的有效卡面、费用、合法目标、禁用原因、任务状态与窗口。
- 名词：以 [卡牌名词与Buff效果说明](../docs/卡牌名词与Buff效果说明.md)、[规则书](../docs/交大四年_DDL战争_游戏规则书.md) §20 与各契约维护源为准；UI 只引用稳定 key，不复制规则文本。
- 音频/动画资源：由资源清单登记 ID、版本、来源与许可；UI 不写死路径。

## 3. 全局参数

### 3.1 时间 token

| token | 时长 | 用途 |
|---|---:|---|
| instant | 0.06 s | 按压、数值跳动、状态角标 |
| fast | 0.10 s | 悬停、焦点、按钮反馈 |
| base | 0.16 s | 抽牌、弃牌、状态弹出 |
| emphasis | 0.24 s | 出牌、命中、任务推进 |
| scene | 0.35 s | 页面转场、战斗入场/退场 |
| hold | 0.6–1.2 s | 发表、阶段击破、胜负等关键节点 |

- 事件队列基础间隔沿用 v1 的约 0.12 s/事件；允许按事件组批量压缩，但不得改变事件顺序。
- 速度档：×1 / ×1.5 / ×2；关闭动画立即消费剩余队列，保留最新视图与完整日志。
- 减少动态：转场缩短到 0.1 s，取消屏幕震动、闪烁和大幅位移，粒子量降至 30% 以下。

### 3.2 音频总线与响度

| 总线 | 默认 | 说明 |
|---|---:|---|
| Master | 100% | 总音量 |
| Music | 70% | 音乐，动态分层 |
| Ambience | 50% | 环境音 |
| SFX | 80% | 战斗与卡牌音效 |
| UI | 70% | 按钮、页面、提示 |
| Voice | 预留 | 本期不做完整配音 |

- 音乐目标约 -16 LUFS integrated，真峰值不高于 -1 dBTP；音效峰值不高于 -3 dBFS。
- 同时播放音效上限 8；同一音效 40–80 ms 内不重复触发；轻微音高随机 ±5%，避免机械重复。
- 关键提示（发表、阶段击破、DDL 剩余 1）可让音乐短暂 duck -6 dB；不做突然切断。
- 音频设备缺失、资源缺失或解码失败时静音继续，记录诊断，不崩溃、不阻塞规则。

### 3.3 性能与降级

- 目标 60 fps（1280×800），最低 30 fps（960×640）。
- 单次粒子爆发不超过 40 个，同屏不超过 200 个；低帧率或减少动态时优先降粒子，不降信息可读性。
- 不使用全屏模糊/强闪作为常规反馈；屏幕震动默认 2–4 px、0.12 s，可关闭。
- 动画关闭、资源缺失、窗口缩放时，所有关键信息仍可从静态视图、日志和 tooltip 获得。

### 4.3 战斗事件演出

现有 `BattleEventAnimator` 只做顺序文字提示（0.12s/事件、可加速/关闭），并有动画开/关 A/B 证据。下表是可选视觉层，不替换文字队列；关闭/失败时回落到文字。P0 只保留现有抬牌、目标高亮、提示条更新；P1 加轻量资源/状态反馈；P2 才做逐事件演出与粒子。

事件名以未来 G0 冻结的枚举为准；下表是语义分组，不冒充已注册事件。

| 事件组 | 触发 | 视觉 | 时长 | 音效 | 可观察验收 |
|---|---|---|---|---:|---|
| 战斗开始 | `battle_begin` | 任务卡入场，DDL 日历落位，起手牌错峰抽取 | 0.6 s | 铃声 + 抽牌 + 落章 | 起手数量与视图一致 |
| 回合开始 | `round_started` / 准备 | 回合横幅；“准备”依次点亮章节→能力→场景→抽牌 | 0.8 s | 轻钟 + 逐项提示 | 顺序与规则准备顺序一致 |
| 抽牌 | `card_drawn` | 牌从抽牌堆飞入手牌，逐张错峰 0.04 s | 0.16 s | 纸滑 + 轻弹 | 不显示隐藏牌序 |
| 出牌 | `card_played` | 牌抬起、放大、沿弧线到中央，按类型落下 | 0.22 s | 类型音 + 角色音色 | 费用与目标使用同一预览 |

## 6. 音乐

### 6.1 风格方向

“校园室内乐 + 轻电子氛围”：钢琴、木吉他、马林巴、拨弦、轻弦乐、玻璃琴、预置钢琴、尤克里里、轻打击与纸/钟表采样。节奏以 70–110 BPM 为主，战斗可到 120–140 BPM；不做大型管弦、摇滚、恐怖或对现成作品旋律的模仿。

### 6.2 曲目清单

下表“优先级”只表示音频内部的最小集顺序；整体音频仍按 §0.1.4 列为 P1/P2，不因表内 P0 变成全局 P0。

| ID | 场景 | 情绪 | 建议长度 | 分层 | 优先级 |
|---|---|---|---:|---|---|
| BGM-01 | 主菜单 | 清晨、开始 | 90 s loop | 基础/角色 | P0 |
| BGM-02 | 选人 | 轻快、期待 | 60 s loop | 基础 | P0 |
| BGM-03 | 地图 | 日常、前进 | 120 s loop | 基础/层数 | P0 |
| BGM-04 | 普通战斗 | 专注、轻紧张 | 90 s loop | 基础/DDL/角色 | P0 |
| BGM-05 | 精英战斗 | 压迫、克制 | 90 s loop | 基础/DDL | P1 |
| BGM-06 | 期末 Boss | 三阶段紧张 | 120 s loop | 基础/阶段/DDL | P1 |
| BGM-07 | 事件 | 安静、叙事 | 60 s loop | 基础 | P1 |
| BGM-08 | 商店 | 轻快、生活感 | 60 s loop | 基础 | P2 |
| BGM-09 | 休息 | 放松、夜晚 | 60 s loop | 基础 | P2 |

### 6.3 动态音乐

- 战斗基础层常驻；DDL ≤3 加入钟表/低音层；DDL ≤1 再压低高频、加入更明显的低脉冲。
- Boss 按阶段 n/3 加层：阶段 1 基础，阶段 2 加弦乐/打击，阶段 3 加玻璃琴/高频；阶段击破可短静默 0.2 s 再续。
- 角色层：同一战斗曲上叠加角色主音色短动机，不单独为四人写四首完整曲。
- 低精力不改变音乐；避免用音乐暗示未公开信息。
- 待选、暂停、菜单打开时音乐降低但不断开；关闭游戏时淡出。

### 6.4 转场与静音

- 曲目切换交叉淡化 1.5–2.0 s；战斗进入用短 stinger，不从头重播整曲。
- 同一场景重绘不重启音乐；读档/回到地图只做音量恢复。
- 发表、阶段击破等关键节点可短 duck；不做突然静音。
- 所有音乐可单独静音；静音不改变任何规则或计时。

### 6.5 来源与许可

逐文件登记：ID、文件名、作者/工具、生成或录制日期、授权范围、是否可商用、循环点、响度、版本。AI 生成音频须记录平台与条款；未确认授权的素材只能作为临时占位，不得写入发布包。

## 7. 辅助交互

### 7.1 信息可达性

- 战斗内优先覆盖被截断或未显示的对象：手牌、任务、单位/伙伴、玩家状态；资源与地图节点 P1。奖励/商店/牌组/饰品/事件/休息已有全文面板，不新增悬停详情。
- 论文/章节/协同/能力悬停阻塞在 `BattleView` 暴露 v3 只读子视图之后；未补齐前不得显示猜测值。
- 关键信息不能只存在于悬停：卡面费用、任务未完成量、资源当前值等必须静态可见，悬停只做增强。
- 任意禁用操作必须显示“为什么不能”：费用不足、目标非法、限次用尽、待选锁定、满手、非合法源等。
- 任意数值显示“基础/有效/上限”与来源；预览标“预计”，不伪装已结算。
- 卡组、弃牌堆、消耗堆、奖励、商店、事件候选均可查看完整效果；抽牌堆只显示数量。
- 事件日志保留离场对象名称快照，可按类型筛选，并与名词解释互链。

| 输入 | 行为 |
|---|---|
| 鼠标悬停 | 战斗内立即显示摘要；局流程 0.25 s 显示浮层；不提交、不抢焦点 |
| 左键点击 | 选中；再次点击合法目标或确认按钮提交 |
| 拖动 | 超过 10 px 进入拖拽；合法目标高亮 |

| Esc | 先取消本地选择；无选择时打开暂停/关闭面板 |

| 方向键 | 在手牌、目标、候选间移动 |
| Enter / Space | 确认焦点项 |
| 1–9 | 选择对应手牌；无目标牌直接使用 |
| E | 结束回合（新增，P1） |
| D | 打开抽牌堆/牌组查看（新增，P1） |

- 现有已实现快捷键只有 1–9、Esc、右键取消；`E/D/L/G/I/P/F1` 为拟新增，须在不处于文本输入框时生效。
- 输入模式自动识别：键鼠与手柄切换时更新提示图标，不混合显示。
- 焦点顺序固定：顶栏 → 任务 → 伙伴/场景 → 手牌 → 结束回合 → 牌堆/日志；模态打开时焦点隔离，关闭后回到原控件。
- 待选、保存中、动画关键节点锁定后台输入，但锁定原因可见。

### 7.3 防误触、确认与失败

- 普通出牌不二次确认；放弃本局、替换旧局、删除永久牌、重开学期等不可逆操作必须明确确认，默认焦点在“取消”。
- 确认框展示后果与范围，不只问“确定吗”。
- 本地选择可取消；已提交规则不可撤销，不用“撤销”伪装回滚。
- 保存失败：固定提示栏 + 重试按钮；保留当前局与待处理状态，不重发业务命令，不自动跳页。
- 服务未冻结/候选不可用：显示原因，不由 UI 补收益或补候选。
- 长按/连续点击：防重复提交；提交中禁用对应按钮并显示忙碌状态。

### 7.4 无障碍

| 项 | 方案 | 验收 |
|---|---|---|
| 字号 | 局流程 100/115/130% 重排；战斗固定舞台字号另立预算（P2） | 960×600 实际渲染可读；战斗 130% 未验证 |
| 高对比 | 加深边框、文字与背景对比 | 不依赖细线区分状态 |

| 减少动态 | 关震动、闪烁、大幅位移；粒子降至 30% | 终态与普通模式一致 |
| 闪烁 | 不超过 3 Hz，不做全屏白闪 | 录屏检查 |
| 音频字幕 | 关键提示（DDL 剩余 1、任务压力、发表）写入日志/toast | 静音仍可理解 |
| 音量 | 五总线独立 + 总静音 | 静音不影响规则 |
| 键盘 | 全路径可完成选人、地图、战斗、奖励、商店、事件、休息、摘要 | 仅键盘实测 |
| 屏幕阅读器 | Godot 原生支持有限；本期不宣称完整支持，提供文本日志/手册替代 | 未验证项明确标注 |

### 7.5 新手引导

- 引导只覆盖规则，不替玩家做选择；不自动出牌、不自动结束回合。

### 8.2 显示层级

| 层级 | 位置 | 内容 | 触发 |
|---|---|---|---|
| L1 摘要 | 战斗悬停小窗 / 局流程浮层 | 当前对象的一句话 + 关键数值 + 禁用原因 | 战斗即时；局流程 0.25 s |
| L2 详情 | 既有 `_info_panel` / `CollectionInspector` | 完整效果、升级差异、限制、来源 | `I`/“详情”/点击 |
| L3 关键词 chip | 详情底部 | 从结构化 ID 生成的名词入口 | 悬停/聚焦 chip |
| L4 词条浮层 | chip 旁 | 定义、当前值、窗口、易误解、来源 | 悬停/聚焦 |
| L5 手册 | 主菜单/战斗帮助 | 分类、搜索、完整规则与例子 | `G` 或帮助按钮 |

- 第一版不做卡面关键词下划线：现有文本由 `UiStyle.describe_effects` 生成纯字符串，没有标记语法；chip 从 `effect.op`/`status_id` 等结构化字段生成。
- 本节只讲名词词条的显示层级；卡牌/单位/任务等对象的摘要与详情见 §8.7。
- 浮层最长约 360 px，自动避让屏幕边缘，不遮挡当前目标；内容过长时内部滚动。
- 图钉面板最多固定 3 条（P1），避免遮屏；关闭后恢复原焦点。
- 手册按“基础数字 / 论文 / 六负面 / 伙伴与场景 / 考试 / 牌区与操作”分类；优先扩展现有“规则”面板。

### 8.3 Tooltip 模板

```text
侵蚀                        任务负面
一句话：任务准备时按层数造成持续完成量。
当前：3/20；本次预计 +3 完成量；自然结算后 -1。
窗口：每次自然结算后减 1；提前验算不减。
易误解：状态完成量仍受屏障影响，不受易伤加成。
关联：任务、屏障、诱发。
来源：规则书 §…；名词说明 §4。
```

必填字段：名称、类型、一句话、当前数值/上限、到期或窗口、至少一条易误解或边界、关联词、来源。
禁止：只写“造成伤害”这类模糊句；用内部字段名或事件名直接展示；把未公开信息写进 tooltip。

### 8.4 数值显示

- 基础/有效分开展示：`费用 2（基础 3 −1）`；`完成量 12（10×1.25，向下取整）`。
- 上限与溢出：`进度 10/10（已满）`；`侵蚀 20/20`。
- 分段与批次：虚弱/乏力/易伤按段显示；侵蚀自然/提前分开；诱发默认/额外合计。
- 预览标“预计”，结算后改为实际值；预览不得显示隐藏抽牌结果。
- 禁用原因紧邻操作：`专注不足：需要 2，当前 1`；`目标已有同名章节`；`本回合额外行动已用`。
- 颜色只作辅助：数值增减同时用 `+`/`−` 和箭头；状态用图标+层数。

### 8.5 术语种子表

| 术语 | 一句话 | 易误解 |
|---|---|---|
| 精力 | 跨节点生命，战后不自动回满 | 不是每战重置的血量 |
| 专注 | 回合出牌成本，自然 3、上限 10 | 不靠弃牌获得 |
| 放松 | 当轮抵挡压力，下次准备清旧值 | 不是永久护甲 |
| DDL | 剩余完整轮末次数，归零仍有任务即失败 | 不是普通回合数 |
| 完成量 | 任务输出，先扣屏障再扣未完成量 | 不是对玩家伤害 |
| 屏障 | 任务的护盾，先于未完成量被扣 | 不是玩家放松 |
| 压力 | 任务对玩家的攻击 | 不是完成量 |
| 侵蚀 | 任务准备按层数持续输出，结算后减 1 | 不是所有负面的统称 |
| 诱发 | 成功出牌后按开始时层数追加完成量 | 新施加不触发自身 |
| 脆化 | 新获屏障减半，已有屏障不变 | 不影响已有屏障 |
| 乏力 | 每段压力先减层数 | 不是百分比减伤 |
| 虚弱 | 每段压力 ×0.75 向下取整 | 不与乏力混为一谈 |
| 易伤 | 工作牌直接完成量 ×1.25 | 不增强伙伴/章节自动/状态 |
| 焦虑 | 下次自然专注每层少 1 | 不是永久降上限 |
| 拖延 | 下次基础抽牌每层少 1 | 不影响效果抽牌 |
| 困倦 | 下次行动工作首段每层少 1 | 不是整回合减伤 |
| 额外要求 | 任务压力每层 +2，本战仅明确移除 | 不是普通任务状态 |
| 护卫 | 承接默认单体压力，不拦全体/点名 | 过量不溢出 |
| 开题 | 开启论文记录，占用首次抽 5 一格 | 不是免费抽牌 |
| 进度 | 论文不同牌名首次使用累计，上限 10 | 不是任务完成量 |
| 引用 | 论文重复牌名累计，上限 5，分层付款 | 不是免费加值 |
| 修正 | 论文完成度加减项 | 不是永久属性 |
| 完成度 | 论文总分 `7×进度+6×引用+修正` | 不是任务完成量 |
| 增幅 | 强化下一张卡正文首个白名单正向数值 | 不强化完成量/修正/自动 |
| 换题 | 移除一个已用名，成功才修正 -1 | 不刷新同名限次 |
| 发表 | 一次兑现论文并退全部章节 | 不是普通攻击牌 |
| 章节 | 三槽、下回合按槽序自动运行 | 自动不算出牌 |
| 协同 | 唐以宁战内资源，上限 6 | 不是专注 |
| 续航 | 伙伴自身精力，行动后减 1 | 不是主角精力 |
| 短驻场 | 伙伴按实例上限恢复 | 主动撤回不退卡 |
| 考试面 | 替代卡面，保留费用/类型/升级 | 不是新永久牌 |
| 独立作答 | 考试中不执行普通召入/换班 | 仍触发合作被动 |
| 固定考场 | 考试场景替代，允许章节常驻 | 不是普通场景选择 |

### 8.6 一致性与检查

- 第一版不引入 `[[关键词]]` 标记：卡面文本由 `UiStyle.describe_effects` 生成；关键词 chip 从 `effect.op`、`effect.status`、`status_id`、`definition_id` 等结构化字段生成，不解析自由文本。
- 每个 chip 必须有词条；每个词条必须有来源与至少一条边界说明；未知 ID 在开发期报错，发布期显示原文并记录。
- 数值 tooltip 从 `BattleView`/`SessionView` 读取，不复制规则常量；公式变化时只改维护源。
- 禁止同义词混用：完成量/进度、屏障/护盾、压力/伤害、精力/生命、专注/费用、放松/护甲。
- 发布前跑术语覆盖检查：所有卡牌效果 op、状态 ID、任务阶段、伙伴/场景/考试 ID 均可解析为 chip；并抽查 20 条详情与规则书一致。
- 中文标点、数字与单位统一；`DDL` 保持大写；百分比与向下取整写清楚。
- 现有 `ui_labels.json` 已有 522 条标签；新增词条优先扩展该管线，不另造一套与 `UiStyle.label` 冲突的命名。

### 8.7 悬停详情与名词解释（P0 详细设计）

#### 8.7.1 边界

- P0：战斗手牌、任务、单位/伙伴、玩家状态。

- P2/阻塞：论文、章节、协同、能力（先补 `BattleView` v3 只读子视图）。

- 关键信息不能只存在于悬停：费用、未完成量、资源当前值必须静态可见。
- 抽牌堆只显示数量；未公开奖励、隐藏牌序、RNG 不进入提示。

#### 8.7.2 触发与载体

| 位置 | 触发 | 载体 | 内容 |

| 事件日志 | P2 | 事件名、来源/目标 | 结果、关联对象 | 现有文字面板 |

#### 8.7.4 交互

- 战斗悬停立即更新摘要，沿用现有抬牌/放大/置前；局流程浮层 0.25s 出现、0.10s 消失。
- 右键始终取消/关闭，不改为固定；`Esc` 逐层关闭；`I` 打开/关闭详情；`P` 固定词条（P1）。
- 拖动中只显示目标摘要，不展开详情，不遮挡落点；待选/保存/加载/切页关闭。
- revision 变化时关闭或刷新详情，不显示旧值；动画播放不改变悬停内容。
- 原生 `tooltip_text` 在摘要接入后对卡牌/任务/单位关闭，避免双提示；按钮禁用原因可暂留原生 tooltip。
- 快捷键只在不处于文本输入框时生效，避免与 seed 输入冲突。
- 手柄 P1；触屏长按 P2。

#### 8.7.5 战斗悬停小窗

小窗 360×168：深色底 `#192f35`、金色边框 2px、12px 阴影；标题 19px、元信息 13px、正文 14px（最多 4 行）、底部右对齐“I 查看详情”。

```text
小步实践
工作 · 专注 2
完成量 8；若上一张是策略，改为 12。
                                      I 查看详情
```

```text
期末大作业
第 2/3 阶段 · 剩余 24/40
屏障 6
下回合：压力 8
                                      I 查看详情
```

- 位置优先尝试目标上方、下方、左侧、右侧，再回退到指针四角；clamp 在舞台内，并避开被悬停目标。
- 禁用原因优先：`无法打出：专注不足（需要 2，当前 1）`。
- 正文超长最多 4 行；完整文本仍按 `I` 打开详情。
- 颜色沿用 `UiStyle` 深色/金色，不新增主题。

#### 8.7.6 详情面板

战斗复用 `_info_panel`：`Rect2(100,130,1080,520)`，深色、内部滚动、Esc 关闭。

结构：

1. 标题：名称 + 类型/归属 + 来源。
2. 核心数值：费用/精力、当前/上限、状态层数。
3. 完整效果：`UiContentText.describe_card` / `UiStyle.describe_effects`。
4. 升级差异：左右两列“当前 / 升级后”；不可升级明确写。
5. 限制：同名每回合、耗尽、衍生不可升级、目标限制。
6. 关键词 chip：由结构化字段生成。
7. 禁用原因与规则来源。

任务/单位/状态详情：

- 任务：阶段、未完成量/上限、屏障、当前/下轮意图、六负面层数与窗口、任务增益、胜利是否必需。
- 单位：当前/最大续航、本轮行动、额外行动、支援→协作、护卫、治疗/撤回、关联卡。
- 状态：层数/上限、一句话、窗口、来源、叠加、作用对象、至少一条易误解。
- 资源：当前/上限、下次变化、分项、不足/溢出预警；`synergy` 需 v3 视图。

局流程：地图节点说明用轻量浮层；奖励/商店/牌组/饰品/事件/休息沿用现有全文页面/检查器。

#### 8.7.7 关键词 chip 与词条

- 第一版不解析 `[[关键词]]`；chip 来自 `effect.op`、`effect.status`、`status_id`、`definition_id`、`phase_key`。
- 词条数据优先扩展现有 `ui_labels.json` 管线；若结构过重再拆 `ui_glossary.json`。字段：`id/term/type/short/full/values/window/misconceptions/related/source`。
- 词条模板：

```text
侵蚀                        任务负面
一句话：任务准备时按层数造成持续完成量。
当前：3/20；本次预计 +3 完成量；自然结算后 -1。
窗口：每次自然结算后减 1；提前验算不减。
易误解：状态完成量仍受屏障影响，不受易伤加成。
关联：任务、屏障、诱发。
来源：规则书 §…；名词说明 §4。
```

- 摘要不打开词条；详情内 chip 只嵌套一层；`P` 固定最多 3 条（P1）。
- 未知 ID 显示原文并记录诊断；不显示空白、不伪造解释。
- 文本仍由 `UiContentText`/`UiStyle.describe_effects` 生成；词条只解释，不复制规则常量。
