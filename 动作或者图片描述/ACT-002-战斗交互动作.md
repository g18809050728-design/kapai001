# ACT-002 战斗交互动作

状态：已验证（G7 范围）｜类型：交互动作｜登记日期：2026-10-14｜设计及验证日期：2026-10-15

## 来源与范围

- 关联需求/契约：[界面层契约 §15.4、§15.5](../docs/界面层契约.md)；[接口文档](../docs/接口文档.md) §3。
- 页面/组件：`BattleScreen` 的手牌、目标、单位、待选面板和结束回合入口。
- 触发条件：选择手牌或单位、补足目标、确认待选、取消本地预选、尝试禁用/非法操作。

## 当前设计与实现

1. 点手牌后进入本地预选；需要目标时由 preview 门控任务/单位按钮，并在“当前预选”区显示等待目标。补齐目标后提交一次 `play_card`；无需目标时按预览结果直接提交。提交期间按当前 revision 防重复输入，收到新 `BattleView` 后清除旧预选并刷新。按钮使用原生点按反馈，不等待额外微动效。
2. 点单位再点任务时生成 `set_ally_target` 草稿。顶部“取消预选”清除卡牌、单位、目标及换班草稿，不改变规则状态、随机快照或 revision。按钮支持原生键盘焦点；本期未实现或验收专门的焦点跳转编排。
   `play_card` 使用 `card_instance_id`，`set_ally_target` 使用 `unit_instance_id` / `task_instance_id`；值来自当前视图，不将视图的短字段名当作命令键名。
3. `pending_choice` 出现后，在右侧滚动列显示选择说明及 `ChoiceRequest.candidates`；“○/●”表示候选选择，只更新本地草稿。确认数量满足请求且 preview 允许时，提交匹配的 `confirm_choice`；保存、菜单、牌堆、规则和动画设置等其他操作保持禁用。失败保留已发布视图，错误显示在提示区，原因来自会话。K19 的 `kind=retain` 沿用同一候选/确认组件；其离手失效语义由规则层决定，不在 UI 推算。
4. 结束回合通过 `end_turn` 草稿提交；`retained_card_ids` 仅使用普通保留额度，不重新选择 K19 标记。无效操作由 preview 禁用并显示悬停原因，伪造请求仍由会话层拒绝；提交中防重复、失败显示原因、成功以新视图及事件提示反馈。交互立即响应，事件提示的时序见 [ACT-003](ACT-003-战斗事件演出.md)。
5. 本记录采用原生按钮、选中标记及文字反馈，无需独立图片；卡图与视觉状态见 [VIS-013](VIS-013-战斗画面与图片需求.md)。

## 验收与覆盖边界

- 给定需要目标的卡，当选择合法目标时，只提交一次带实例 ID 的 `play_card`；取消预选后不提交且规则状态不变。
- 给定 `pending_choice`，当尝试其他规则操作时，界面不产生可提交草稿；非法确认后待选面板仍可继续操作。
- 实现：[BattleScreen](../src/ui/battle_screen.gd)、[命令路由](../src/ui/game_shell.gd)；详细交互见 [G7 设计](G7界面与交互设计.md)。
- 实测：[G7 执行记录](../docs/G7界面执行记录.md)及 [UI 战斗测试](../tests/suites/test_ui_battle_choice.gd)。生产 P01、seed=0 下，K14 预选/取消不改状态，K03 产生真实弃牌待选；候选选择不改规则状态，确认只增加一次 revision，待选期间保存被拒绝，完成后恢复稳定保存。
- 本轮验证核心出牌/取消/待选/结束回合路径；未逐项穷举生产 K19、单位换班及全部目标组合的 UI 分支，规则覆盖与剩余生产验证分别见 G3 记录及 G8 范围。
