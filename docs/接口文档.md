# 《交大四年：DDL战争》接口文档

版本：v3.1｜日期：2026-11-04｜状态：新版公共交互目标；当前扩展见 §0，旧语义表保留为历史设计目标。

## 0. 当前四学年可调用扩展

本节为 2026-11-04 已接入原型的精确增量，覆盖下文对应的“第一学期终点/未实现”旧条款。范围与证据见[根计划 §0.6](../实施计划与验收基线.md)及[实现记录](四学年地图与视听实现记录_20261104.md)，G0/G8 状态不变。

| 接口/字段 | 当前约定 |
|---|---|
| get_setup_options | 默认首个 manifest 为 campus_four_year；另有 campus_v3、campus_mvp |
| start_run | 四年入口 P01～P04，起手 12 张、无开局饰品，内部 term=学年 1–4 |
| choose_campaign | 经 GameSession.submit；payload 白名单 offer_id、option_id、candidate_id、replace_relic_id；后两者可省略 |
| option_id | 饰品 claim/convert/skip；大奖励 card/upgrade/remove/resources/skip；服务 upgrade/remove/heal/money/progress/skip 或 direction_方向；方向 theory/engineering/competition/practice；去向 job/exam/research/abroad；熟人 money/skip |
| RunView.campaign_offer | 冻结 offer_id/kind/source_node_id/candidates，加只读 details、node_meta、service_cost |
| RunView.screen | 有未处理学年奖励/服务/方向/去向时为 campaign；不允许其他推进动作，仍可放弃整局 |
| BattleView.v3 | 领域 v3 的深拷贝，包含 paper/turn/synergy/abilities 等已存在状态，不公开隐藏抽牌序 |
| get_audio_settings() | 返回音量字典副本，不修改局状态 |
| update_settings(Dictionary) | 接受 autosave 与 audio；audio 必须完整包含 Master/Music/Ambience/SFX/UI 的 0–100 整数和 muted 布尔值 |

学年奖励是可保存的稳定待选择状态，与战斗内未结算完的 pending_choice 分开。公开提交仍检查 run_id/expected_revision；预览和拒绝不改变状态、RNG、revision。角色战斗动作与 DSL 细节见[卡牌实现契约](卡牌实现契约_v3.md)。

## 1. 公共约定

2026-11-11 测试房间扩展（设计定稿 v1.0，首版已实现，部分）：接口签名、DTO、错误码、文件类型与容量已在[测试房间功能设计 §7 与附录](测试房间功能设计.md)冻结。GameSession 已提供独立测试上下文入口：`start_test_room`、`get_test_view`、`get_test_room_options`、`begin_test_edit`/`cancel_test_edit`、`preview_test_patch`/`apply_test_patch`、`preview_test_action`/`submit_test_action`、`restore_test_checkpoint`、`step_test_history`、`restart_test_battle`、`set_test_outcome`、`save_test_preset`/`save_test_snapshot`/`save_test_record`、`list_test_files`、`load_test_preset`/`load_test_snapshot`/`load_test_record`、`close_test_room`。测试命令绑定 test_id/branch_id/expected_revision；覆盖层、检查点与测试文件独立于正式档。仍为设计目标：独立 `execute_test_rule_op` 入口（当前经 `run_rule_op` 编辑操作）、导入导出文件选择器与重放；部分规则开关仍仅保存。现有正式 start_run/restart_run 语义不变。实际覆盖与缺口见[实现记录](测试房间实现记录_20261111.md)。

UI只经GameSession读视图或提交命令，查询返回副本。定义ID、实例ID、run_id与业务幂等ID分工独立。金额、费用、次数与资源为整数，空集合不冒充未知值。

现有v1方法名可作为迁移入口参考，本文没有为新规则创建可调用接口；精确现有签名与字段可从Git 历史恢复。新版G0须冻结DTO及其白名单并升级兼容检查，不能把下列语义表直接当作当前schema。

## 2. 会话生命周期

| 现有入口名 | v3须保持的语义 |
|---|---|
| start_run / get_setup_options | 只提供已加载生产内容；新版目标四人，永久12张，无初始饰品；不能因旧生产仅开放两人而隐藏设计目标 |
| restart_run | 明确确认后在独立候选验证新局；处理旧终局待提交与原件归档，写盘成功后再替换，失败保留旧局 |
| continue_run / restore_backup | 正式档与显式备份恢复分别处理，不静默回退、不重抽冻结候选 |
| get_view / get_profile / inspect_saves | 只读；文件存在、可继续、Profile可用与设置错误分别表达 |
| generate_run_seed | 为新局生成种子，不推进活动局玩法随机流；开局后seed锁定 |
| preview_action / submit | 共用有效卡面、费用和合法性解析，预览无副作用，提交再次校验 |
| save_current / save_and_exit | 仅稳定边界；保存与Profile提交状态分别报告，任一步失败保留会话 |
| update_settings | 只更新已支持设置，不改变当前人物、难度、seed或revision |

新版选人信息须表达被动、两张专属起手、公共构成、资源和专属池；移除初始饰品要求。侵蚀有限复制的源/目标、诱发快照与触发次数、章节部署/换序/额外激活、论文区手动用牌、耗尽他牌和唯一发表取回等选择的精确字段与错误码尚待冻结，不假称已有v1参数支持。

## 3. 命令事务与返回

写上下文沿用run_id与expected_revision，旧局/旧视图请求拒绝。接受并改变状态或待选工作区的命令revision加1，拒绝、预览、查询、保存不加。start/restart新run_id从0开始。

返回须区分业务成功、只读视图、增量事件、待选、规则稳定、当前局持久化、Profile合并和标记清理。稳定只表示队列完成且无pending_choice，不表示已写盘。提交在状态与RNG副本执行，异常不发布半套结果；磁盘失败不撤销已经发布的业务状态或重发收益。

## 4. 战斗动作

| 动作语义 | 校验与结果 |
|---|---|
| 打出手牌 | 传实例，先升级/考试面，再目标、资源选值、费用、限次，整体支付 |
| 论文区手动使用 | 校验已开题、章节实例/生效记录、费用和同名限次；只基础+记账，不额外常驻 |
| 效果内确认 | 仅当前choice_id与合法候选/范围；错误保留工作区，不能取消已揭示抽牌的整牌 |
| 结束回合 | 无待选才可提交，保留规则按当前卡面；清行动末诱发/检索连锁→自动合作→弃牌→任务行动→轮末DDL |

伙伴默认自动选择协作目标，额外行动由卡文且每实例每回合最多一次；不新增通用指定目标动作。R3-T201不能升级/复制/变化/耗尽/永久删除；所有衍生/临时不得进入永久操作。章节重用与换序也由领域校验，不能只靠UI拦截。资源不足或同名能力已生效时应返回可显示的禁用原因。

## 5. 局流程动作

| 动作语义 | 校验与结果 |
|---|---|
| 进入/离开节点 | 校验拓扑与完成条件；返回地图，由玩家点击下一站 |
| 领取/跳过奖励 | 当前offer及候选ID有效、未领取，资格符合当前人物；一次执行 |
| 购买 | 当前库存价格由领域层读取，不接受UI自报价格；成本与发牌整体提交 |
| 事件与变化 | 选项、永久卡目标、资格与下限预检；空变化池在支付前禁用 |
| 升级/训练 | 永久卡最多1级；合作牌双面一起升级，衍生及临时排除 |
| 放弃/总结 | 确认后形成一次性摘要；期末终点不追加构筑奖励 |

删牌服务与未定经济须先G0裁决，不能沿用旧费用。所有授牌来源均经过同一人物+公共过滤，业务ID保证重复请求无收益。

## 6. 视图与事件

SessionView由会话组装当前页面、revision、RunView/BattleView、pending_choice、can_save、终局摘要与持久化诊断。BattleView须公开前牌/连携、论文进度/引用/修正/完成度/付款及两集合、唯一发表位置、三槽章节/生效/激活、六种任务负面/窗口、诱发剩余次数、检索剩余抽牌及复合反应机会、协同/伙伴精力/额外行动、限次、有效面、任务阶段/意图和场景计次；不公开隐藏抽牌顺序与未发生随机结果。RunView须展示奖励与商店归属、完整效果和资格原因。

沿用事件事实结构 `{index,type,source_id,target_ids,data}`；会话统一连续index，历史消费键为run_id/revision/index，离场对象显示名称快照。论文记账/发表/章节、侵蚀自然/提前、诱发、检索施毒/批次及复合反应及伙伴额外行动的事件类型与data字段待G0，不能据文字假称已注册。日志与动画可分别消费同一事实，表现关闭不影响领域状态或RNG。

## 7. 错误与恢复

沿用错误分类：请求/旧revision、阶段/目标/费用、内容无效或未支持、存档缺失/损坏/不兼容/IO失败。新资源与资格失败如何映射到具体错误码待冻结；不得吞错继续或伪装成玩家失败。备份须显式选择，损坏旧档先原样归档再明确重开。
