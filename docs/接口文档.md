# 《交大四年：DDL战争》接口文档

版本：v0.5｜日期：2026-10-15｜状态：G5 存档恢复接口已接线；正式阶段验收以根计划及运行记录为准

依据：[架构设计基线](初步架构设计.md)与[实施计划与验收基线](../实施计划与验收基线.md)。本文描述 Godot 进程内接口。DTO、统一结果结构和 `GameSession` 方法签名在 Godot 4.7.2 下实现为 `src/common/`、`src/app/game_session.gd` 中的可编译类型。`GameResult.data` 在 GDScript 中以 `Variant` 承载契约定义的具体返回对象；G4 已实现开局、查询、预览、提交与局/战斗原子交接；G5 已接入正式档继续、显式备份恢复、稳定保存、设置持久化及 Profile 幂等合并，相关入口不再返回 G5 占位错误。实现、测试与阶段正式通过分别记录，正式验收状态以根计划为准。玩法数值按基线来源表核对。

接口标识及规则数值入口见[内容层契约 §7](内容层契约.md)，操作名与错误码使用GameConstants中的同名常量值。

内部方法和实体行为见[初步架构设计 §10](初步架构设计.md)，保存布局与关系约束见[数据库与实体关系设计](数据库与实体关系设计.md)。

## 1. 公共约定

- UI只调用GameSession；BattleEngine、RunService、ContentDB和SaveStore由会话层协调。
- 查询返回只读视图或副本。外部不得直接修改内部状态。
- 所有规则写操作同步执行至规则稳定边界或唯一待选位置；动画不推进规则。这里的“规则稳定”只表示效果队列已完成且没有 `pending_choice`，不表示该 revision 已写入磁盘。
- ID使用字符串：定义ID如K01；卡、单位、任务使用各自唯一实例ID。目标参数必须传实例ID，不能传名称。
- 可空字段用`null`，集合无内容用`[]`或`{}`。金额、费用、次数、精力和DDL使用整数。
- 本局所有写操作共用一个会话`revision`，由GameSession管理；`start_run`创建新`run_id`时初始值为0，不执行增量提交，继续游戏恢复快照中的revision。此后每次接受并改变会话视图或待选工作区的命令递增1。拒绝、预览、保存和设置更新不递增；`run_id + expected_revision`共同拒绝旧局或旧视图请求。

### 1.1 写操作上下文

`CommandContext`由UI随每次写请求传入：

| 字段 | 类型 | 说明 |
|---|---|---|
| run_id | String | 必须等于当前局 |
| expected_revision | int | 必须等于当前视图版本 |

旧版本请求返回`STALE_STATE`，不再次执行。UI刷新视图后由玩家重新操作，不自动重发购买或出牌。战斗结算与奖励另用业务ID/领取标记保证只执行一次。

### 1.2 返回结构

普通查询和存储使用`Result<T>`：`{ok: bool, data: T或null, error: ApiError或null}`。

规则写操作使用`ActionResult`：

| 字段 | 类型 | 说明 |
|---|---|---|
| accepted | bool | 命令是否已接受并发布会话变化；待选工作区变化也算已接受。拒绝或规则异常时为false，保留命令开始前的已发布状态 |
| revision | int | 当前版本；失败时仍返回原版本 |
| view | SessionView | 操作后的只读视图 |
| events | Array<RuleEvent> | 本次增量事件，拒绝时为空 |
| pending_choice | ChoiceRequest或null | 效果内选择，存在时只能确认该选择 |
| stable | bool | `true`表示没有待选续算工作区；只表示规则队列完成，不表示已经写盘 |
| error | ApiError或null | 规则拒绝原因；接受时为null |
| persistence | String | `not_attempted / saved / failed`，仅表示`current_run`快照写盘结果 |
| save_error | ApiError或null | 当前局快照写入失败原因，与规则错误分开 |
| profile_merge | String | `not_pending / pending / merged / failed`，表示终局摘要写入Profile的状态 |
| profile_error | ApiError或null | Profile写入失败原因；当前局可能已成功写盘 |
| profile_cleanup | String | `not_needed / pending / cleared / failed`，表示已合并摘要在current_run中的待处理标记清理状态 |
| cleanup_error | ApiError或null | 清理标记后的current_run写入失败原因；Profile可能已经合并成功 |

`ActionResult`将规则结果、`current_run`写盘和Profile合并分开报告。规则命令已完成且自动保存失败时，`accepted=true`、`stable=true`、`persistence=failed`；保留内存结果，只重试保存，不重做原操作。若应用随后异常退出，恢复到最近一次成功写入的稳定快照。`autosave=false` 时规则稳定提交的 `persistence=not_attempted`；只有 `save_current()` 或 `save_and_exit()` 成功写入当前局才算持久化。含终局摘要的 current_run 写盘成功后才允许合并 Profile。

`SessionSaveResult = {current_run_receipt: SaveReceipt, profile_merge: ProfileMergeStatus, profile_error: ApiError或null, profile_cleanup: ProfileCleanupStatus, cleanup_error: ApiError或null}`。`ProfileMergeStatus`为`not_pending / pending / merged / failed`；`ProfileCleanupStatus`为`not_needed / pending / cleared / failed`。`current_run_receipt`指本次最后一次成功写入的current_run快照。若第一步当前局写盘失败，方法返回`Result`错误且不开始Profile合并；若Profile写入失败，返回成功的`SessionSaveResult`，其中`profile_merge=failed`、`profile_cleanup=pending`。若Profile写入成功但清理标记写盘失败，返回`profile_merge=merged`、`profile_cleanup=failed`，保留部分成功事实并允许重试清理。无待合并摘要时返回`not_pending / not_needed`。

`ApiError = {code: String, message_key: String, details: Dictionary}`。`details`可包含字段名、缺少资源、当前版本等诊断数据。`ENGINE_NOT_READY`保留为历史工程常量，当前 G5 存档、继续、设置入口不使用该占位返回。

## 2. GameSession：UI入口

| 方法 | 参数 | 返回 | 前置条件/行为 |
|---|---|---|---|
| start_run(request) | StartRunRequest | ActionResult | 无进行中局；校验人物、难度和内容清单后开局，新`run_id`的revision为0；自动保存失败不撤销内存中的新局 |
| continue_run() | 无 | Result<SessionView> | 无内存局；只读取正式档，校验后恢复；已持久化待合并摘要自动幂等重试，部分成功由视图报告 |
| get_view() | 无 | SessionView | 只读；未开局返回主菜单视图 |
| preview_action(draft) | ActionDraft | Result<ActionPreview> | 不改状态、不消费随机 |
| submit(context, action) | CommandContext、GameAction | ActionResult | 校验当前局、版本与阶段后路由 |
| save_current() | 无 | Result<SessionSaveResult> | 仅规则稳定边界；待选状态返回`CHOICE_PENDING`；当前局写盘后继续尝试待合并Profile摘要 |
| save_and_exit() | 无 | Result<SessionSaveResult> | 仅规则稳定边界；当前局写盘且Profile合并与标记清理均完成后才释放会话；待选或任一步失败均保留会话 |
| get_profile() | 无 | ProfileView | 只读解锁、教学记录与设置；分别返回 Profile/Settings 错误诊断 |
| update_settings(settings) | SettingsPatch 或 Dictionary | Result<ProfileView> | 校验已支持字段后保存，写盘成功才发布设置；不改变局revision或当前难度/seed |
| inspect_saves() | 无 | Result<SessionStorageView> | 只读查询正式档、备份及内存局状态，不自动恢复 |
| get_setup_options() | 无 | Result<SetupOptions> | 已加载且在生产 allowlist 的人物/难度/manifest，与解锁条件一起返回 |
| restore_backup() | 无 | Result<SessionView> | 仅无内存局时显式读 current_run 备份；兼容/不变量全部校验通过后发布，保留正式档，后续显式或自动稳定保存才替换 |


`StartRunRequest = {character_id, difficulty, manifest_id, seed}`。当前生产目标 campus_mvp，仅提供 difficulty=normal；relaxed/hard 属完整版本，不出现在 MVP 的可选项。manifest 必须在生产 allowlist 且已由 ContentDB 成功加载；test_ fixture 不进入玩家入口。seed 为十进制整数字符串，开局后 seed 与 difficulty 锁定。存在任何内存局、未结束磁盘局或待合并摘要时返回 RUN_ACTIVE，不能覆盖；损坏或不兼容的正式档返回其实际错误。正式档缺失但备份存在时要求显式处理备份，损坏备份也不能被新局静默覆盖。新局 revision=0，autosave 失败仍保留内存局并报告 persistence=failed。

`SetupOptions = {characters:[{id,name_key,starter_cards,starter_relic_id,locked,reason}], difficulties:[normal], manifests:[{id,content_version,content_hash}], default_difficulty, default_seed}`；集合来自已加载生产内容。

`SessionStorageView = {has_active_session, has_save, save_meta:SaveMetadata或null, save_error:ApiError或null, backup_meta:SaveMetadata或null, backup_error:ApiError或null}`。缺档由 has_save=false 与 SAVE_NOT_FOUND 表达；损坏档仍返回可展示的诊断，不把它当作无档覆盖。本查询只聚合current_run及其备份诊断；Profile/Settings由get_profile与update_settings提供。continue_run 只读正式档；正式档失败返回错误，备份须由 restore_backup 显式选择，不能静默回退。

`SettingsPatch` 在MVP只接受 autosave:bool，也可直接传入同构 Dictionary；空 patch 保留当前值。首次无设置档且无备份时默认为 true。未知键或非 bool 值返回 INVALID_ARGUMENT；已损坏/不兼容设置档，或正式缺失而备份存在/损坏时，保留错误并拒绝覆盖，详情通过 ProfileView.settings_error 返回。音量、显示和输入字段在G7详细设计时明确键名并扩充契约后才可支持。default_difficulty/default_seed 若后续支持只作用于未来开局；不接受 difficulty/seed 来改变当前局。内容和设置字段的扩充先更新契约再实现。

### ProfileView

`ProfileView = {available, unlocked_characters, unlocked_endings, completed_run_ids, autosave, unlocked_ids, seen_content_ids, tutorial_flags, error, settings_error}`。集合与教学字典均为副本；completed_run_ids 从已去重摘要的键排序取得。available 表示 Profile 已成功读取或在正式档与备份均不存在时得到空默认值；它不表示首次默认 Profile 已写盘。error 表示 Profile 读取/校验错误，settings_error 独立表示设置错误；这两类错误不得被显示为空进度后自动覆盖。Profile 正式档缺失但备份存在或损坏时同样保留诊断，不初始化新文件。

### SessionView

```text
run_id: String或null
revision: int
screen: menu / map / battle / reward / shop / event / rest / term / ending / summary
run: RunView或null
battle: BattleView或null
node: 当前节点视图或null
pending_choice: ChoiceRequest或null
can_save: bool
terminal_summary: RunSummaryView或null
event_log: Array<LoggedRuleEvent>
profile_commit_status: Dictionary
```

`profile_commit_status` 为 `{profile_merge, profile_cleanup, profile_error, cleanup_error}` 或尚无提交时的空字典；错误值为 ApiError 的字典副本或 null。继续游戏读到持久 pending 时自动重试 Profile 合并及标记清理；即使载入成功，重试仍可能部分失败，调用方须读取此字段。显式恢复备份可以先合并 Profile，但暂缓 current_run 标记清理，返回 merged/pending，保留正式档；后续稳定保存才清理标记并替换正式档。

BattleView包含当前精力、专注、DDL、手牌及有效卡面、单位、任务、意图、场景和牌堆数量。默认不暴露抽牌堆顺序和未公开随机状态；查看牌堆时展示规则允许的信息。`zones_public` 字段提供弃牌堆与耗尽堆的卡面（与 `hand` 同构），抽牌堆与结算区只给计数。

## 3. GameAction：写操作清单

`GameAction = {type: String, payload: Dictionary}`。除标明可空的字段外，表内字段均必填。

### 3.1 战斗操作

| type | payload | 规则 |
|---|---|---|
| play_card | card_instance_id、target_ids、replace_unit_id（可空） | 玩家行动阶段；先解析考试卡面，再校验目标、费用和换班 |
| confirm_choice | choice_id、selected_ids | 仅处理当前ChoiceRequest，不能选择不在候选中的ID |
| set_ally_target | unit_instance_id、task_instance_id | 玩家行动阶段；双方实例必须仍有效 |
| end_turn | retained_card_ids | 玩家行动且无待选项；仅用于明确授予的普通保留额度，默认0；K19 执行时标记另一张牌，不在此临时任选，可为空数组 |

出牌前取消选牌、目标或换班属于UI本地操作，无需提交。K03抽后弃牌等效果已经开始时返回ChoiceRequest，必须完成选择；不能调用取消整张牌的接口。

`ChoiceRequest`字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| choice_id | String | 本次选择唯一ID，完成后失效 |
| kind | String | `discard / recall / purify / retain` |
| prompt_key | String | 提示文本键 |
| candidates | Array<ChoiceOption> | 每项为`{id, label_key, preview}` |
| min_count / max_count | int | 数量限制；可选效果允许min_count=0 |
| source_card_id | String或null | 来源战斗卡实例，可空 |
| effect_amount | int或null | 选择后实际处理的层数/数量，可空 |


无合法候选时由引擎按“尽量执行”等牌义自动处理，不返回无法完成的强制选择。确认选择若仍产生后续选择，返回新的choice_id。错误选择不清除原待选状态。

### 3.2 局流程操作

| type | payload | 规则 |
|---|---|---|
| enter_node | node_id | 只能进入地图当前可达节点 |
| claim_reward | offer_id、item_id、candidate_id（可空）、replace_relic_id（可空） | 领取指定奖励项；直接收益无需candidate_id；满槽须提供替换对象 |
| skip_reward | offer_id、item_id | 跳过尚未处理且允许跳过的奖励项 |
| buy_item | shop_id、stock_id、replace_relic_id（可空） | 按库存实际价格校验、支付、发放；不接受UI自报价格 |
| remove_card | shop_id、card_instance_id | 校验余额、删牌次数和至少保留5张 |
| choose_event | event_instance_id、option_id、selection_ids、replace_relic_id（可空） | 一次收齐升级/删牌等目标及替换选择后提交 |
| take_rest | node_id、option_id、card_instance_id（可空） | 恢复无需卡目标；升级、训练和删负担需合法卡 |
| leave_node | node_id | 商店离开、事件无变化离开或所有必处理项完成后退出 |
| choose_term_option | settlement_id、step_id、option_id、candidate_id（可空） | 处理学期路线、履历或方向奖励的当前步骤 |
| choose_ending | ending_id | 只能选当前满足条件的结局 |
| abandon_run | confirmed | confirmed必须为true；稳定边界结束当前局，不给战胜奖励 |

候选ID、option_id及step_id由当前节点视图提供，UI不自行构造规则条件。已领取奖励、已售库存、已完成节点不能再次提交。取消交易预选不发送命令。

### 3.3 预览

`ActionDraft`与GameAction字段相同，但允许缺少尚未选择的目标。

`ActionPreview = {revision, can_submit, required_selections, costs, known_effects, unknown_effects, effective_card, blocking_errors}`。BattleEngine 生成预览时 `revision=-1` 表示尚未绑定；GameSession 必须从会话状态写入当前 revision，revision 不属于 BattleState。

缺目标等正常预选情况通过required_selections和blocking_errors描述；未知操作类型、未知 payload 键等请求格式错误才返回Result失败。BattleEngine 支持出牌、结束回合、待选确认和单位目标；RunService 提供节点、交易、事件与休息预检，并返回必要的目标候选、已知效果和成本。费用与有效卡面使用执行时同一解析函数，提交仍重新校验；`replace_unit_id` 可省略或传 `null` 表示未选择替换单位。预览不预测隐藏抽牌或抽取消耗随机结果。

## 4. BattleEngine：规则接口

唯一公共签名、BattleInput/BattleStep/BattleOutcome/BattleView 与状态机见[战斗模块契约 §1–§8](战斗模块契约.md)。会话传完整四流快照，引擎只推进 battle 流。

待选续算只驻内存；每次 confirm_choice 在最近已发布工作区及随机副本上执行，错误保留已有工作区，成功发布并递增一次 revision，队列完成才允许保存。内部异常返回 RESOLUTION_ERROR，不伪装成玩家失败；进程中断恢复最近成功写盘的稳定快照。

## 5. RunService：局流程接口

唯一公共签名、RunStep/RunView 和终点流程见[局流程契约 §1–§4](局流程契约.md)。create 从 request.seed 初始化四流，其余写调用显式接收完整快照；只推进 map/reward/event，battle 原样返回。

GameSession 将战斗结算、写回精力和创建奖励放在一次会话发布中；后续领奖是独立命令。交易全部校验后整体应用，失败不扣费、不发牌、不消费随机。MVP B01 胜利直接 finalize 摘要，完整 B08 选择去向后才 finalize。

## 6. ContentDB与RandomSource

ContentDB 的加载/查询/候选 API 和 RandomSource 的四流导出、恢复、抽取 API 只在[架构 §10.5](初步架构设计.md)维护；内容 JSON 只在[内容契约 §8](内容层契约.md)维护。失败加载保留旧有效索引，未知 op/字段/引用返回 CONTENT_INVALID。查询不消费随机；64位 seed/state 在 JSON 中使用十进制字符串。

## 7. SaveStore：文件存储接口

存储签名、外壳、checksum、领域 Codec 与三步提交唯一见[存储契约 §7–§11](数据库与实体关系设计.md)。UI 只调用 GameSession 的查询、继续、恢复、保存入口。SaveStore 仅执行文件 IO 与完整性校验，不注入 ContentDB、不补内容元数据、不迁移或解释规则。

稳定终局先写 current_run（terminal_summary 与 profile_merge_pending=true）→按 run_id 幂等写 Profile→只清 profile_merge_pending 并再写 current_run。保留摘要与 event_log，重启后仍能查询总结；未完成时不得覆盖旧局。autosave=false 时显式保存触发。三个步骤的部分成功按 §1.2 分别报告，不能重新执行终局收益。

## 8. 规则事件与UI通知

领域输出 `RuleEvent = {index,type,source_id,target_ids,data}`；index 从0递增，仅在本次结果内唯一。GameSession 合并多个模块结果后重新连续编号，并给历史记录附加 `{run_id,revision,index}` 作为唯一消费键。来源或目标允许离场；LoggedRuleEvent 增加 source_label 与 target_labels 的显示文本快照，不用旧实例重新查询名称。

SessionState.event_log 是有界、有序的 LoggedRuleEvent 数组，工程上限1000条，超出只移除最旧条目；该上限是日志存储预算，不是玩法数值。与当前局稳定快照一起保存并由 SessionView 提供；从未保存的待选工作区产生的日志也只驻内存，重启回到磁盘日志。下表键全部位于 data，事件生产者只输出下表类型和固定载荷；局流程命令的未知 type/payload 键直接返回 INVALID_ARGUMENT。

## 9. 错误码

| code | 含义 | 调用方处理 |
|---|---|---|
| INVALID_ARGUMENT | 格式、枚举或数量非法 | 修正请求 |
| RUN_ACTIVE / RUN_NOT_FOUND | 局状态不符合操作要求 | 返回对应页面 |
| STALE_STATE | 视图版本过期 | 刷新视图，不自动重发写操作 |
| WRONG_PHASE | 当前阶段不允许 | 更新按钮状态 |
| INVALID_TARGET | 实例不存在或目标类型不符 | 重新选择 |
| INSUFFICIENT_RESOURCE | 钱、专注、精力或状态资源不足 | 显示缺少项 |
| UNPLAYABLE | 卡定义明确不可打出 | 禁用出牌并展示原因 |
| LIMIT_REACHED | 本回合/本战限次、容量或删牌下限 | 显示限制 |
| CHOICE_PENDING | 必须先完成效果内选择 | 聚焦选择界面 |
| ALREADY_RESOLVED | 节点、奖励、库存或战斗已结算 | 刷新，不重复执行 |
| CONTENT_INVALID | 定义或引用不合法 | 阻止进入，报告具体ID |
| SAVE_NOT_FOUND | 指定正式档或备份不存在 | 查询另一来源；正式与备份均无档时才允许初始化 |
| SAVE_CORRUPT | 存档结构、校验和或领域不变量损坏 | 保留文件与诊断；current_run 可显式选择有效备份 |
| VERSION_MISMATCH | 格式、内容或随机算法不兼容 | 保护原档并提示 |
| SAVE_IO_ERROR | 写入或读取失败 | 保存可重试，不重做游戏操作 |
| RESOLUTION_ERROR | 内部规则异常 | 保留命令开始前的已发布状态和诊断信息 |
| ENGINE_NOT_READY | 历史工程占位常量；当前 G5 会话入口不返回 | 若未来新增未接线入口，先补齐契约与实现后再公开 |

## 10. 调用示例与验收

### 打出K01对应的手牌实例

```json
{
  "context": {"run_id": "run_001", "expected_revision": 12},
  "action": {
    "type": "play_card",
    "payload": {
      "card_instance_id": "card_017",
      "target_ids": ["task_001"],
      "replace_unit_id": null
    }
  }
}
```

合法提交后revision变为13；重复发送上述revision=12请求返回STALE_STATE，费用只扣一次。若这次操作需要后续选择，UI读取pending_choice，再用新revision提交confirm_choice；期间save_current返回CHOICE_PENDING。

### 商店购买饰品

先preview_action获取实际成本和所需替换对象→玩家确认→submit buy_item。取消预选不调用submit；规则提交成功但保存失败，只调用save_current重试。库存已售再次购买返回ALREADY_RESOLVED。

### 接口验收要点

1. 查询、预览与取消不改revision或随机状态。
2. 旧revision、非法目标、资源不足均无副作用。
3. 备考/回忆卡面在预览与执行中完全一致。
4. 效果内选择不能被其他写操作绕过。
5. 战斗结算、奖励领取和Profile摘要不会重复应用。
6. 存档错误与规则错误分开，读档恢复触发次数与随机结果。
