## 3. 新增 schema 与引擎能力

内容层（`src/content/content_db.gd`，白名单与校验同步扩充）：

| 位置 | 字段 | 语义 |
|---|---|---|
| task | `victory_required`（可选，默认 true） | 为 false 的可选任务不参与胜利判定 |
| task.phases[] | `intent_loop`（`cycle` 默认 / `clamp`） | `clamp` 表示意图推进到最后一个后停留，用于"仅第一回合" |
| task.phases[].intents[] | `pressure_per_unit`、`pressure_per_unit_cap` | 每个存活合作单位增加压力，按上限裁切 |
| task.phases[].intents[] | `summon_tasks`（`[{task,count}]`） | 战斗中生成任务；每个任务实例只生效一次 |
| task.phases[].intents[] | `transform_task`（`{task}`） | 以目标定义的首阶段替换自身，保留未完成量并按新上限裁切 |
| task.phases[].intents[] | `ddl_bonus` | 推进剩余 DDL |
| task.phases[].intents[] | `self_destruct` | 压力结算后移除该任务 |
| encounter | `initial_members` | 只让列出的成员在开战时入场，其余供召唤 |
| encounter | `absorb_cooperation`（`draw_per_card`／`focus_per_card`） | 开战吸收合作牌：移入消耗堆，每张换抽牌与专注 |
| status | `brainstorm`（绞尽脑汁）、`confusion`（迷惑） | 目标为任务的敌方增益：压力 +1/层、屏障 +1/层（cap 3） |

引擎侧（`src/battle/battle_engine.gd`）：

1. `begin` 只实例化 `initial_members`；准备阶段后执行合作牌吸收（`card_absorbed`，专注受上限裁切，抽牌走 battle 流）。
2. 敌方技能阶段按 `shield`（含迷惑加成）→ 状态/恢复/加牌 → `ddl_bonus` → 记录召唤/转换 的顺序结算；召唤与转换都在实际压力阶段之后落场，因此触发它们的当回合不会额外施加新形态/新任务的压力，下一回合从目标定义的第一个意图开始。
3. 压力阶段改为按索引遍历：先叠加 `extra_requirements`、`brainstorm`、单位数缩放，再按 `pressure_times` 分段结算；`self_destruct` 在压力后移除任务并重新判定结局。
4. 轮末意图推进支持 `clamp`，预置屏障同样计入迷惑加成。
5. 结局判定改为"不存在必需的存活任务"即胜利，因此可选任务存活不阻止胜利。
6. 新增事件：`card_absorbed`、`task_summoned`、`task_transformed`、`task_self_destructed`、`ddl_adjusted`。
7. 召唤每实例一次的计数使用 `battle` 作用域计数键，随快照持久化；**未新增战斗状态字段**，`BattleCodec` 的字段集合与存档 schema 不变（旧档仍可解码）。
8. 战斗页最小配套：我方状态栏只显示 `target_id` 为玩家的状态，避免任务增益（绞尽脑汁/迷惑）混入我方；任务增益暂以任务卡 tooltip 的"增益："文字呈现。专用图标与召唤/转换/自爆演出登记为 R2-VIS-006/R2-ACT-002，留待 G7。

## 4. 对草稿的解读与偏差（必须明示）

1. **Q0A 顶层"小组大作业"未建任务。** 草稿顶层未完成量为 `.../8`，没有可实现的数值；本轮按草稿给出的三个子任务（27/29/25）直接组成遭遇。草稿"2 阶段三选一、3–4 阶段三选二、5 阶段全上"的按学期子集未实现：当前所有学期固定上三个子任务，需 G0 决定子集规则与随机性。
2. **Q0A 吸收合作牌的语义。** 草稿仅写"战斗中自动吸取消耗所有合作牌转化为抽牌和专注"。本轮按"开战时牌组中每张合作牌移入消耗堆，换 1 抽牌与 1 专注"实现（`absorb_cooperation`）。若原意为"每回合打出合作牌时转化"，需改契约与实现。
3. **Q0B 的"保留血量"。** 作业答辩 45 → 答辩作业 15 无法逐字保留剩余量；实现为保留剩余未完成量但按新形态上限 15 裁切，转换当回合不结算压力，剩余 DDL +1。答辩作业 A 的"恢复 5 未完成量"实现为对自身 `work_restore 5`。
4. **Q0A_3 的召唤频率。** 草稿 C 意图未注明是否重复；本轮令召唤在每个任务实例中只生效一次，C 意图本身仍按 A→B→C 循环。
5. **绞尽脑汁／迷惑的数值。** 草稿只写"类似力量／敏捷"；本轮取 +1/层、上限 3。E 系列未使用这两项，仅 Q0C/Q0D/Q0E 使用。
6. **学期范围。** 草稿 2 §3 只写"后续学期"；本轮取 E04 2–4、E05 3–5、E06 2–4、E07 4–6，属暂定值，G0 需冻结。E01/E02/E03 的 1 学期入选与草稿 2 §2 一致。2026-11-02 按用户要求把 Q0B、Q0C 的学期范围提前包含第 1 学期（草稿原为 2–4 与 2–6），见 §7。
7. **E03 无考试标签。** 草稿 2 对"精英是否允许无独立作答"仍标为 G0 依赖；本轮按草稿正文实现（不设标签、允许单位、压力随单位数上升）。
8. **Q0C→Q0D 的跨战斗替换。** "击败四级后四级全部替换为六级、击败六级后不再出现"需要跨局进度与投放过滤，本轮未实现，二者仅按学期池并存。这是本轮最大的行为缺口。

## 7. 第一学期首期试玩（2026-11-02）

**入选名单。** 第一学期精英池 = `Q01`（v1 原有）、`E01 期中考试`、`E02 课程设计中期检查`、`E03 小组项目冲刺`（草稿 2 §2 指定首期）、`Q0B 作业答辩`、`Q0C 英语四级`（本轮按用户要求提前）。每局只有 1 个精英节点，因此单局遇到"新增精英"的概率是 5/6。

**测法。** [playtest_elites.gd](../artifacts/playtest-20261102/playtest_elites.gd) 在 Godot 4.7.2 headless 下用真实生产内容、`RunService` 起始牌组与饰品跑完整战斗：机器人按"先挡伤害 → 再打作业 → 其它"的简单优先级出牌，**不带任何节点奖励或升级**，因此结果是难度下限。每个（人物 × 精英 × seed）24 场，共 624 场；0 异常、0 未完成、0 引擎错误。

**结论与处置**

1. `Q0B`/`Q0C` 偏易：两人物 100% 胜、3–5.6 回合结束、剩余 DDL 4 以上。它们正好展示"形态转换"与"敌方增益"两条新机制，适合首期演示，但不构成压力。建议下次平衡从 DDL（Q0C 10→7、Q0B 8→6）或压力档入手；本轮保留草稿数值。
2. `Q0A`/`Q0D` 近似必败：Q0A 三个子任务每回合合计 15–27 压力、81 点总量却只有 8 DDL；Q0D 首回合 13 点后持续 6＋绞尽脑汁。**调低前不得进入第一学期**。
3. `E01` 对 P04 近似必败（4%）：`independent_answer` 废掉 P04 起手中的两张合作牌，只剩公共牌；与草稿"唐以宁只能用考试面、需要更保守"的预期一致，但对起始牌组过严。若要保证两人物都能过首期，优先给 P04 替代起手，或把 E01 的 DDL 上调 1。
4. `E02`/`E03` 两人为 50–100%，是当前最接近"有压力但可过"的两项；`E01` 对 P01 也在 83%。
5. 以上是机器人下限：真实玩家会带节点奖励、升级、更多饰品，胜率应更高；机器人也不会利用弃牌/回收配合。**不据此冻结平衡**，只作为 G3/G8 的起点与回归基线。
