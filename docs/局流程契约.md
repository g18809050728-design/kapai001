## 1. 边界与状态

RunService负责开局、地图、节点、奖励/商店/事件与终局摘要，GameSession协调战斗交接及唯一revision。create、preview、apply、settle_battle、make_view为现有职责入口参考；新版字段待G0，精确v1定义见Git 历史。

RunState保存人物、精力、生活费、永久牌实例、节点路径、已见事件、冻结奖励/库存和结算幂等标记。所有写入在状态与完整RNG副本执行，只推进map/reward/event流，battle流不变；preview无副作用。失败不扣款、不发卡、不耗随机，不能发布半个交易。

## 2. 开局与地图

新版目标四人可选，每人永久12张：R3-C-01×4、R3-C-02×4、R3-C-03×1、R3-C-04×1加各自两专属；精力72、生活费60、正常难度，无初始饰品。P02开题固有占首次基础抽5一格，开题后生成唯一发表；论文衍生不加入永久牌组。旧包的两人物allowlist不能当作新版设计限制。

第一学期6层/8个候选节点，每条路线经过6节点，第2与4层二选一，保留不打精英路线。校验拓扑、节点状态与必处理项；完成后返回地图，下一站由玩家点击进入，商店主动离开。活动战斗期间禁止其他节点写操作。

## 3. 所有永久卡来源统一过滤

先确认卡为当前人物专属或公共，排除基础R3-C-01/02与全部衍生/临时，再执行来源稀有度与同次去重。每人可见40专属+10非基础公共=50种。奖池已有同ID可再次获得，单次候选ID不得重复。变化、事件直发与永久生成也执行同一资格判断，不能只过滤普通奖励。

| 来源 | 数值与规则 |
|---|---|
| 普通战 | 3不同ID候选可跳过；每位置75%专属/25%公共，普通/进阶/稀有70/25/5 |
| 精英 | 相同角色份额，稀有度35/50/15 |
| 商店 | 3专属1公共，ID不同；稀有度60/30/10，售价45/75/120，入店冻结 |
| 交流方法事件 | 本角色普通/进阶70/30的2选1，可不拿 |
| 调整学习计划事件 | 合法永久牌变化为同资格同稀有度另一ID；无候选支付前禁用，删后不得少于8张 |
| 期末终点 | 直接总结，不追加无后续用途卡牌 |

空稀有度按普通→进阶→稀有固定找非空层，角色/公共一侧空则转另一侧，两侧全空缩短候选；不补其他人物卡、不重复ID。使用reward流，只生成一次，候选随稳定快照保存；预览、重绘和继续不重抽。完整语义见[角色设计](角色与专属卡池重设计_v3.md)§8。

## 4. 事件、休息与未定经济

旧事件显式卡池、饰品奖励及空饰品池折钱退出v3。人物故事以角色设计§8为候选，事件名单/文本/成本待G0，不能照抄旧V事件收益。免费故事选择每局每事件一次，互斥，不产生跨战人物资源。

每张永久牌最多升级1次，所有衍生/临时排除；训练合作等同升级普通/考试双面，不维护永久单位属性。节点生活费、餐食/休息恢复、升级与删牌服务价格/次数、通用删牌下限未定，先冻结才实现；不能将旧运行数值当作新定案。

## 5. 战斗交接、结算与持久化

进入战斗把遭遇、人物、永久牌来源、精力与完整四流快照交给BattleEngine；只在begin成功后共同发布节点/战斗状态。结算按battle_id幂等写回剩余精力、记录结果与生成奖励，不以动画完成为触发。

第一学期B01真正三阶段完成后直接形成终局摘要；失败/放弃同样只形成一次摘要，不给未完成旧局通关奖励。GameSession按run_id执行当前局→Profile→清标记的三步提交，存储故障只重试持久化，不重新打战斗或抽奖励。明确替换旧局先归档/校验，详见[存储设计](数据库与实体关系设计.md)。

## 6. 后续验证与边界

新版G4/G5须逐个覆盖所有授牌入口、空池、去重、余额不足、非法目标、双击、旧revision、重绘不耗随机、候选恢复与终局去重。R3-T20为跨入口核心用例；本轮未运行。先完成新版G0，不能借用旧四路线或六节点通过记录证明新卡池与经济可玩。
