> 本文是[四大地图复杂化设计方案](四大地图复杂化设计方案.md) §2.10 的独立展开文档。地图文档只保留触发位置、次数和摘要；本文维护饰品奖励、学期结束大奖励、饰品槽、强度边界、候选池、验证计划与 G0 待决项的完整设计。两处冲突时，以本文为准，再回写地图文档。

> 现行 v3 首期明确“不装备、不投放 v1 饰品”。本文是**范围变更候选**，不是现行规则；G0 批准前不得写入运行数据、生产 manifest、测试 fixture 或玩家存档。本文也不新增卡牌、单位、场景或考试面。

## 1. 定位与范围

- 每个学年大地图（大一至大四）固定提供 **2 次饰品奖励**，分别放在上、下两个学期的中点。
- 每个学期 Boss 结算后提供 **1 次学期结束大奖励**。
- 完整四年共 **8 次饰品奖励 + 8 次学期结束大奖励**。
- 两类事件都不占地图层、不改变路线长度、不产生新的节点连接，也不进入地图节点库存。
- 饰品奖励用于获得/替换/转化饰品；学期结束大奖励是学期收束奖励，默认**不新增饰品**，以维持每学年 2 次饰品的上限。
- 所有数值、稀有度、候选池和 ID 均为候选；新版 G0 冻结前不得实现。

### 2.3 触发约束

- 学期饰品奖励在每个学期的中点层完成后触发；6 层学期取第 3 层后，7 层学期取第 4 层后。
- 学期结束大奖励在 Boss 结算后触发；触发后才进入假期选择、学期结算或学年结算。
- 事件必须完成或明确跳过，不能积压；进入下一层或下一阶段前必须处理。
- 首期模式仍按现行 END-002 在第一学期 Boss 后结束；大奖励是否在总结前展示由 G0 决定，不得改变结算、解锁和存档边界。
- 事件不产生地图移动，不改变可达性、revision 语义或随机流隔离。

## 3. 饰品奖励事件

### 3.1 选择结构

- 每次给出 3 个饰品候选，玩家选择 1 个、跳过，或在槽位已满时替换/转化。
- 跳过收益：20 生活费或恢复 5% 精力（二选一，待 G0）。
- 槽位已满：替换一个已有饰品，或把新饰品转化为 30 生活费。
- 同名饰品不重复获得，自动转化为 25 生活费。
- 饰品奖励不提供卡牌奖励；卡牌奖励仍走普通/精英/商店的原规则。
- 确认前显示候选效果、稀有度、当前饰品栏、将替换的饰品和跳过收益。

### 3.2 候选池与稀有度

- 候选来自当前学年的饰品池；高学年可以出现更强的主题饰品，但不得引入无限组合。
- 若中点前最近节点是精英/竞赛，稀有度权重提高；普通/事件节点后以普通饰品为主。
- 建议稀有度：普通 / 稀有 / 珍藏；具体权重待 G0。
- 候选不包含 v1 A01–A24 的旧定义；如需复用机制，只复用效果类别，不复用 ID、数值或文案。
- 候选池按学年收敛：大一校园生活、大二专业与竞赛、大三去向准备、大四毕业收束。

### 3.3 饰品槽与替换

- 建议饰品栏上限 3 个；上限、转化金额和稀有度权重均为候选，不是平衡值。
- 饰品跨学期、跨学年保留，不自动清空；具体槽位和替换规则待 G0。
- 槽位已满时必须显示“将替换哪一个”和“替换后失去什么”，不能只显示新饰品。
- 同名效果不叠加；不同饰品提供同类效果时，按获得顺序或明确优先级结算。

### 3.4 强度边界

- 只允许地图/经济/轻战斗触发；不允许改变卡牌基础费用、复制卡牌、无限抽牌或绕过 DDL。
- 每个饰品每回合最多触发一次；同名效果不叠加；触发顺序按获得顺序。
- 允许的效果示例：休息多恢复、商店折扣、事件多一个选项、首次精英奖励提升、伙伴首次支援少扣 1 精力、每学期首次升级免费。
- 禁止的效果：永久增加专注上限、永久减少所有压力、无限回收、战斗外无限回血、生成不可消耗的无限资源。

## 4. 学期结束大奖励

### 4.1 定位

- 学期结束大奖励是学期 Boss 的收束奖励，不叠加普通 Boss 奖励，避免双重收益。
- 大奖励默认不新增饰品；如果 G0 希望大奖励也能给新饰品，必须相应下调学期饰品次数或槽位。
- 大奖励不改变卡牌奖励的 50 种资格池；选项 A 的稀有卡牌仍从当前人物+公共池过滤。
- 大奖励不是地图节点，不产生新的地图移动或路线层。

### 4.2 三选一选项

| 选项 | 内容 | 约束 |
|---|---|---|
| A 稀有卡牌 | 从当前人物+公共池给 3 张稀有/进阶候选，选 1 | 排除基础牌、衍生牌和临时副本；不扩大 50 种池 |
| B 牌质整理 | 升级 1 张牌，或移除 1 张牌 | 不额外给卡；不能重复执行同一张牌的升级 |
| C 资源与饰品 | 获得 60 生活费并恢复 20% 精力；若已有饰品，可改为强化/替换 1 个现有饰品 | 默认不新增饰品；无饰品时只结算资源 |
| 跳过 | 获得 30 生活费 | 不获得卡牌/饰品 |

### 4.3 数值与边界

- 60 生活费、20% 恢复、30 生活费跳过收益均为候选，待 G0。
- 大奖励不能绕过 DDL、精力失败检查、战斗稳定边界或存档幂等规则。
- 大奖励的卡牌候选必须可追溯到当前内容池；不得生成未注册卡牌或临时定义。
- 大奖励的饰品强化/替换只能作用于已拥有饰品；不能把 v1 旧饰品直接注入。
- 若首期只做第一学期，Boss 后仍按现行规则总结；大奖励只作为总结前的展示候选，是否展示由 G0 决定。

| 大二 | 专业收束 | 课程设计模板（稀有卡）、实验室钥匙（强化）、竞赛奖金（经济） |

## 6. 与现有系统的接口

本文只提出候选需求，不改变现有卡牌、战斗和奖励规则。未来实现至少涉及：

- `RunState`：学年、学期、饰品栏、饰品获得顺序、学期中点奖励历史、学期末大奖励历史、待选奖励。
- `RunMap`：学期中点奖励槽、学期末大奖励槽；不改变节点连接和路线长度。
- `RunService`：饰品三选一/跳过/替换/转化、学期末大奖励三选一、跨学期继承、首期总结前展示开关。
- `RewardGenerator`：饰品池按学年/角色/稀有度过滤；不扩大 50 种卡牌奖励资格；大奖励的卡牌候选仍走现有过滤。
- 饰品内容：独立 schema、槽位上限、稀有度、同名去重、替换/转化规则、触发时点和效果上限。
- 存档：地图版本、饰品栏、获得顺序、学期中点/学期末奖励历史、待选奖励、内容版本。
- 随机流：建议新增独立 relic 流；若复用 reward 流，必须在 G0 说明并保证固定种子重放一致。
- UI：饰品三选一、槽位比较、替换确认、大奖励三选一、跳过收益；具体视觉留待 G6/G7。

本节只登记信息需求，不做视觉设计；具体图标、布局、动效留待 G6/G7。

## 9. 平衡与验证计划

以下均为计划，**本文没有执行任何测试**。

### 9.1 待验证假设

| 编号 | 假设 | 观察指标 |
|---|---|---|
| R1 | 每学年 2 次饰品奖励足够形成构筑差异，且不是必选 | 饰品获取率、跳过率、替换率、构筑分布 |
| R2 | 学期结束大奖励的 A/B/C 三选项可比 | 选项分布、选择后的胜率与资源曲线 |
| R3 | 3 槽上限产生有意义的替换决策 | 满槽率、替换率、转化率 |
| R4 | 饰品不会绕过 DDL/精力/稳定性边界 | 规则矩阵、异常组合测试 |
| R5 | 大奖励不会与 Boss 奖励重复发放 | 结算前后资源、卡牌、饰品差异 |
| R6 | 首期模式不因大奖励改变总结/解锁边界 | 首期总结、存档、Profile 合并一致性 |

### 9.2 测试矩阵

| 层级 | 样本 | 要比较的内容 |
|---|---|---|
| 单事件 | 固定种子，逐次饰品奖励/大奖励 | 3 选 1、跳过、满槽替换、同名转化是否原子 |
| 单学期 | 每学期 1 次饰品 + 1 次大奖励 | 选项分布、资源曲线、牌组变化 |
| 单学年 | 2 次饰品 + 2 次大奖励 | 跨学期继承、槽位替换、学年结算 |
| 全四年 | 固定种子 + 机器人 + 真人 | 8 次饰品 + 8 次大奖励、胜率、构筑分布、退出率 |
| 无饰品路线 | 全部跳过/关闭饰品 | 安全线是否仍可通关，饰品是否变成硬门槛 |
| 满槽/重复 | 3 槽已满、同名候选、全部拥有 | 替换/转化是否可读、是否卡死 |
| 存档 | 学期中点、Boss 后、假期/学年结算 | 饰品栏、历史、待选奖励是否往返一致 |
| 首期模式 | 第一学期 Boss 后 | 大奖励是否展示、是否改变 END-002/解锁/存档 |

### 9.3 机器人/真人记录

机器人：胜率、饰品获取/跳过/替换率、满槽转化率、大奖励选项分布、平均生活费、平均剩余精力、构筑分布。

真人：能否理解“每学年两次饰品”和“学期结束大奖励”的区别；是否觉得大奖励选项有取舍；是否能看懂替换后失去什么；是否觉得饰品过多或过少。
