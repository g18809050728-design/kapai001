# G5 存档恢复与无头闭环执行记录

更新：2026-11-04。**当前存储能力与四学年状态保存/恢复原型已实现，相关规则/UI 回归通过；不宣称全部历史存档可迁移或已完成真实四年磁盘续玩验收。**

## 当前实现及证据

| 项目 | 实现与实际覆盖 |
|---|---|
| 领域及外壳 | RunCodec、BattleCodec、SnapshotCodec、SessionState；稳定状态、revision、实体引用、内容兼容信息与四条随机流保存/恢复 |
| 真实磁盘与故障 | SaveStore 的临时文件、备份、checksum、损坏/失败拒绝；既有存储 suite 随当前规则 runner 回归 |
| 终局 Profile | `profile_merge.gd` 与 GameSession 按 run_id 幂等合并，报告当前局/合并/清标记的部分成功；既有提交故障用例继续回归 |
| 四学年领域往返 | `test_four_year.gd` 在 52 站受控路线的每个稳定动作后 RunCodec 编解码，检查候选、历史、触发键、跨年资源与路径一致 |
| 四学年公开保存/继续 | `test_four_year.gd` 检查公开会话开局保存/恢复；`test_ui_four_year.gd` 对方向、去向、饰品/满槽、大奖励及服务待选检查公开保存/继续，候选逐字段一致 |
| 两类待选 | campaign 待领奖是可保存的稳定选择；战斗效果 `pending_choice` 是半条命令工作区，保存返回 `CHOICE_PENDING` |
| 防篡改 | 错学年饰品、基础卡大奖励、同一 offer 已领又待选等记录拒绝解码 |
| 音量设置 | 五路音量与静音在 Settings 单独持久化，重建会话恢复；不写入战斗 RNG |

入口：`tests/run_tests.gd`、`tests/run_ui_tests.gd`。证据：[当前规则/UI 摘要](../artifacts/verification/four-year-20261104/docs-refresh-runtime/summary.json)、[输入核对](../artifacts/verification/docs-refresh-20261104/runtime-review.json)。所有核验隔离 APPDATA/LOCALAPPDATA，不加载实际玩家档。

## 尚未覆盖的整版出口

52 站逐步 RunCodec 往返属于内存编解码；它不等于从同一初始档出发、自然实际战斗并在全部磁盘边界重启的四年对照。旧六节点 fixture 的 autosave 开/关及故障用例也不扩称为四年生产通关。全部历史内容 hash/schema 迁移与干净发布环境仍待核对。

旧入口 `campus_mvp`/`campus_v3` 保留各自内容身份；“保留入口”不保证任何旧 hash 的档都能直接读取。维护源见[存储契约](数据库与实体关系设计.md)、[接口](接口文档.md)。旧 G5 原文及当时的检查数、路线在[清理前快照](../artifacts/verification/docs-refresh-20261104/documents-before.zip)，不再以“UI 尚未开展、下一步 G6”描述当前状态。
