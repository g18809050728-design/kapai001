RunCodec/BattleCodec 各自独占领域映射，SnapshotCodec 只协调与验证外壳，SaveStore 只处理固定槽位文件。RNG 的 64 位 seed/state 使用十进制字符串，普通 JSON 数字限制为安全整数；拒绝 NaN/Infinity。迁移只在副本上执行显式迁移链并重算 checksum，不写盘，也不在 continue/restore 中隐式调用。

终局提交顺序为 current_run 含 pending 摘要 → Profile 按 run_id 幂等合并 → current_run 清理 bool；各步骤有独立状态。continue_run 读取正式档后重试持久 pending；restore_backup 显式读取备份，允许合并 Profile，但暂缓 current_run 清理，保留正式原文件至后续稳定保存。没有内存局时，正式档缺失但备份存在或损坏，不能无提示开新局覆盖；Profile/Settings 同样保留缺正式档的备份诊断。

本轮还修复两处实际存档不变量问题：空 origin_card_id 作为合法临时卡处理；任务换阶段或最终离场时清除旧任务持有的状态，避免合法稳定战斗被读档校验拒绝。测试覆盖新阶段 ID 和离场后的 BattleCodec 往返。
