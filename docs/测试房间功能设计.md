## 1. 定位与核心原则

测试房间是**战斗层的实时编辑沙盒**：用于规则验证、平衡调参、缺陷复现、内容试玩与确定性重放。进入后不必退回配置或重开即可修改当前实验；配置、战斗、待选、演出和结果页面都能打开编辑器。

1. **隔离**：测试拥有独立 `test_id`、`branch_id`、`revision` 与独立文件目录；不写正式 `current_run`、`profile`、`settings`，不读写正式玩家档，不修改 `data/`、`assets/` 或基础 `ContentDB`。正式局可同时在内存中存在，进入测试不结束、不推进、不保存正式局。
2. **唯一写入口**：UI 仍只经 `GameSession` 的测试上下文读视图、预览与提交命令；UI 不持有可写领域状态，不自行计算规则、候选或随机结果。
3. **结构不变量保留，玩法限制可解除**：唯一实例、有效引用、可识别 schema、合法 RNG 始终校验；人物资格、费用、槽位、精力归零、胜负自动判定等玩法限制可由测试开关解除。
4. **复用真实规则**：直接设值只改字段并生成编辑事件，不伪造出牌/抽牌/饰品触发；需要真实效果时使用“执行规则操作”，走同一处理器与随机流。
5. **可复现**：记录基础内容 hash、覆盖层 hash、四流 RNG、命令/编辑序列与规范化状态 hash；同一引擎/规则版本下可确定性重放。动画、分支身份、时间不参与玩法终态比较。
6. **不静默**：缺少处理器、覆盖字段不支持、容量超限、结构损坏都明确报错并定位；不以裁切、空值或“看起来像”冒充已生效。

## 2. 首版范围与边界

首版是**战斗沙盒**，覆盖一场战斗内的全部可编辑对象：

| 类别 | 可随时更改的内容 |
|---|---|
| 角色与被动 | 切换四角色；开关/替换已注册被动；编辑角色专属资源与计次。切换时默认保留牌与通用战斗状态，目标角色专属状态按默认值建立，旧专属状态收入撤销快照；也可显式恢复目标角色起手配置 |
| 所有牌区 | 搜索并加入任意可加载卡牌（含跨角色专属、基础、衍生、临时牌）；增加、删除、复制、移动实例；调整手牌/抽牌/弃牌/消耗/章节区；调整抽牌顺序、指定抽牌、洗牌、清空牌堆、恢复起手 |
| 卡牌属性 | 修改升级面、费用、数值、类型、目标与已注册效果组合；作用范围可为“仅当前实例”或“同定义全部实例”，界面必须标出范围 |
| 资源与上限 | 精力、专注、放松、精力上限及角色专属资源（论文进度/引用/修正/放大、协同、连携计次等）；修改上限、设为 0、锁定数值、无限专注、无敌、关闭费用与次数限制；开关默认关闭 |
| 饰品 | 添加、删除、复制、排序、编辑已注册 hook 参数、设置触发次数；可关闭同名唯一与槽位限制，不以正式获取资格限制实验 |
| 伙伴、章节、场景与能力 | 创建/删除单位实例，调整精力/槽序/数量/生效时机/剩余次数/本回合行动记录；章节增删、排序与槽数；场景替换或清除；已注册能力开关与计次；可解除正式槽位限制 |
| 敌人与遭遇 | 切换完整遭遇，或自由增删、复制、组合任务；修改当前/最大未完成量、屏障、压力、阶段、意图序列、召唤关系、胜利必需标记与考试标签；允许只留木桩或清空敌方 |
| 状态 | 给主角、任务、伙伴、单位添加/清除已注册状态，编辑层数、到期策略、来源与触发记录；支持批量清除/批量设置 |
| 时间与结算 | 回合数、DDL、当前行动阶段、计次、创建顺序；暂停敌方行动、冻结 DDL、手动执行一个完整规则步骤、跳到下一回合 |
| 随机性 | 随时修改 seed；选择重置全部四流或单流 seed/state；也可只重排抽牌堆。记录具体操作，单改标签不冒称改变实际 RNG |
| 胜负与结果 | 开关自动胜负检查；手动判胜/判负；清除测试结果后继续编辑；允许主角精力为 0 或没有敌人的实验状态；恢复自动判定时立即按当前状态检查 |
| 演出与观察 | 动画开关、倍速、跳过当前演出、日志筛选、查看完整牌序与四流 RNG 状态；仅作用于测试，不写入正式设置 |
| 检查点与预设 | 保存/恢复实验检查点、撤销/重做、恢复初始状态、保存命名预设、导出/导入完整实验；使用独立测试文件 |

**v1 明确不包含**：地图/节点/商店/事件/休息/学年结算/局外经济（金钱、奖励、解锁）；正式局内 UI 不提供测试入口；网络、多人、任意脚本、SQL 或内容编辑器写回 `data/`；新增 AI 图片或正式音频。金钱等局外数值在测试界面标为“不适用（本实验不包含局外经济）”，不放置无效的假字段。若后续扩展为整局沙盒，须另行修订本文与根计划。

数量与数值仍须有限、可处理：容量和范围见 §7.6；超限明确报因，不静默裁切，也不以正式平衡上限拒绝实验。容量是引擎表示上限，不是玩法限制；玩法限制只在对应开关关闭时按正常规则生效。历史内容包可作为显式加载的测试内容源；不兼容定义必须报告命名空间、schema 或处理器冲突，不能默默套用四年规则，也不把历史内容列为已兼容。

## 3. 生命周期与“随时修改”的一致性

### 3.1 状态机

| 状态 | 含义 | 允许的操作 |
|---|---|---|
| `configuring` | 测试主页，未建立实验 | 选择模板/角色/遭遇/种子/覆盖层；载入预设；开始实验；返回主菜单 |
| `running` | 实验进行中、规则稳定边界 | 战斗命令；暂停；打开编辑器；保存快照/预设；查看结果 |
| `awaiting_choice` | 存在唯一 `pending_choice`（效果内选择或确认） | 只接受匹配的 `confirm_choice`；可打开编辑器（应用时选择回退/截断策略）；保存须先处理待选 |
| `result` | 已有测试结果（正常、手动或截断） | 继续编辑、以当前为新起点重试、换种子、保存、退出 |
| `editing` | 编辑器打开，实验暂停 | 编辑草稿、预览、应用、撤销；关闭编辑回到打开前状态 |
| `closed` | 退出测试 | —（正式上下文恢复） |

`paused` 与“启用的规则覆盖”是独立可观察标记，不是单独状态。`editing` 可叠加在 `running` / `awaiting_choice` / `result` 之上；打开编辑器后测试规则命令一律拒绝，直到关闭或应用。

### 3.2 入口与暂停

- 主菜单直接展示一级“测试房间”按钮，与新游戏/继续游戏并列；**无存档、无正式局、未选角、未解锁均可进入**，入口永不禁用。
- 点击后进入独立测试上下文的 `configuring` 页面；“继续游戏”仍只指向正式局。
- 正式局若正在进行，进入测试不结束正式局、不保存、不改变其 `revision`；退出测试回到主菜单，正式局仍可按原路径继续。
- 战斗、待选、演出、结果中始终可打开编辑器；打开即暂停后续测试输入与规则推进。演出中途打开时，先把已有动画收尾到已发布状态，不等待玩家看完，不重放规则。
- 规则命令在副本中原子执行，编辑不能插入其半个处理器内部。若点击发生于命令执行期间，在该次原子发布或待选工作区发布后立即打开，并告知草稿基于哪个 `revision`；不需要等待整个回合或完成待选。
- 编辑期间正式局与正式自动保存均不动作；测试不使用自动保存，只有显式保存预设/快照/导出。

### 3.3 待选与未完成结算

待选期间允许编辑。默认策略为 **`rollback`（回到命令前）**：放弃触发该命令的付款、抽牌、事件、待选和续算队列，一并恢复其 RNG，再应用编辑；界面显示将撤销哪条命令。高级策略 **`truncate`（保留已结算部分并截断）**：保留当前工作区状态与 RNG，清除待选与未执行队列，标明“实验状态已截断，不是正常完整结算”。关闭编辑器而未应用时，原待选完整保留（策略 `cancel`）。

- 应用前必须重新校验实例、牌区、引用与 RNG；无法建立结构一致状态则拒绝本次编辑并定位，原工作区不变。
- 两种策略都建立新分支身份：`branch_id` 递增、`revision` 归 0；本次编辑作为新分支的首个事务记录（`revision = 0`），旧 `choice_id`、请求与事件消费键失效。
- `truncate` 必须显式选择并记录；结果标记为 `truncated`，不计入正常胜负统计。
- 正式会话的待选语义不受影响：测试策略只在测试上下文内生效。

### 3.4 编辑事务

- 修改在草稿中进行，可单项即时应用或批量应用；不逐值弹确认，但批量替换、换人、换遭遇、清空/恢复模板先给出变化摘要。
- 应用采用“状态 + 内容覆盖 + 规则覆盖 + RNG + 计次 + 实例序列”的完整副本，结构校验成功后**一次发布**；失败保留原实验与草稿，发布不可部分生效。
- 稳定状态下的正常应用 `revision + 1`；待选期间应用先按 §3.3 建立新分支（`revision = 0`）；回退、恢复检查点、撤销/重做与切换分支也建立新分支，旧请求全部失效。
- 默认“直接设置”只改指定值并生成编辑事件，不伪造出牌/抽牌/饰品触发；需要实际效果时使用单独的“执行规则操作”。
- 删除/移动对象同时处理其区域、来源、目标和关联记录，返回级联摘要（例如删除任务→清除其状态与意图引用；删除单位→清除其状态与来源登记；删除饰品→清除 hook 计次与来源）。复制分配新实例 ID，禁止两个实例共享同一引用。
- 默认保留战斗现场；整场替换、恢复模板、清空、载入预设属于批量替换，先显示摘要，可取消。
- 撤销/重做以编辑事务为单位，恢复其全部级联状态与 RNG；若中间执行过战斗命令，撤销按“恢复到该编辑前检查点”处理，并提示将回退的命令数量，不合并两条不相容的时间线。

### 3.5 撤销、检查点与分支

- 每次成功写命令（战斗命令或编辑应用）前自动建立内存检查点；起点、每次应用、手动保存快照也建立命名检查点。内存检查点保留最近 **50** 个（起点不计入上限），导出记录时写入全部已选检查点。
- 撤销 = 恢复到当前分支最近一次事务前的检查点并丢弃其后日志；重做 = 在未产生新事务时恢复被丢弃的日志顶端。撤销/重做后建立新分支（`branch_id + 1`、`revision = 0`），并提示旧输入失效。
- 恢复任意检查点会先显示“将丢弃检查点之后的 N 条命令/编辑”，确认后建立新分支；不静默覆盖当前分支。
- 分支身份只影响请求与事件消费，不参与玩法终态 hash；最多保留 **20** 个可达分支，超出时提示先导出记录或删除旧分支。

### 3.6 校验分层

| 层 | 检查 | 违反时 |
|---|---|---|
| 结构校验（永不放宽） | `test_id/branch_id/revision` 绑定；字段类型与未知键；实例 ID 唯一且在本战斗命名空间内；牌区/状态/单位/任务引用闭合；定义 ID 可加载；效果 op 已注册；RNG 快照结构合法；数值有限 | `TEST_STRUCTURE_INVALID` / `CONTENT_INVALID` / `STALE_STATE`，定位到路径 |
| 玩法校验（可解除） | 精力 ≥ 1、任务非空、单位/饰品/章节槽位、费用、同名唯一、每回合限次、DDL > 0、自动胜负 | 由测试开关解除；开关关闭时按正常玩法拒绝并给出可显示原因 |
| 文件校验 | 类型、schema 版本、引擎/内容/覆盖层 hash、闭包、处理器 | `TEST_FILE_INVALID` / `VERSION_MISMATCH`，保留原实验 |

正常 `BattleState.validate()` 中属于玩法限制的项目（精力归零、无任务、槽位、DDL）不得直接用于拒绝已解除限制的实验；测试使用独立的结构校验器，禁止用“全局跳过校验”掩盖破损引用。

## 4. 使用流程与操作语义

主菜单 → 测试房间 → 选择模板或自由配置 → 开始实验 ↔ 随时编辑 → 继续实验/查看结果 → 保存、回退、重试或退出。

- **模板**：四角色默认模板（按实际规则起手与默认遭遇）、`TEST.encounter.dummy` 木桩模板、空白沙盒（木桩起始后自行编辑）。模板只是配置预设，不改变正式内容。
- **自由配置**：角色、起始牌（默认该角色起手，可替换/增删）、起始饰品、遭遇、难度、种子、初始覆盖层与开关。开始前做与正常开局同级的校验；`begin` 要求非空牌组与合法遭遇，空牌组/无敌人只能作为**开始后编辑**的实验状态（界面明确说明）。
- **同条件重试**：使用本次开始时的配置、覆盖层与 RNG 起点；“以当前状态作为新起点”另设操作，要求当前处于规则稳定边界或先选择截断策略；“换种子再试”生成并展示新 seed。三者都建立新尝试，不消耗正式局 RNG。
- **退出**：保留正式局原状态；有未保存实验（日志非空且自上次保存后有变化）时提示保存测试预设/保存快照/丢弃/取消。测试快照只能从测试房间加载，不通过正常“继续游戏”。
- **设置与素材**：字号、减少动态、倍速等演出偏好可在测试内临时开关，只影响当前测试显示，不写入正式设置；复用现有角色、卡牌、任务、饰品与战斗背景，无新增 AI 图片要求。

## 5. 记录与复现

- 持续显示测试身份、分支/尝试编号、暂停、人工干预次数、启用的规则覆盖、覆盖层定义数与内容版本/hash。
- 记录战斗命令、拒绝结果、编辑事务、级联变化、前后值、覆盖层变更、RNG 操作、待选处理策略、撤销/恢复与手动胜负；保留原始分支及父检查点。
- 导出版本化 JSON，包含基础 manifest/hash、局部内容覆盖（自定义定义随记录导出，不只保存 ID）、配置/检查点、四流 RNG 与算法版本、命令/编辑序列、事件及规范化状态 hash。
- 导入先在独立候选中验证版本、闭包与处理器；失败定位问题并保留原实验，不静默替换定义或丢弃不支持效果。
- 相同引擎/规则版本、基础内容、覆盖层、起点及全部战斗/编辑操作序列用于确定性重放；分支身份、时间与动画耗时不参与玩法终态比较。首个不一致的 `revision` 与两侧 hash 报出。
- 只读浏览、编辑草稿和预览不改变状态/RNG/revision；导出失败只重试文件操作。
- 规则正常胜负、人工判定、截断结算、主动结束分开记录；干预后的结果为实验结果。统计根据真实事件区分直接、状态、伙伴完成量与屏障吸收，不从动画估算。

## 6. 工程边界与实现职责

## 7. 冻结接口与数据契约

以下为设计定稿的**目标契约**，当前不可调用；实施时字段名、错误码、取值范围不得再自行变更，变更须修订本文并同步根计划。

### 7.1 上下文对象

所有测试命令携带：

```json
{
  "test_id": "test-20261111-193000-a1b2c3",
  "branch_id": 3,
  "expected_revision": 12
}
```

- `test_id`：`^test-[0-9]{8}-[0-9]{6}-[0-9a-f]{6}$`，进入测试时生成，不复用。
- `branch_id`：正整数；初始 0，回退/恢复/撤销建立新分支时加 1。
- `expected_revision`：当前已发布测试 revision；不匹配返回 `STALE_STATE`，不产生副作用。

### 7.2 接口

除 `get_test_room_options()`、`get_test_view()`、`list_test_files()` 外，以下入口都要求 §7.1 上下文；表中为突出业务参数而从略，实际签名把 `context` 作为首个参数（如 `apply_test_patch(context, patch, resolution_policy)`）。

| 入口 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `get_test_room_options()` | — | `ActionResult`，`data` 为选项文档（§7.3） | 只读；不建立上下文 |
| `get_test_view()` | — | `Dictionary`（`TestRoomView`） | 只读副本；无测试时返回 `screen = "closed"` |
| `start_test_room(config)` | `TestConfig` | `ActionResult` | 校验并建立隔离实验；`revision = 0`、`branch_id = 0` |
| `begin_test_edit(context)` | 上下文 | `ActionResult`，`data` 为只读草稿基准 | 暂停并返回可编辑快照；不改状态/RNG/revision |
| `preview_test_patch(patch)` | `TestPatch` | `ActionPreview` | 只校验与计算级联，无副作用，不推进 RNG |
| `apply_test_patch(patch, resolution_policy)` | `TestPatch`、策略 | `ActionResult` | 事务应用；策略见 §3.3；成功后 `revision + 1` 或新分支 |
| `cancel_test_edit(context)` | 上下文 | `ActionResult` | 关闭编辑器，原状态与待选完整保留 |
| `submit_test_action(action)` | `ActionDraft` 同构 + 上下文 | `ActionResult` | 正常战斗命令；按当前测试开关执行；行为与正式命令同级 |
| `execute_test_rule_op(op)` | `{"op": String, "args": {...}}` | `ActionResult` | 执行真实规则操作（抽牌/加状态/伤害/完成量等），与直接设值分开记录 |
| `set_test_switch(key, value)` | 开关键、布尔 | `ActionResult` | 等价于单项 `set_switch` patch；立即按当前状态重校验 |
| `restore_test_checkpoint(checkpoint_id, context)` | 检查点 ID、上下文 | `ActionResult` | 建立新分支并恢复全部上下文；旧请求失效 |
| `step_test_history(direction)` | `"undo"` / `"redo"` | `ActionResult` | 编辑事务级撤销/重做；建立新分支 |
| `restart_test_battle(origin_policy, seed_policy)` | `"initial"`/`"current"`、`{"mode":"same"}`/`{"mode":"new","seed":String}` | `ActionResult` | 新尝试；`current` 要求稳定边界或先选截断 |
| `set_test_outcome(result)` | `"won"`/`"lost"`/`"clear"` | `ActionResult` | 人工判胜/判负/清除实验结论；记录来源 |
| `finish_test_step()` | — | `ActionResult` | 手动执行一个完整规则步骤（粒度见 §7.6） |
| `save_test_preset(name)` | 名称 | `ActionResult`，含保存回执 | 保存配置 + 覆盖层；不保存中间战斗现场；同名覆盖须确认 |
| `save_test_snapshot(name)` | 名称 | `ActionResult`，含保存回执 | 保存完整实验上下文；待选时须先选回退/截断 |
| `list_test_files(kind)` | `"preset"`/`"snapshot"`/`"record"` | `ActionResult` | 只列测试目录；含名称、时间、schema、兼容性 |
| `load_test_preset(preset_id)` | 预设 ID | `ActionResult` | 建立新实验（`configuring` → `running`） |
| `load_test_snapshot(snapshot_id)` | 快照 ID | `ActionResult` | 建立新分支；`revision = 0` |
| `export_test_record(record_id)` | 记录 ID | `ActionResult`，含路径 | 导出完整记录（含自定义定义） |
| `import_test_record(record_id)` | 记录 ID | `ActionResult` | 先验证再载入；失败保留原实验 |
| `close_test_room(action)` | `"discard"`/`"saved"` | `ActionResult` | 退出测试；正式上下文保持原状 |

所有写入口：成功一次发布全部变化；拒绝、预览、查询、保存不改变状态/RNG/revision；返回须区分业务成功、只读视图、增量事件、待选、规则稳定与持久化（测试只有“测试文件已写/未写”）。

| `test` | Dictionary | `test_id`、`branch_id`、`revision`、`attempt`、`paused`、`editing`、`interventions` |

| `overlay` | Dictionary | `hash`、定义数、实例覆盖数、字段覆盖数、按类摘要 |

### 7.4 编辑包 TestPatch

```json
{
  "schema_version": 1,
  "test_id": "test-20261111-193000-a1b2c3",
  "branch_id": 3,
  "expected_revision": 12,
  "resolution_policy": "rollback",
  "ops": [
    {"op": "set_player_field", "field": "focus", "value": 9},
    {"op": "add_card", "definition_id": "R3-P03-04", "zone": "hand", "count": 1}
  ]
}
```

- `ops` ≤ **100** 项；单项操作字段 ≤ **32** 个；未知键/op/字段直接拒绝并给路径（如 `ops[2].value`）。
- `ops` 按顺序应用；同一对象的多次操作都记录前后值；事务内任一项失败则整包不发布。
- 操作目录见附录 A；开关见附录 B；覆盖字段见附录 C。

### 7.5 规则开关

完整清单见附录 B。开关默认全部关闭；切换立即重校验，不重建实验、不清空牌区。关闭某项后，若当前状态已违反正常玩法限制，不强制改写状态，而是标记为“当前不满足”并提示原因；恢复自动胜负检查时立即按当前状态检查一次。

### 7.6 数值范围、容量与单步粒度

| 项 | 范围/上限 | 超限行为 |
|---|---|---|
| 战斗数值（精力/专注/放松/精力上限/屏障/完成量） | 整数 `-9999..9999`，按字段语义使用（上述资源通常非负）；解除限制后允许把精力设为 0，但不把负值当作可用资源 | `TEST_LIMIT_REACHED` |
| 精力上限 | `0..9999` | 同上 |
| 牌区单区实例数 | `0..300` | 同上 |
| 战斗卡实例总数 | `0..500` | 同上 |
| 定义搜索 | 单次返回 ≤ **80** 条，分页 | 提示继续输入 |
| 任务数 | `0..40` | 同上 |
| 单位数 | `0..32`（默认槽位 3，可解除） | 同上 |
| 章节数 | `0..8`（默认 3，可解除） | 同上 |
| 饰品数 | `0..64`（默认 3，可解除） | 同上 |
| 状态条目 | `0..500`；层数 `1..999` | 同上 |
| 覆盖定义 | ≤ **200** 个；实例覆盖 ≤ **1000** 条 | 同上 |
| DDL | `0..99`（0 仅冻结/实验状态允许） | 同上 |
| 回合 | `1..999` | 同上 |
| 检查点 | 内存 50；导出全部已选检查点 | 超出丢弃最旧并提示 |
| 分支 | 20 | 提示导出或删除 |
| 记录日志 | 2000 条 | 提示导出后继续 |
| 自定义定义 ID | `TEST.<kind>.<name>`，ASCII 安全字符，≤ 64 字符 | `CONTENT_INVALID` |

**规则单步粒度**：一个“完整规则步骤”= 一条规则命令的原子结算边界（对应一次 `preview/apply`），即整张牌的效果队列（含其待选续算）、一次结束回合到下一回合开始、或一次单项规则操作（如抽 1 张）。不允许逐效果/逐事件单步，因为效果队列跨待选没有可持久化的稳定中间态；界面按“单步 = 一条命令”显示。

### 7.7 错误码

沿用 `ApiError{code, message_key, details}`，`details` 在适用时包含 `test_id`、`branch_id`、`path`（可定位到字段/对象）与 `limit`；无上下文的调用只返回诊断键。新增：

| 错误码 | 触发 | 是否改变状态 |
|---|---|---|
| `TEST_ROOM_NOT_ACTIVE` | 无测试上下文时调用测试命令 | 否 |
| `TEST_CONTEXT_MISMATCH` | `test_id/branch_id` 不匹配 | 否 |
| `TEST_PATCH_INVALID` | 编辑包 schema/未知键/未知 op/字段不支持/类型错误 | 否 |
| `TEST_STRUCTURE_INVALID` | 唯一实例、引用闭合、牌区/状态/任务/单位一致性失败 | 否 |
| `TEST_LIMIT_REACHED` | 超出 §7.6 范围 | 否 |
| `TEST_CHOICE_CONFLICT` | 待选期间提交不匹配命令或策略非法 | 否 |
| `TEST_CHECKPOINT_INVALID` | 检查点不存在/被丢弃/属于其他分支 | 否 |
| `TEST_FILE_INVALID` | 测试文件类型、schema、hash 或闭包不合法 | 否（保留原实验） |
| `TEST_IO_ERROR` | 测试文件读写失败 | 否（可重试文件操作） |
| `TEST_REPLAY_MISMATCH` | 重放终态 hash 不一致 | 否 |
| `TEST_UNSUPPORTED` | 处理器缺失或该能力不属于测试覆盖范围 | 否 |

其余沿用 `INVALID_ARGUMENT`、`STALE_STATE`、`CONTENT_INVALID`、`VERSION_MISMATCH`、`ENGINE_NOT_READY` 等既有分类；不吞错、不伪装成玩家失败。

### 7.8 文件类型、路径与隔离

| 类型 | `kind` | 路径 | 内容 |
|---|---|---|---|
| 预设 | `test_room_preset` | `user://test_room/presets/<preset_id>.json` | 配置 + 覆盖层 + 开关 + 展示偏好（可选） |
| 快照 | `test_room_snapshot` | `user://test_room/snapshots/<snapshot_id>.json` | 完整实验上下文（稳定状态；待选须回退或截断后保存） |
| 记录 | `test_room_record` | `user://test_room/records/<record_id>.json` | 起点 + 完整日志 + 终态 + 规范化 hash |
| 导出/导入 | 同上 | `user://test_room/exports/` | 导入只从该目录选择，路径固定，不接受任意路径 |

- 所有测试文件带 `schema_version`、`kind`、引擎/内容/覆盖层 hash；正常 `SaveStore` 只认 `current_run/profile/settings`，测试 `TestStore` 只认上表类型，互不加载。
- 快照必须完整包含：战斗状态、规则/内容覆盖、开关、四流 RNG、实例序列与计次、检查点与日志、以及 `resume_policy`（稳定保存时为 `stable`；经 `truncate` 保存时为 `truncated`，并保留截断标记）。待选不允许以“半条效果”伪装稳定快照；不能序列化的续算对象必须走回退或明确截断。
- 写入使用临时文件 + 校验后替换；失败保留旧文件并返回 `TEST_IO_ERROR`。
- 正式玩家档（`user://saves/`）不在测试访问范围内：测试不读取其内容（避免泄露），也不写入；退出测试不改变其字节。

### 7.9 版本与兼容

- 测试文件 `schema_version = 1`；覆盖层 schema 1；编辑包 schema 1。版本不同先尝试已登记迁移，无迁移路径则拒绝，不静默降级。
- 记录与快照必须匹配：引擎版本、`manifest_id`、基础内容 hash、ruleset id、覆盖层 hash、RNG 算法版本；任一不符返回 `VERSION_MISMATCH`/`TEST_FILE_INVALID` 并列出差异。
- 自定义定义随文件保存；导入时不写回 `data/`，只进入当前候选覆盖层，导入成功后才成为当前实验的一部分。

### 8.3 实验中状态栏与入口

- 战斗页顶部增加测试状态条（高 44 px，不遮挡手牌与任务）：`测试房间 · <短 test_id> · 分支 <n> · rev <n>` + 状态标记（`运行中`/`已暂停`/`待选`/`已截断`）+ `干预 <n> · 覆盖 <n>` + 右侧按钮 `暂停`/`继续`、`编辑器`、`撤销`、`重做`、`保存`、`结果`。
- UID：`test:pause`、`test:open_editor`、`test:undo`、`test:redo`、`test:save`、`test:result`。
- 暂停：状态条变金色底，战斗输入全部禁用（含数字键/拖拽），悬停详情可看；`Esc` 仅关闭详情，不解除暂停。
- 待选：状态条显示“待选”，编辑器入口仍可用；应用时弹 §8.5 对话框。
- 截断/人工干预：状态条常驻红色/金色标记，悬停显示最近一次操作摘要。
- 演出中打开编辑器：先将动画收尾到已发布状态，状态条显示“已暂停”，不重放旧事件。

### 8.4 编辑器（`test_editor`）

结构：`tab 栏` → `筛选/搜索行` → `对象列表` → `草稿条（底部固定）`。

Tab 顺序与内容：

| Tab | 编辑内容 | UID |
|---|---|---|
| 角色 | 角色切换、被动、专属资源、精力上限/精力 | `test:editor:tab.character` |
| 牌区 | 手牌/抽牌/弃牌/消耗/章节；增删复制移区排序、抽牌顺序、洗牌、清空、恢复起手 | `test:editor:tab.cards` |
| 资源 | 专注/放松/精力/上限/论文与协同等专属资源、锁值、无限专注 | `test:editor:tab.resources` |
| 敌人 | 遭遇切换、任务增删复制、完成量/屏障/压力/阶段/意图/必需标记/考试 | `test:editor:tab.enemies` |
| 伙伴与场景 | 单位、章节、场景、能力与计次 | `test:editor:tab.allies` |
| 状态 | 主角/任务/单位状态增删、层数、到期、来源、批量清除 | `test:editor:tab.statuses` |
| 时间与随机 | 回合、DDL、阶段、计次、seed/单流重置 | `test:editor:tab.time` |
| 规则与覆盖 | 规则开关、覆盖定义/字段、作用范围 | `test:editor:tab.rules` |
| 检查点 | 检查点列表、恢复、撤销/重做范围、保存预设/快照 | `test:editor:tab.history` |

- 搜索行：输入即过滤（≤80 条分页），`/` 聚焦；筛选芯片：类型、稀有度、所有者、费用、`仅本角色`/`全部`。
- 列表行（高度 40 px）：名称、类别徽标、当前值、`实例`/`整类`范围徽标；数值可点 `-`/`+`/直接输入，输入非法内联报错不高亮整行。
- 草稿条：`待应用 N 项`、`预览变化`、`应用`、`丢弃草稿`、`关闭`；UID `test:editor:apply`、`test:editor:discard`、`test:editor:close`。未保存草稿关闭时二次确认（丢弃/继续编辑）。
- 批量操作（换角色、换遭遇、恢复模板、清空牌堆）先弹变化摘要（对象数、级联数、将失效的检查点），可取消。
- 应用失败：错误条显示路径与错误码；草稿保留，原实验不变。
- 编辑期间战斗输入与键盘战斗快捷键禁用；只读预览不变状态。
- 长列表：虚拟滚动或分页，滚动位置在刷新后保留；10 项以上不一次性展开详情。

尺寸：宽度 ≥ 1100 且高度 ≥ 700 → 右侧抽屉 520 px（战斗区压缩但保留状态条与牌区摘要）；否则全屏编辑器（战斗页隐藏，关闭后回到原状态）。字号 150% 时列表改为单列卡片式，数值按钮 ≥ 44 px。

### 8.5 待选处置对话框

- 触发：待选期间点击“应用”。
- 内容：将撤销的命令摘要、涉及付款/抽牌数、RNG 是否恢复；三个选项：
  - `回到命令前并应用`（默认，金色焦点）→ `rollback`
  - `保留已结算部分并截断`（需勾选确认“这是实验结果，不是完整结算”）→ `truncate`
  - `取消`（保留原待选）→ `cancel`
- UID：`test:choice:rollback`、`test:choice:truncate`、`test:choice:cancel`。
- 应用后显示新分支编号与“旧选择已失效”。

### 8.6 结果页（`test_room_result`）

- 标题：`实验结束 · <来源>`：正常胜负/人工判定/截断/主动结束分别显示，不混为“胜利”。
- 摘要：回合数、DDL、剩余精力、完成/失败任务、干预次数、覆盖数、分支、终态 hash 短值。
- 操作：`继续编辑`（清除结论或保留）、`同条件重试`、`以当前为新起点`、`换种子重试`、`保存记录`、`返回主菜单`。UID：`test:result:continue`、`test:result:retry_same`、`test:result:retry_current`、`test:result:retry_seed`、`test:result:save`、`test:result:exit`。
- 自动判定开启时，“继续编辑”先允许；点击继续后若当前状态已满足结局条件，立即按规则检查并提示会再次结束，不假装战斗可继续。

### 8.7 退出确认

- 有未保存实验：`保存预设`、`保存快照`、`丢弃并退出`、`取消`；UID `test:exit:save_preset`、`test:exit:save_snapshot`、`test:exit:discard`、`test:exit:cancel`。
- 保存失败：显示错误码与路径，提供重试；不自动丢弃。
- 退出后回主菜单；“继续冒险”仍指向正式局。

### 8.8 视觉与尺寸规范

- 颜色沿用 `UiStyle`：纸白 `#f4eedf`、墨 `#243e4a`、次要 `#637871`、金 `#dda957`、红 `#bd6b64`、绿 `#78978e`；测试模式额外使用 2 px 金边状态条，不引入新主色。
- 字号：沿用 100/125/150% 三档；标题 24、区块标题 20、正文 16–18、元信息 14；正文不缩小到 14 以下。
- 间距：页面外边距 10（战斗全屏 0）；区块间距 10–16；按钮最小 44×36 px（紧凑 44×40）。
- 尺寸验收：1280×800 与 960×600 均需无重叠、无截断；960 下编辑器全屏、主菜单两行按钮。
- 动效：抽屉滑入 120 ms；减少动态时直接显示；测试状态条不闪烁。

### 8.9 键鼠、焦点与无障碍

| 按键 | 行为 |
|---|---|
| `F2` | 打开/关闭编辑器（焦点在文本输入时不拦截） |
| `Esc` | 关闭当前详情/对话框/编辑器；不退出测试、不解除暂停 |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 撤销/重做编辑事务（有焦点输入框且正在编辑文本时不拦截） |
| `/` | 聚焦搜索框 |

- Tab 顺序：状态条 → 战斗区 → 编辑器；抽屉打开时焦点进入抽屉并隔离背景焦点，关闭后回到触发控件。
- 所有可点击对象有可见焦点框；状态条/标记不只靠颜色表达（文字 + 图标/边框）。
- 长列表支持键盘上下移动与 Enter 编辑；数值输入支持直接键入。

### 8.10 反馈、空态与错误

- 每次应用/撤销/恢复/重试显示一行短反馈（如“已应用 3 项 · rev 15”），3 秒后淡出；不打断操作。
- 错误：红色提示条 + 可定位路径 + 错误码；同一错误重复出现时合并计数。
- 空态：无牌、无任务、无状态、无检查点、无文件均显示明确说明与下一步按钮。
- 覆盖标记：被覆盖的定义在卡面/详情显示“已覆盖”徽标；悬停显示原始值→测试值。

## 附录 A 编辑操作目录

字段含义以正文与视图为准；`scope` 为 `instance`（仅当前实例）或 `definition`（同定义全部实例）。所有操作都要求结构校验通过。

| op | 主要参数 | 作用与级联 |
|---|---|---|
| `set_character` | `character_id`、`keep_deck`、`keep_relics`、`migrate` | 切换角色；默认保留通用牌与状态，目标专属状态按默认建立，旧专属状态入撤销快照 |
| `set_passive` | `character_id`、`passive_id`、`enabled` | 开关/替换已注册被动；立即重算只读摘要 |
| `set_player_field` | `field`、`value` | 精力/精力上限/专注/放松及专属资源；值域见 §7.6 |
| `adjust_player_field` | `field`、`delta` | 同上，可负；超出值域时拒绝并提示，不静默裁切 |
| `set_player_lock` | `field`、`locked` | 锁定数值，规则结算不改变它（默认关） |
| `add_card` | `definition_id`、`zone`、`count`、`position` | 新建实例并分配新实例 ID；加入指定牌区；`zone` 为 `hand/draw/discard/exhaust/chapter` |
| `remove_instance` | `instance_id` | 删除实例并清理牌区/保留/章节引用；级联清来源 |
| `duplicate_instance` | `instance_id`、`count`、`zone` | 复制为新实例（新 ID、同定义），不共享引用 |
| `move_instance` | `instance_id`、`zone`、`position` | 移动；目标区满或实例被章节占用时拒绝 |
| `set_zone_order` | `zone`、`instance_ids` | 全量重排；必须恰好覆盖该区实例集合 |
| `shuffle_zone` | `zone`、`stream` | 用指定随机流重排（默认 `battle`）；记录 RNG 前后值 |
| `clear_zone` | `zone` | 清空指定区并级联清理引用 |
| `restore_starter` | `character_id` | 恢复角色起手牌与初始饰品（批量替换，先摘要） |

| `set_card_effects` | `scope`、`target`、`effects` | 已注册 op 组合；未知 op 拒绝 |
| `set_card_upgraded` | `target`、`upgraded` | 切换升级面 |
| `add_relic` | `relic_id`、`position` | 加饰品；关闭同唯一/槽位限制时允许重复与超槽 |
| `remove_relic` | `relic_id` 或 `position` | 删除并清 hook 计次与来源 |
| `set_relic_hook` | `relic_id`、`hook_index`、`at`、`params` | 编辑已注册 hook 参数；仅允许已注册窗口 |
| `set_relic_charge` | `relic_id`、`hook_index`、`count` | 设置触发计次 |
| `add_unit` | `definition_id`、`position` | 创建伙伴/单位实例；来源登记 |
| `remove_unit` | `unit_id` | 删除单位并清其状态与来源 |
| `set_unit_field` | `unit_id`、`field`、`value` | 精力/上限/协同/放松/行动记录/槽序 |
| `add_task` | `definition_id`、`position` | 增加任务实例，按定义建立初始阶段/意图 |
| `remove_task` | `task_id` | 删除任务，级联清其状态与意图引用 |
| `set_task_field` | `task_id`、`field`、`value` | 完成量/上限/屏障/阶段/意图/资格回合/必需标记 |
| `set_task_intent` | `task_id`、`intent` | 直接设定下一条意图快照（实验设值，不伪造敌方行动） |
| `replace_encounter` | `encounter_id`、`keep_player` | 整场替换任务集合与考试标签；先摘要 |
| `add_status` | `status_id`、`target_id`、`stacks`、`expiry` | 加状态；目标须为存活主角/任务/单位 |
| `remove_status` | `instance_id` 或 `status_id`+`target_id` | 清除单个或匹配批 |
| `set_status_field` | `instance_id`、`field`、`value` | 层数/到期/来源 |
| `clear_statuses` | `target_id`（可空） | 批量清除 |
| `add_scene` | `scene_id` | 建立场景；默认单场景，解除上限后可多置 |
| `clear_scene` | — | 移除场景及触发记录 |

## 附录 B 规则开关

全部默认 `false`；切换即时生效并重校验。开关只解除玩法限制，不解除结构校验。

| 键 | 效果 |
|---|---|
| `allow_zero_vitality` | 主角精力可为 0 并继续实验 |
| `allow_empty_tasks` | 允许没有敌方任务 |
| `freeze_outcome` | 不自动判胜/判负 |
| `freeze_ddl` | DDL 不随回合递减 |
| `freeze_enemy` | 跳过敌方自动行动（仍需手动单步） |
| `infinite_focus` | 费用支付不改专注 |
| `no_cost` | 出牌不检查/不支付费用 |
| `ignore_limits` | 忽略每回合/每实例限次与同名能力限制 |
| `ignore_relic_unique` | 允许重复饰品 |
| `ignore_relic_slots` | 忽略饰品槽位上限 |
| `ignore_unit_slots` | 忽略伙伴/单位槽位上限 |
| `ignore_chapter_slots` | 忽略章节槽位上限（≤8） |
| `manual_rule_steps` | 敌方/回合结算只在手动单步时推进 |
| `keep_hand` | 回合结束不强制弃手牌（实验用） |

## 附录 C 覆盖层字段（按定义种类）

覆盖层只允许下列字段；未列出字段视为不支持并返回 `TEST_PATCH_INVALID`。新增定义沿用同一 schema，ID 以 `TEST.` 开头。

| 种类 | 可覆盖字段 |
|---|---|
| `card` | `cost`、`type`、`target`、`rarity`、`tags`、`effects`、`upgrade`、`flags`、`limits`、`requirements`、`owner`、`exhaust`、`permanent` |
| `character` | `passive`、`starter_cards`、`starter_relic_id`、`resources`、`art_key`（只读显示） |
| `task` | `phases[].work_max`、`phases[].intents`、`phases[].pressure`、`exam_flags`、`required`、`taunt`、`summon`、`transform` |
| `encounter` | `members`、`initial_members`、`base_ddl`、`exam_flags`、`kind` |
| `unit` | `vitality`、`max_vitality`、`cooperation`、`relax`、`actions`、`support`、`slots` |
| `relic` | `hooks[].at`、`hooks[].params`、`hooks[].limit`、`rarity`、`availability`、`campaign` |
| `status` | `target`、`duration_policy`、`stack_policy`、`dispel_policy`、`numeric_rule_key` |
| `scene` | `slots`、`triggers`、`effects`、`duration` |
| `ruleset` | `battle.*`（手牌上限、专注与抽牌、槽位、最低 DDL/精力）、`statuses.*.cap`、`run.starting_vitality` 等已注册字段 |

`relic` 覆盖仅允许已注册窗口：`round_start`、`draw`、`card_resolved`、`work_segment`、`stage_entered`、`unit_action_completed`、`before_status_gain`、`cost_quote`。新增触发窗口属于引擎扩展，不在测试覆盖层能力内；需要时必须走正式引擎变更，不能在测试中伪造。

## 附录 E 错误与恢复对照

| 场景 | 返回 | 界面与恢复 |
|---|---|---|
| 旧 revision/旧分支请求 | `STALE_STATE` / `TEST_CONTEXT_MISMATCH` | 刷新视图与草稿基准，不自动重发 |
| 未知 op/字段/类型 | `TEST_PATCH_INVALID`，`details.path` | 内联定位；草稿保留 |
| 结构不一致 | `TEST_STRUCTURE_INVALID` | 显示引用/实例问题；原实验与草稿不变 |
| 超容量 | `TEST_LIMIT_REACHED`，`details.limit` | 提示上限与当前值；不裁切 |
| 待选冲突 | `TEST_CHOICE_CONFLICT` | 打开策略对话框或取消 |
| 文件损坏/版本不符 | `TEST_FILE_INVALID` / `VERSION_MISMATCH` | 保留原实验；列出差异；可换文件 |
| 读写失败 | `TEST_IO_ERROR` | 只重试文件操作，不重发业务 |
| 重放不一致 | `TEST_REPLAY_MISMATCH`，首个差异 revision 与两侧 hash | 停止重放；导出记录供排查 |
| 能力缺失 | `TEST_UNSUPPORTED` | 明确说明缺少处理器，不创建半套效果 |
