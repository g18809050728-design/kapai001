## 3. 路线选择与接入边界

| 路线 | 当前依据 | 决策 |
|---|---|---|
| 原生 Skeleton2D / Bone2D + Sprite2D / Polygon2D | 本批真实工程验证通过，无新增动画中间件 | 当前推荐；先补资源和动作质量，再扩大样本 |
| Spine 等专用二维工具 | 本批未安装、未购买，运行时许可和 Godot 4.7.2 兼容未核对 | 美术团队有成熟工作流，或原生编辑效率成为实测瓶颈时，另做同一角色对比后决定 |
| 完整 3D + 固定摄像机 | 本批未制作或测量 | 当前固定二维战斗构图无需因此重做渲染管线；未来有全角度需求再独立评估 |

接入沿 `GameSession → BattleEventAnimator → BattleStageEffects → BattleActorView → NativeActorRig`。领域只发布已结算事件，表现层根据真实 source/target 播放动作。骨架在稳定 Control 中绘制，血条、意图、命中区和焦点不随骨架摆动；出牌的动作锚点来自当前手/道具。

持续待机单独运行；同一次出牌的后续工作事件合并已有动作，不反复重启。只有有限动作 Tween 进入现有终局屏障，待机不计入等待。减少动态时回到稳定姿态，取消/离场释放动作，局部重建保留同一实体及待机时钟。动作时长继续除以原基础 4 与用户倍速乘积。

`GameSession.effect_sources` 补充真实 `battle.card_by_id` 的初始牌归属。这是只读视图投影，未知来源仍不伪装为玩家；不改变 source_registry、规则、RNG、内容 ID 或存档 schema。其余新增实现集中于原有表现链和独立试验工具；现有卡牌类型符号、地图点击语义与输入门控继续有效。

## 5. 生产资源与动作规格

先固定角色轮廓、校园语义和在战场中的实际高度，再拆件。代表扩展阶段建议主角 14–22 件、普通敌怪 8–14 件；这是待校准规格，本批主角 8 件只能证明接入。至少将头/前后发、胸/髋、上下臂/手、上下腿/鞋、持物和前后衣摆按实际动作需要分开。道具与手分开，避免当前电脑前臂整块限制转动。

部件须有完整遮挡区，关节保留约 15–20% 的重叠余量，并在动作峰值复核；不能把整图硬切后让旋转暴露断口。导出真实 RGBA，检查半透明边缘、色边、重复件及层序。按实际显示像素制作 1×/2× 密度样本后选择；不将生成图的画布尺寸直接当作角色尺寸。

每套保存原图/分层源、生成提示词与版本、来源说明、实体 ID / 阶段映射、部件命名、尺寸、父子骨骼、轴心、层序、网格权重、动作作用点、文件 hash 和评审图。当前 rig.json/source.json 可作机器记录起点，后续补充便于美术修改的分层源文件与编辑入口。

动作最低集合为 idle、enter、action、hit、guard、depart；多阶段敌怪增加 phase，关键角色增加表情与大幅姿势替换。先设计蓄力—命中—回收关键姿势，再添呼吸、发梢、衣物、纸页与材质循环；在现有有效倍速下观察可读性，不能把慢速动画直接压缩后视为达标。命中效果/跳字使用实际目标锚点，动作不可遮挡意图、费用和条件。
