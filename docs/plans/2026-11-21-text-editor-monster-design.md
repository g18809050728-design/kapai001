# 文本编辑器怪物实体分类

日期：2026-11-21  
需求：UIR-078（[需求文件](../../动作或者图片描述/主菜单文本编辑器怪物分类_20261121.md)）  
上位记录：§0.20.53 实体优先文本编辑器

## 1. 目标

在现有“卡牌、饰品、人物、剧情、词条”之后增加“怪物”实体分类，并把原本落在“其他”里的怪物名称、阶段名和意图名归入每只怪物实体。

## 2. 实体与字段

- 怪物实体来自正式 `campus_four_year` 的 60 个 task 定义。
- 实体 ID：`monster:<task id>`。
- 字段：
  - 名称：`label:<task id>`。
  - 阶段：若 `phase.name_key` 在文本标签表中存在，字段 UID 为 `label:<name_key>`。
  - 意图：若 `intent.text_key` 在文本标签表中存在，字段 UID 为 `label:<text_key>`。
  - 同一怪物实体内部按阶段/意图去重；同名意图在不同怪物实体中共享同一 UID，编辑会影响所有使用该意图名的位置，符合文本实际复用方式。
- 不为没有标签的阶段/意图伪造新 UID；这些位置继续使用规则或硬编码默认显示。这样不会把“分类”扩大成新的文案层改造。
- 怪物实体元信息：task ID、类型（普通/精英/首领/附属）、学年、阶段数。

## 3. 数量变化

合并 RX 饰品后的当前实体库：

| 项目 | 当前值 |
|---|---:|
| 实体总数 | 595 |
| 怪物实体 | 60 |
| 其他实体 | 198 |
| 逻辑字段 | 1690 |
| 覆盖 UID | 1711 |

怪物名称、意图/阶段标签原本在“其他”的单字段实体中；现在按 task 分组为 60 个多字段怪物实体，因此实体数下降，字段与 UID 总数不变。

## 4. 界面

- 页签顺序：全部、卡牌、饰品、人物、剧情、词条、怪物、其他。
- 怪物页签显示 60 个实体；筛选为怪物类型。
- 进入怪物实体后，右侧字段列表显示名称、阶段名、意图名；字段折叠与实体保存/撤销/恢复沿用现有机制。
- 960×600/150% 仍使用紧凑页签与右栏布局。

## 5. 实现

- `src/ui/text_entity_library.gd`：
  - `TYPE_ORDER`/`TYPE_NAMES` 增加 `monsters`。
  - 新增 `_add_monsters()`，在 `_add_glossary()` 之后、`_add_terms()` 之前执行。
  - 归入怪物实体后，`_add_terms()` 不再把这些标签放进“其他”。
- `src/ui/text_editor_page.gd`：
  - TABS 增加“怪物”；紧凑页签宽度适配 8 个页签。
  - 怪物类型筛选。
  - 副标题加入怪物。
- 不改 `TextOverrides`、规则/命令/RNG/存档或原内容定义。

## 6. 验证

- 实体 595、怪物 60、其他 198、字段 1690、UID 1711。
- `monster:N03` 暴露名称与意图字段；怪物名称不再出现在 `term:N03`。
- 搜索“C语言练习”只返回 `monster:N03`；类型过滤 boss 只返回首领。
- 修改怪物名称影响 `UiStyle.label("N03")`；修改意图影响共享意图文本。
- 旧 1699 个源 UID 全部仍归属；旧覆盖无需迁移。
- 专项、完整 UI、完整规则、默认入口和实际实渲。

## 7. 边界

- 无标签的阶段/意图不新增覆盖项；它们仍由规则/默认显示。
- 固定 GDScript 按钮/提示、动态数值短句、考试面独立字段仍不在本批范围。
- 自动检查与实渲不构成用户最终视觉签收。
