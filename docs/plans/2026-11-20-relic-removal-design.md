# 2026-11-20 · 移除旧饰品，仅启用 RX

本次落实用户「原有的饰品删除，不保留」，取代 §0.20.35–36 的 FY 兼容掉落要求。

## 正式游戏

- `campus_four_year_relics.v2` 只读取并启用 104 件 RX（40 通用、四角色各 16）；原 `FY_Y1_1` 至 `FY_Y4_4` 的 16 件不会进入装备、奖励、测试房间、图鉴或文本编辑器。图鉴保留通用／角色、品质、学年和搜索，不再提供「学年」归属。文本编辑器改为实际版本的 RX 名称和效果说明。
- 通用、个人、混合三个奖励位置保留。四学年各有两次饰品奖励，独立学年大奖励四次，装备上限三槽。早年 FY 金色途径取消；RX 金色仍从大三开始，每份候选至多一件金色。两个考场限制保留。
- 显式 `--relic-pilot` 仍单独存档，在 `.v2` 只启用首测的 24 件 RX。104 张选定图片不替换；其中 56 张 V2 及 48 张 V1。API 新增 0，累计 173/200。

## 继续旧档

1. 按旧清单、内容哈希、快照校验和及规则结构校验旧存档或备份。历史定义只为校验保留，不会成为继续冒险所用目录。
2. 在内存中卸下 FY，正在进行的战斗也移除这些饰品及其来源引用。RX 保持实例和槽位。冻结候选只过滤 FY，保留同一个奖励 ID 和其余候选原顺序；全为 FY 时结束该奖励，不补发、不折现、不重抽。
3. 牌组、此前获得的资源、已生成地图、历史学年的奖励层与 RNG 不变。普通继续不回写文件，下一次正常保存才使用新版本。旧测试快照或测试记录若仍引用 FY，则提示新建测试，原文件不删除。

在 Godot 4.7.2 中，把 `APPDATA` 和 `LOCALAPPDATA` 重定向到独立测试目录。`tests/run_relic_roster_tests.gd` 核对全部 104 件实效；`tools/audit_relic_roster_rewards.gd` 从生成的地图奖励层核对实际候选，受控抽样并非自然通关；`tests/run_relic_removal_tests.gd` 用隔离的旧版本快照验证混合/全旧奖励、原始固定地图、战斗续玩、备份、文件未写和新版再读。`tools/capture_relic_roster.gd` 用实际入口和游戏窗口核对画廊、筛选、领取、装备及实际触发。
