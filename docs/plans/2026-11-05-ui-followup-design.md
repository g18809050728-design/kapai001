# UI 追加反馈实施设计

日期：2026-11-05。依据[逐项需求](../../动作或者图片描述/UI追加反馈与验收_20261105.md)，先登记范围、再补图与实现。复用现有 Godot 控件、GameSession 写命令及冻结候选，预览、排序、滚动和取消不改变领域/RNG/revision。

1. 共享卡牌使用独立视觉容器，文字根据实际宽度测量，图片高度固定；不将 Button 自带文字最小尺寸或活动视觉容器尺寸反馈给外部最小高度。悬停同步设置视觉容器上下偏移，保持可点击区域与整体尺寸。未固定说明置于候选网格外侧，进入说明的窄间隙保留当前内容；固定后用较宽面板并隔离焦点，重建后按稳定布局定位。
2. 所有预选保留候选网格，以暖金边框/勾选强调选择；升级比较、装备替换槽、事件目标作为同页补充。真实类别浏览保持可返回导航。方向与去向复用现有图，面板横向填充，必要时滚动。
3. 地图区分当前深青底、可达浅绿、已完成弱化与预选金边。在新地图业务视图出现时，等滚动恢复和节点排列完成后，用可视高度的一半居中下一可达层；本地刷新保持原位置。
4. 校园餐食仅生成一张，使用配置 API/模型与 medium 质量、1024×1024，上传已有风格参考，保存完整提示词和原始输出；机器检查及 AI 看图后接入，不等同最终人工签收。
5. GameSession 在 zones_public 新增稳定排序的 draw 成员，按定义 ID、升级和实例 ID 排序，禁止实际抽取序列进入视图。战斗只读牌堆覆盖层复用卡牌网格和完整预览，保留关闭/强制待选隔离。记录与规则换位，专注/结束回合复用纸张配色并用轻量线条图标。
6. 音效先备份原 WAV/生成器，再确定性重建柔和音色；减轻高频、峰值和持续时间，关闭悬停发声，以组间冷却和有限复音控制连续抽弃牌/状态轰炸，重要结果可优先播放。保留设置值。检查解码、峰值/RMS、首尾包络和事件节流。
7. 继续条件区分未结束会话、有效未结束存档、终局与无档；新局替换确认仅在存在未结束或无法判定的旧档时要求。服务层保留确认/归档保护，终局不冒充可继续游戏。
8. R3-P03-19 对照卡表及引擎触发路径检查，补完整能力说明；只在回归发现规则不符时修复规则，并保留触发前/后与限次断言。

验证需包含真实指针点击后多帧尺寸稳定、所有预选保留候选、两尺寸/大字号、地图返回和滚动定位、牌堆无序成员与 RNG 不变、菜单状态、音频突发以及该卡实际规则。保留引擎版本、隔离数据目录、输入哈希、退出码、原始输出及实际截图，不读写玩家档。结果见[实施记录](../UI追加反馈实施记录_20261105.md)；整版 G0/G6/G8 未关闭项继续保留。
