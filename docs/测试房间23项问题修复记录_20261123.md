## 补强后的边界

- **记录不是逐命令重放。** 本次修复版本/hash 忽略、日志丢失及坏记录接受的问题。载入会校验后恢复最终状态并保留 journal；没有重执行全部命令或报告首个重放差异。旧 hash v1/v2 按各自字段计算，不要求旧文件具备新元数据；新记录为 hash v3。
- **手动推进以完整回合命令为单位。** 回合内部不逐效果暂停，普通结束回合等待显式推进；保存处为稳定边界。节点跳转、新战斗、重试或离开 enemy_turn 时清理旧待推进命令。
- **整局范围需要明确选择。** `persistence_scope=run` 的删除/升级只作用于确切关联对象；临时对象没有来源时拒绝，不猜同定义的永久对象。旧文件缺少 `relic_origins` 时保守视为未关联，下场战斗再建立准确来源。校园奖励替换永久饰品后会清理旧战斗占位状态中的失效来源。
- 校验保留测试房间任意跳年/节点的 8 项明确路线历史例外；饰品容量和定义重复仅在相应开关启用时放宽。类型、有效引用、唯一实例、非负/唯一槽位仍需满足。
- 数值锁恢复是测试层边界行为，保留真实引擎事件并追加恢复回执；无法同时满足锁值与合法上限的命令原子拒绝，不发布矛盾状态。
- 存档载入在校验后清理临时 editing 标记。现有 shell 首次渲染原本也会自愈；补测没有复现“原 UI 保存再载入后卡死”，不能夸大为已复现的产品死锁。
