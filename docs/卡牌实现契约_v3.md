## 2. 条目结构

每条卡包含设计字段与引擎导向字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `name_key` / `name` | string | R3 命名空间；`name_key` 暂与 ID 一致，接入 UI 时再补本地化键 |
| `owner` | `C`/`P01`～`P04` | 公共牌或角色归属 |
| `character` / `group` | string | 设计快照中的展示名与功能分组 |
| `type` | `work`/`strategy`/`ability`/`cooperation`/`scene` | 主类型；考试替代面不改变主类型 |
| `rarity` | `basic`/`common`/`advanced`/`rare`/`token` | 基础、普通、进阶、稀有、衍生 |
| `cost` / `upgraded_cost` | int | 基础费用；重费资格判断用 `cost`，不随临时减费改变 |
| `target` | `self`/`task`/`all_tasks`/`unit`/`discard`/`paper`/`earliest_task` | 出牌目标 |
| `permanent` | bool | 永久牌/衍生牌 |
| `tags` | string[] | 设计标签，不参与规则判定 |
| `requirements` / `upgrade_requirements` | condition[] | 出牌前必须满足的条件 |
| `effects` / `upgrade_effects` | effect[] | 主效果序列；升级面为完整替换列表 |
| `conditions` / `triggers` | string[] | 从条目中提取的 DSL 词表，供审计 |
| `flags` | object | `innate`、`retain`、`exhaust`、`unique`、`upgradable`、`paper_record` |
| `limits` | object | `per_instance_per_turn`、`same_name_once_per_turn` 等 |
| `ability` | object? | 能力牌的延迟生效与触发器 |
| `chapter` | object? | 章节牌的基础/常驻/升级常驻面 |
| `exam` | object? | 完整考试替代面（触发条件 + 基础/升级效果） |
| `base_text` / `upgraded_text` | string | 设计原文，便于逐字追溯 |
| `implementation` | object | `status`、`runtime_enabled`、`pending_mechanics` |

目录顶层 `character_rules` 记录跨卡规则：P01 被动取回、准备加值上限 12 与减费上限 1；P02 同名每回合一次、论文进度 10/引用 5/章节 3 槽；P03 复合反应每回合一次；P04 协同上限 6、伙伴槽 3。`starters` 记录公共起手（C-01×4、C-02×4、C-03、C-04）与四人各自的 2 张专属起手，合计每人 12 张。

## 3. 条件 DSL

条件对象为 `{"kind": "...", ...}`；可用 `{"all": [...]}` / `{"any": [...]}` 组合。

| kind | 语义 |
|---|---|
| `link` | 当前工作牌的前一张成功打出牌主类型为策略 |
| `prev_card_type_is` | 前一张成功打出的牌主类型等于 `value` |
| `played_type_count_turn` | 本回合已成功打出 `value` 类型牌至少 `min` 张 |
| `instance_plays_battle` | 本实例本战成功打出次数至少 `min` |
| `previous_strategy_plays_min` | 前一策略实例本战已成功打出至少 `value` 次 |
| `retrieved_strategy_this_turn` | 本回合被动已成功取回策略牌 |
| `paid_citation_focus_this_turn` | 本回合已为引用额外支付专注 |
| `citation_min` / `hand_other_min` | 引用层数 / 其他合法手牌数量门槛 |
| `target_has_status` / `target_status_kinds` | 目标已有指定状态 / 状态种类数达到 `min`（`max` 可用于“无负面”） |
| `target_has_any_timed_debuff` | 目标有易伤/虚弱/脆化之一 |
| `target_had_induced_at_play_start` | 出牌开始时目标已有诱发 |
| `target_still_alive` | 前一效果后目标仍在场 |
| `ddl_lte` | 剩余 DDL 不高于 `value` |
| `paper_open` / `paper_closed` | 已/未开题 |
| `paper_progress_min` | 论文进度至少 `value` |
| `paper_name_unused` / `paper_name_used` | 本牌名在本篇未用/已用（主效果前快照） |
| `chapter_count_min` / `other_chapter_ran_window` | 在场章节数 / 本次窗口已有其他章节运行 |
| `partner_count_min` / `no_partner` | 伙伴数量 |
| `synergy_min` / `synergy_is_zero` | 协同资源 |
| `independent_exam` / `fixed_exam_room` | 考试替代面条件 |
| `first_cooperation_resolved` / `summoned_partner_turn` / `healed_partner_turn` | 本回合事件 |
| `erosion_applied_events_min` / `first_induced_trigger` / `compound_reaction_success` | 沈见章计数/反应事件 |
| `any_task_has_induced` / `any_task_debuff_kinds_min` / `two_tasks` / `prepare_window` | 目标集合与准备窗口 |

## 4. 效果 DSL

效果对象为 `{"op": "...", ...}`，按数组顺序结算；`condition` 可挂在效果上，`bonus` 表示同段条件加值。

| 组 | op |
|---|---|
| 完成/资源 | `complete`、`relax`、`heal`、`lose_vitality`、`gain_focus`、`draw`、`discard`、`retain`、`exhaust_other`、`retrieve` |
| 任务负面 | `apply_status`、`remove_status`、`remove_shield`、`status_complete`、`trigger_erosion`、`extend_timed_debuffs`、`modify_erosion_window`、`arm_erosion_on_next_draws` |
| 林序准备 | `add_work_bonus`、`work_bonus_next`、`cost_discount_next` |
| 论文/章节 | `paper_open`、`paper_progress`、`paper_citation`、`paper_modifier`、`paper_amplify`、`paper_publish`、`spend_citation`、`change_topic`、`chapter_deploy`、`chapter_run`、`chapter_return`、`chapter_return_with_modifier`、`swap_chapter_slots`、`copy_chapter_to_hand`、`publication_cost_discount` |
| 唐以宁 | `gain_synergy`、`spend_synergy`、`spend_synergy_up_to`、`spend_all_synergy`、`summon_partner`、`partner_heal`、`partner_retreat`、`partner_extra_action` |
| 卡牌/抽牌堆 | `generate_card`、`search_draw_for_type`、`shuffle_draw`、`establish_scene` |

动态数值用 `{"ref": "actual_discarded"}` 或 `source_stacks` 等值表达式；多段完成用 `segment` 和 `no_transfer`；群体目标用 `target: "all_tasks"`，按目标计数的字段用 `per_target`。结构化加值字段包括 `bonus`（条件同段加值）、`per_link_work`、`per_partner`、`per_debuff_kind`、`per_other_chapter`、`per_spent`、`per_unit` 和 `cap`；`same_segment` 表示只作用于当前段/主目标。`search_draw_for_type` 携带 `fallback_draw`；`arm_erosion_on_next_draws` 携带 `status`/`stacks`/`target`；`status_complete` 携带 `status`/`target`。

## 5. 能力、章节与考试

- `ability`：`activate`（当前只允许 `next_round`）、`stack`（同名不叠加用 `unique_name`）、`triggers[]`（`on`、`effects`、`upgrade_effects`、`limit`、`no_compound_reaction`）。能力牌自身出牌不执行触发器效果。`on` 词表包含准备、首张/连携工作结算、策略结算、论文进度、章节窗口、首张合作、侵蚀/诱发/复合反应等；需要“结算前加值”的能力使用 `first_work_card_resolving`，不能复用结算后触发器。
- `chapter`：`activate`（固定 `next_round`）、`deploy.requires`、`resident.on/effects`、`upgraded_resident.on/effects`。首次部署执行主效果后进槽；自动运行不记账；手动重用只执行基础面。
- `exam`：`condition`（`independent_answer`/`fixed_exam_room`）、`target`（考试面自己的目标，允许与普通面不同）、`effects`、`upgrade_effects`。考试面保留主类型、费用、升级与耗尽，不执行普通面的召入/恢复/协作选择。

## 6. 生成与校验

```powershell
python artifacts/redesign-20261030/build_cards_v3_runtime.py
python tools/validate_cards_v3_catalog.py
```

生成器从设计快照读取身份、费用、类型、稀有度与原文，合并人工编写的结构化效果，输出 174 条目录；校验器逐项核对 ID 集合、名称/费用/类型/稀有度/原文、172+2 数量、每人 20/15/5、公共 12、DSL 词表、`catalog_only` 与 `runtime_enabled: false`。

当前实测摘要：`cards=172 tokens=2 total=174`；`permanent owners = C12/P0140/P0240/P0340/P0440`；`runtime_enabled=0`；DSL 词表为 48 个 op、46 个 condition、14 个 trigger；`cards_v3_catalog=valid`。证据见 `artifacts/verification/cards-v3-catalog-20261103/`；Godot 套件 `CARDS_V3_CATALOG_EVIDENCE` 同时验证文件可解析、数量与 owner 计数。
