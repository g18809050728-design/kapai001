## 3. 新增 schema 与引擎能力

内容层（`src/content/content_db.gd`，白名单与校验同步扩充）：

| 位置 | 字段 | 语义 |
|---|---|---|
| task | `on_complete_effects: [effect]` | 任务被完全完成（最后阶段移除）前结算的效果；复用现有效果 op |
| task | `shield_persistent`（布尔） | 为 true 时敌方准备阶段不清零屏障 |
| task | `taunt`（布尔） | 单体任务牌的目标候选必须包含至少一个嘲讽任务 |
| task | `draw_reduction`（正整数） | 在场时每回合少抽 N 张 |
| task | `first_card_cost_bonus`（正整数） | 在场时每回合第一张牌费用 +N |
| task | `discard_on_first_card`（正整数） | 在场时每回合第一张牌打出后随机弃 N 张 |
| task | `max_vitality_reduction`（正整数） | 在场时每回合我方精力上限 -N |
| task | `self_copy_every_round`（布尔） | 每回合复制自身（复用召唤逻辑） |
| task.phases[].intents[] | `pressure_per_vitality` + `pressure_vitality_step` | 我方精力每高出 step 点压力 +N |
| task.phases[].intents[] | `pressure_has_unit_mult` / `pressure_no_unit_mult` | 有/无合作单位时压力百分比倍率 |
| task.phases[].intents[] | `pressure_when_shield` | 自身有屏障时压力 +N |
| task.phases[].intents[] | `pressure_per_card_type`（`{type: N}`） | 我方本局已打出该主类型牌数 ×N 加到压力 |
| task.phases[].intents[] | `player_gain_focus` / `player_reduce_focus` | 意图结算时我方专注 +N / -N |
| 效果 op | `pressure` / `reduce_relax` / `reduce_max_vitality` / `restore_max_vitality` / `reduce_focus` / `random_discard` / `summon_task` | 供结课效果与后续内容复用 |
| status | `work_boost`（工作增益） | 我方状态，cap 10；每层工作时额外完成 1（`completion_per_stack`） |
| card | `X03 签到表` | `unplayable: true` 的临时废牌，仅由 N26 注入 |

引擎侧（`src/battle/battle_engine.gd`、`battle_card_rules.gd`、`battle_codec.gd`）：

1. `_advance_or_remove_task` 在移除最后阶段前调用 `_run_on_complete_effects`；单阶段任务与多阶段任务的最终阶段都会触发。
2. 敌方准备阶段跳过 `shield_persistent` 任务的屏障清零。
3. `_run_player_prepare` 每回合按 `max_vitality_reduction` 削减精力上限；`restore_max_vitality` 以开战基线 `max_vitality_base` 为上限恢复。
4. 抽牌阶段按 `draw_reduction` 减少抽牌；`calculate_cost` 在第一张牌时叠加 `first_card_cost_bonus`。
5. 出牌时维护 `played:any` 回合计数；第一张牌后按 `discard_on_first_card` 随机弃牌（`battle` 随机流）。
6. `_target_candidates(state, "task")` 在存在嘲讽任务时收窄单体候选。
7. 压力阶段支持 `pressure_per_vitality`、`pressure_when_shield`、`pressure_has_unit_mult`/`pressure_no_unit_mult`、`pressure_per_card_type`；`pressure_per_card_type` 读取本局 `card_type:*` 计数。
8. `_execute_intent_skill` 支持 `player_gain_focus` / `player_reduce_focus`。
9. 轮末按 `self_copy_every_round` 召唤自身；`work_boost` 在 `_apply_completion` 中按层追加完成量。
10. `BattleCodec` 仅新增可选的 `max_vitality_base` 字段（缺省时回退 `max_vitality`），旧档仍可解码。

## 4. 对草稿的解读与偏差（必须明示）

### 4.1 N14/N20 的「对敌方施加压力、降低其屏障」

草稿原文按项目术语把「敌方」定义为任务方，但「施加压力」在本引擎只能作用于我方，两者字面冲突。本轮采用「任务死亡时反噬我方」的解读：N14 结课施加压力4并扣放松4；N20 结课施加压力4。**未实现**「削减相邻任务未完成量/屏障」的友军伤害版本。这是实现计划中标注为需用户拍板的唯一语义分歧，G0 前应重新裁决。

### 4.2 N15 的「可解除的补考回复」

草稿写「阶段完成时：回复自身未完成量8」。本轮建模为两个连续阶段：代码 30 → 补考 8，总工作量等价于 30+8，但**没有**独立的「补考」增益与其可解除性。玩家无法用净化类效果提前结束第二形态。

### 4.3 N16 的反应式切换

草稿要求「受到我方攻击或轮末时切换惊喜/惊吓」。本轮用普通意图交替（A 惊喜 → B 惊吓）近似，**未实现**受击立即切换的状态机；切换时机只在轮末。

### 4.4 N18 的「免疫一次攻击」

草稿写「获得1次屏障（免疫一次我方攻击）」。本轮用 `shield_persistent: true` + 意图 `shield: 5` 建模为「不清零的 5 点屏障」，接近吸收一张工作牌，但**不是**严格的「整次攻击免疫」；屏障仍按点数抵扣。

### 4.5 N21/N25/N31 的精力/专注上限

- N21 的「每回合精力上限-1（逐回合递增）」实现为在场期间每回合 -1（累加），未实现「削减量本身逐回合增大」。
- N25 的「完成时专注上限-2，持续2回合」只实现了 +5 专注；**未实现**限时专注上限削减（需要临时状态与上限状态机）。
- N31 的「完成时恢复被降低的精力上限」以 `restore_max_vitality 99` 恢复到开战基线，符合语义。

### 4.6 N24/N37 的递增与倒计时

- N24「每回合攻击力翻倍」实现为 4 段递增意图 4→8→16→32 并 `clamp` 停留，未做真正的逐回合指数增长。
- N37「2回合内未完成则全体压力10＋专注-2＋自身完成」实现为 `clamp` 双意图（A 压力5 停留；B 触发并 `self_destruct`），倒计时长度由 A 的停留次数体现，**没有**独立的回合计数器。

### 4.7 数值

全部为草稿值，未平衡。N24 的 32 点压力、N32/N27 的缩放上限都可能过强；进第一学期前需按实际试玩调整。
