# 程序启动指南

希望用当前服务器已有的 screen 长期运行或维护项目，见 [screen 部署与长期运行指南](screen部署指南.md)，其中区分已有 systemd 部署与可选的 screen API 接管步骤。

适用于当前 Windows 开发、Linux 部署的《交大四年：DDL 战争》。主程序地址为 `https://47.93.245.237/`。账号、对局、云存档和玩家反馈使用生产 MySQL，生产 API 就绪检查返回 `status=ok`，迁移版本为 `0005_feedback`。[当前发布记录](plans/2026-11-27-player-feedback-release.md)

当前各入口的用途如下。

| 入口 | 使用方式 | 数据位置 |
|---|---|---|
| Windows Godot 源工程 | 本机开发、运行和调试 | 本机 Godot 存档 |
| Linux HTTPS 内测 | 浏览器使用账号登录、游客登录、对局历史和云存档 | 本浏览器存档及内测 MySQL |
| 当前公网主程序 | 浏览器使用账号登录、游客登录、对局历史、云存档和反馈 | 本浏览器存档及生产 MySQL |

账号功能当前接入 Web 构建。Windows 直接运行 Godot 源工程时使用本机存档，账号界面通过 Web 的 JavaScript 桥接加载。Windows 上可以直接访问公网主程序验证账号功能。

管理员即开发者：正式站和内测使用管理员账号登录后，主菜单直接提供「测试房间」和「文本编辑」。普通账号与游客不开放开发工具，无需配置独立团队资格开关。本机 Godot 开发运行直接提供这些工具。[权限实施记录](plans/2026-11-21-admin-developer-tools.md)

当前服务链路为浏览器 → Nginx HTTPS → FastAPI → MySQL。正式站使用独立的生产库，玩家在正式站注册账号。使用原公网地址访问时，可在游客模式读取该站点已有的本机游客档。

| 环境 | 数据库名 | 当前迁移版本 | 管理员数量 |
|---|---|---|---|
| 开发 | `kapai_dev` | `0005_feedback` | 0 |
| 内测 | `kapai_stage` | `0004_direct_signup` | 0 |
| 生产 | `kapai_prod` | `0005_feedback` | 1（原账号发布检查） |

下面的启动及管理员命令默认针对正式环境。

## 访问主程序

浏览器打开 `https://47.93.245.237/` 即可。主菜单提供「登录」「创建账号」「游客登录」。注册无需邮件。游客进度保存在本浏览器，账号可使用云存档。游客菜单的「退出登录」返回身份选择页。

## 从 Windows 访问已部署的内测版

1. 在 Windows PowerShell 中建立 SSH 隧道。把 `服务器SSH用户名` 和 `服务器地址` 替换成自己的连接信息。

   ```powershell
   ssh -N -L 18443:127.0.0.1:18443 服务器SSH用户名@服务器地址
   ```

2. 保持该窗口运行，在浏览器打开 `https://localhost:18443/`。首次使用需信任服务器的内测证书，证书文件位于 Linux 的 `/etc/kapai001/stage-cert.pem`。Windows 上继续使用此地址，浏览器才能读取同一站点的游客进度。
3. 主菜单提供「登录」「创建账号」「游客登录」。创建账号填写用户名、密码和确认密码，成功后直接进入已登录菜单。注册无需邮件。
4. 游客登录后可开局及继续本浏览器进度。游客菜单里的「退出登录」返回身份选择页，再次选择游客可续玩原本机档。
5. 普通账号从主菜单「账号 · 用户名」查看「我的对局」或「云存档」。跨设备使用同一账号，游客旧进度可在云存档页面选择导入。

内测入口监听服务器回环地址 `127.0.0.1:18443`，远程访问使用上述隧道。

2026-11-26 的换题、额外要求和眨眼修复可在同一隧道下的 `https://localhost:18443/three-battle-fixes/` 试玩。沿用内测账号和游客入口。[验证记录](../artifacts/verification/three-battle-fixes-20261126/README.md)

## Linux 当前服务器的启动与检查

当前服务器已安装 Godot `4.7.2.stable`、Python `3.11.13`、MySQL `8.0.45`、Nginx 和后端虚拟环境。下面的命令在有服务管理权限的 Linux 终端运行。

```sh
cd /opt/kapai001
systemctl start kapai-mysql
systemctl start kapai-api-prod
systemctl start nginx
systemctl start kapai-api-prod-prune.timer
systemctl is-active kapai-mysql kapai-api-prod nginx
```

正常情况下输出三行 `active`。这些服务及清理定时器当前都已设置开机启动。

检查 API 进程和数据库就绪状态。

```sh
curl --fail http://127.0.0.1:18445/internal/live
curl --fail http://127.0.0.1:18445/internal/ready
```

当前预期返回如下。

```json
{"status":"ok"}
{"status":"ok","migration":"0005_feedback"}
```

`/internal/ready` 会实际查询 MySQL 的迁移表。它返回 200 且版本一致，说明 API 可以访问已迁移的数据库。`/internal/live` 用于检查 API 进程。

当前连接及文件位置如下。

| 项目 | 位置或地址 |
|---|---|
| 源工程 | `/opt/kapai001` |
| 后端 Python 环境 | `/opt/kapai-api-venv` |
| MySQL 数据目录 | `/var/lib/kapai-mysql` |
| MySQL Unix socket | `/run/kapai-mysql/mysql.sock` |
| 正式 API | `http://127.0.0.1:18445` |
| 正式站点 | `https://47.93.245.237/` |
| 正式 Web 构建 | `/var/www/kapai001/releases/20261121-admin-developer-tools` |
| 正式后端快照 | `/opt/kapai-api/releases/20261121-admin-developer-tools` |
| 正式 Nginx 配置 | `/etc/nginx/conf.d/kapai001.conf` |
| 正式数据库配置 | `/etc/kapai001/prod-app.env` |
| 正式 API 功能配置 | `/etc/kapai001/prod-api.env` |
| 正式迁移配置 | `/etc/kapai001/prod-migrate.env` |
| 内测 API | `http://127.0.0.1:18444` |
| HTTPS 内测 | `https://localhost:18443/` |
| 当前内测构建 | `/var/www/kapai001/staging/admin-developer-tools-20261121` |
| Nginx 内测配置 | `/etc/nginx/conf.d/kapai-stage.nginx.conf` |
| 内测应用数据库配置 | `/etc/kapai001/stage-app.env` |
| 内测 API 功能配置 | `/etc/kapai001/stage-api.env` |
| 内测迁移数据库配置 | `/etc/kapai001/stage-migrate.env` |

MySQL 当前使用 Unix socket，`kapai-mysql` 服务以 `--skip-networking` 运行。Windows 浏览器通过 API 使用数据库。

查看最近的服务日志。

```sh
journalctl -u kapai-api-prod -n 80 --no-pager
journalctl -u kapai-mysql -n 80 --no-pager
nginx -t
```

生产服务从版本目录加载后端代码。更新后端时创建新发布快照并调整服务工作目录，然后运行 `systemctl daemon-reload` 和 `systemctl restart kapai-api-prod`。只修改生产 API 环境配置时运行 `systemctl restart kapai-api-prod`。修改 Nginx 配置后先运行 `nginx -t`，通过后运行 `systemctl reload nginx`。

## Windows 本机开发启动

安装 Godot `4.7.2.stable`，在项目根目录用编辑器导入 `project.godot`，然后按 F5 运行项目。命令行可用以下 PowerShell 命令，将路径替换成本机实际位置。

```powershell
Set-Location 'D:\你的项目目录\kapai001'
$env:GODOT_BIN = 'D:\Godot\Godot_v4.7.2-stable_win64_console.exe'
& $env:GODOT_BIN --headless --editor --path . --quit
& $env:GODOT_BIN --path .
```

本机存档通常位于 `%APPDATA%\Godot\app_userdata\交大四年：DDL战争\saves\`。Web 游客进度保存在相应站点的浏览器数据中，Web 账号存档按账号分别隔离，云副本存入 MySQL。

本机开发后端时需要 Python 3.11 和已建好的开发 MySQL 库。安装依赖并在本机环境变量中填写[配置样例](../server/config.env.example)的开发数据库信息。应用账号具有读写权限，迁移时使用该开发库的迁移账号。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r server\requirements.txt
```

配置样例中的值需要换成本机实际配置。下面只展示加载到当前 PowerShell 的变量形式。

```powershell
$env:KAPAI_DB_HOST = '127.0.0.1'
$env:KAPAI_DB_PORT = '3306'
$env:KAPAI_DB_NAME = 'kapai_dev'
$env:KAPAI_DB_USER = '本机开发库账号'
$env:KAPAI_DB_PASSWORD = Read-Host '输入本机开发库密码' -MaskInput
$env:KAPAI_ORIGIN = 'https://localhost:18443'
$env:KAPAI_ACCOUNTS = '1'
$env:KAPAI_REGISTRATION = '1'
$env:KAPAI_ADMIN = '1'
$env:KAPAI_CLOUD = '1'
```

`-MaskInput` 适用于 PowerShell 7。Windows TCP 连接使用上面的 host/port，Linux 当前环境则设置 `KAPAI_DB_SOCKET`。

新库先用迁移账号运行迁移，再把用户及密码切换为应用账号启动 API。

```powershell
.\.venv\Scripts\alembic.exe -c server\alembic.ini upgrade head
.\.venv\Scripts\python.exe -m uvicorn kapai.main:api --app-dir server --host 127.0.0.1 --port 18444
```

完整 Web 登录使用同源 HTTPS 网关，`KAPAI_ORIGIN` 必须等于浏览器页面的协议、域名和端口。例如当前内测为 `https://localhost:18443`。网关将 `/api/v1/` 转发到 API，其他路径提供 Web 构建。现成的路由配置可参考[内测 Nginx 配置](../server/deploy/kapai-stage.nginx.conf)。Windows 开发机上快速验证完整账号流程可直接使用本文开头的 SSH 隧道。

## 管理员账号

程序的管理员由服务端命令创建，用户名和密码在创建时指定。当前生产库已有管理员账号，可用原用户名或邮箱加密码登录。普通注册创建 `player` 角色。

| 登录项 | 当前状态 |
|---|---|
| 默认管理员账号 | 未预置 |
| 默认管理员密码 | 未预置 |
| 当前可用管理员 | 生产库已有管理员账号 |
| 创建后可用登录名 | 创建时指定的用户名或邮箱 |
| 密码要求 | 12–128 个字符，创建时自行设置 |
| 登录方式 | 用户名或邮箱加密码 |

创建正式管理员时，在服务器的私有终端中运行以下步骤。命令中的邮箱和 `game_admin` 为填写示例，替换成自己的邮箱及希望使用的用户名。选择尚未注册的用户名和邮箱。

```sh
cd /opt/kapai-api/releases/20261121-admin-developer-tools
set -a
. /etc/kapai001/prod-app.env
. /etc/kapai001/prod-api.env
set +a
/opt/kapai-api-venv/bin/python -m kapai.manage admin-create your-admin@example.org --username game_admin
```

终端提示 `New administrator password` 时输入自定密码。密码存 Argon2id 哈希，创建成功后会显示确认信息。

创建成功后，打开正式站点，选择「登录」，输入设定的用户名或邮箱及密码即可。登录后从主菜单进入「账号 · 管理员 → 管理统计」。

创建、撤权及管理员统计访问会记录审计。撤销指定邮箱的管理员角色可在同样环境下运行下面的命令。

```sh
/opt/kapai-api-venv/bin/python -m kapai.manage admin-revoke your-admin@example.org
```

管理员账号属于创建时所选数据库。上述命令创建正式管理员，内测管理员使用内测工作目录及对应的 `stage-app.env`、`stage-api.env` 创建。

## 更新 Web 构建和数据库

启动现有正式版或内测版时使用 `systemctl` 即可。开发改动后需要重新导出 Web。以下命令在 Linux 项目根目录执行，先安装 Godot 4.7.2 对应的官方 Web 导出模板。

```sh
cd /opt/kapai001
godot --headless --path . --import
KAPAI_BUILD_VERSION=20261121-dev01 sh tools/export_web.sh /var/www/kapai001/staging/20261121-dev01
```

示例版本号为 `20261121-dev01`，可换成新的字母、数字、点或连字符组成的版本号。将内测 Nginx 配置的 `root` 指向完整导出的新目录，检查配置并重载。当前服务器内存较小，导出期间可沿用既有的导出进程内存限制配置，历次导出证据保存在 `artifacts/verification/`。

有新的数据库迁移时，在项目根目录加载相应环境的迁移配置。例如升级内测库可运行以下命令。

```sh
cd /opt/kapai001
set -a
. /etc/kapai001/stage-migrate.env
set +a
/opt/kapai-api-venv/bin/alembic -c server/alembic.ini upgrade head
/opt/kapai-api-venv/bin/alembic -c server/alembic.ini current
systemctl restart kapai-api-stage
curl --fail http://127.0.0.1:18444/internal/ready
```

当前正式数据库已升级至 `0005_feedback`，生产 API 和公网网关已经接入。后续生产发布沿用版本目录、迁移、就绪检查与原子切换流程。[当前发布和回滚记录](plans/2026-11-27-player-feedback-release.md)

| 遇到的现象 | 检查方式 |
|---|---|
| 打不开 `localhost:18443` | 检查 SSH 窗口及 Linux 的 Nginx 服务 |
| 提示无法确认账号状态 | 检查 API 服务及 `/internal/ready` |
| 返回 `database_not_migrated` | 核对当前数据库的 Alembic 版本 |
| 返回 `origin_rejected` | 核对页面地址与 `KAPAI_ORIGIN` 是否完全相同 |
| 注册成功后无法保存会话 | 核对 HTTPS 网关和浏览器 Cookie，保持同一站点访问 |
| 登录后没有「管理统计」 | 核对账号在当前数据库中的角色及 `KAPAI_ADMIN` |
| 新账号忘记密码 | 当前用户名注册未绑定邮箱，已有验证邮箱的账号可用邮件重置 |

账号服务和运维细节见[后端说明](../server/README.md)，现有登录、游客和退出流程见[游客流程记录](plans/2026-11-21-restore-guest-login.md)。
