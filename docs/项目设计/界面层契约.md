# 界面层契约（src/ui/**）

> 实现来源：《统一设计文档》§10 局流程、《接口文档》§5 RunView、《局流程契约》§2 RunStep、t1 战斗界面契约。
> 本文是 **界面层（局流程页面）对外契约的唯一说明**：页面与 shell 的分工、页面跳转表、视图字段来源、
> 存档入口、战斗交接与测试口径。变更本文件必须同步 `tests/suites/test_ui_shell_run.gd` 与 `test_ui_shell_pages.gd`。
> 验证命令见 README（退出码 0 才算过）。

## 1. 模块边界

| 文件 | 职责 | 谁可以改 |
|---|---|---|
| `src/ui/ui_page.gd` | 页面基类：`render(view)` / `build_action()` / 按钮 uid / 门控落地 | ui-shell |
| `src/ui/page_*.gd` | 12 个页面（menu/setup/map/reward/shop/event/rest/battle_entry/term/ending/summary/settings） | ui-shell |
| `src/ui/game_shell.gd` | 唯一知道 RunService / SaveStore 的界面对象：路由、分发、存档、门控、战斗交接 | ui-shell |
| `src/ui/dev_auto_battle.gd` | 开发回退：没有战斗界面时用 BattleEngine 公开入口代打 | ui-shell |
| `src/ui/main.gd` / `main.tscn` | 游戏入口：载内容库 → 造 shell → 探测并接入战斗界面 | ui-shell |
| `src/ui/battle_screen.gd` / `battle_screen.tscn` | 战斗界面（t1，class BattleScreen） | ui-battle |
| `src/ui/battle/**` | 战斗界面组件与控制器：`battle_session.gd`、`battle_labels.gd`、`battle_style.gd` 等 | ui-battle |

铁律：

1. **页面不持有规则状态**：页面只有 `view`（只读视图）与本地展示选择；不 import RunService / SaveStore / RunState。
2. **可达性与可用性不自己算**：节点来自 `view.nodes`，可达集合来自 `view.reachable_node_ids`；
   每个规则操作按钮的可用性由 shell 用 `RunService.preview` 统一门控（§2.3）。
3. **存档只走 SaveStore**：界面不出现 FileAccess / DirAccess；写盘只发生在 `GameShell.save_now()`。
4. 只消费 `RunService.make_view` / `BattleEngine.make_view` 的现成字段；缺字段先发消息给队长，不自己在界面里补规则。

## 2. UiPage 契约（页面与 shell 的唯一接口）

```gdscript
func render(view: Dictionary) -> void      # 画出来；重复调用会清空重建（按钮表也重建）
func build_action() -> Dictionary          # 最近一次点击产生的操作草稿 {"type","payload"}，无则 {}
func press(uid: String) -> bool            # 模拟鼠标：按钮不存在或 disabled 时返回 false
func action_uids() -> Array                # 登记为规则操作的按钮 uid
func action_draft(uid: String) -> Dictionary  # 该按钮当前草稿（可以是 Callable 动态算出来）
func apply_gating(results: Dictionary) -> void  # {uid: {"ok": bool, "reason": String}}
func button_disabled/button_reason/button_text/button_uids()
```

### 2.1 uid 命名（测试与自动化依赖）

| 前缀 | 含义 | 例 |
|---|---|---|
| `menu:*` | 主菜单/设置导航 | `menu:new`、`menu:continue`、`menu:settings` |
| `setup:character:<id>` / `setup:difficulty:<id>` / `setup:seed_random` / `setup:start` | 选人与开局 | `setup:start` |
| `node:<node_id>` | 地图节点（`node_id` 来自视图） | `node:R...|t1l6_boss` |
| `reward:<item_id>:pick:<candidate_id>` / `reward:<item_id>:claim` / `reward:<item_id>:skip` / `reward:<item_id>:replace:<relic_id>` / `reward:leave` | 奖励 | |
| `shop:buy:<stock_id>` / `shop:remove:<card_instance_id>` / `shop:leave` | 商店 | |
| `event:<option_id>` / `event:<option_id>:card:<card_instance_id>` / `event:<option_id>:pick:<candidate_id>` / `event:<option_id>:replace:<relic_id>` / `event:leave` | 事件 | |
| `rest:take:<option_id>[:<card_instance_id>]` / `rest:leave` | 休息 | |
| `battle:start` / `battle:resume` / `battle:leave` / `battle:save` / `battle:menu` | 战斗入口 | |
| `term:<step_id>:choose:<candidate_id>` / `term:<step_id>:skip` / `term:<step_id>:track:<track>` / `term:menu` | 学期结算 | |
| `ending:<ending_id>` / `ending:menu` | 结局 | |
| `summary:retry` / `summary:menu` | 摘要与失败重开 | |
| `map:save` / `map:abandon` / `map:abandon_confirm` / `map:menu` | 地图上的存档与放弃 | |
| `settings:difficulty:<id>` / `settings:save` / `settings:restore_backup` / `settings:back` | 设置 | |

### 2.2 草稿类型

- 规则操作：`enter_node` / `claim_reward` / `skip_reward` / `buy_item` / `remove_card` / `choose_event` /
  `take_rest` / `leave_node` / `choose_term_option` / `choose_ending` / `abandon_run`（= `RunService.RUN_ACTIONS`）。
- 界面动作（shell 自己处理，不发给 RunService）：`ui.*`（menu / new_run / settings / continue / save /
  save_settings / restore_backup / start_battle / resume_battle / retry / quit）与 `create_run`。
- **依赖页面本地选择的草稿必须是 `Callable`**：例如「休息升级哪张牌」「事件替换哪个饰品」。
  否则 shell 的门控会拿到渲染那一刻的旧选择。

### 2.3 门控（界面不得自行放行非法操作）

`GameShell._regate()` 在**每次渲染后**对页面上的每个规则操作按钮调用一次 `RunService.preview`：

```
can_submit == false  ->  按钮 disabled + tooltip 写明原因（preview.blocking_errors / required_selections）
```

于是「点击不可达节点」「买不起还买」「没休息就离开」「奖励没领完就离开」在界面上**根本点不动**，
`press(uid)` 对 disabled 按钮直接返回 false（与鼠标一致）。

## 3. 页面跳转表

页面由 `view.screen` 决定（`RunService._screen_of` 是唯一路由依据），局外页面由 shell 的 `_ui_screen` 覆盖：

| screen | 页面 | 触发条件（规则层） |
|---|---|---|
| `menu` | UiMenuPage | shell 处于菜单（无局或从局内返回） |
| `setup` | UiSetupPage | shell 处于选人（`ui.new_run`） |
| `settings` | UiSettingsPage | shell 处于设置（`ui.settings`） |
| `map` | UiMapPage | 没有待决界面（节点可进入 / 节点已结算完） |
| `battle` | UiBattleEntryPage | 当前节点是未结算的战斗节点 |
| `reward` | UiRewardPage | `run.pending_reward != null`（含已领完、等待离开） |
| `shop` | UiShopPage | 当前节点是 active 的商店 |
| `event` | UiEventPage | 当前节点是 active 的事件 |
| `rest` | UiRestPage | 当前节点是 active 的休息 |
| `term` | UiTermPage | `run.settlement != null 且未完成` |
| `ending` | UiEndingPage | 已通关且还没选结局 |
| `summary` | UiSummaryPage | `run.outcome` 非空（胜利/失败/放弃） |

`ui.menu` 会把 `_ui_screen` 置为 `menu`（局内状态保留在 session 里，可再 `ui.continue` 回局内）；
`ui.save` 走 §7；`map:abandon` 是二次确认（第一次是本地按钮，第二次才发 `abandon_run(confirmed=true)`）。
## 4. 局外页面视图（shell 组装）

### 4.1 主菜单 `menu`

| 字段 | 来源 |
|---|---|
| `has_save` / `save_meta` / `save_error` | `SaveStore.inspect(current_run)`；不存在时 `SAVE_NOT_FOUND` |
| `profile` | `SaveStore.load(profile)` 的 payload（没有则 `ProfileMerge.empty_profile()`） |

「继续」在 `has_save=false` 时由页面自己禁用（不是门控，因为读档不是规则操作）。

### 4.2 选人 `setup`

`characters: [{id, name_key, starter_cards, starter_relic_id, locked, reason}]`。
`locked` 用 **`RunService.create` 试跑判定**（幂等、无副作用），不重算解锁规则；`create` 仍是唯一判定。
`difficulties` 直接来自 `RunService.DIFFICULTIES`；`defaults` 来自设置文档（§8）。
开局草稿 = `{"type":"create_run","payload":{character_id,difficulty,seed}}`，种子原样交给规则层。

### 4.3 设置 `settings`

`settings: {difficulty, seed, autosave}`、`difficulties`、`save_meta`、`backup_meta`。
`ui.save_settings` 用 `SnapshotCodec.encode_document` + `SaveStore.save(settings)` 落盘；
`autosave=false` 时局内每一步不写档，只有 `ui.save` 才写（测试覆盖了这条）。

## 5. 地图页（RunView 消费）

- 只画 `view.nodes`（当前学期 8 个节点：第 2/4 层二选一分支）；`next_ids` 原样展示，不自己连线。
- 按钮文案带类型名（普通作业 / 精英作业 / 期末大作业 / 商店 / 突发事件 / 休息）与状态（可进入 / 当前 / 已完成 / 不可达）。
- 可达性完全由 `preview(enter_node)` 门控：不在 `reachable_node_ids` 里的节点按钮是 disabled。

## 6. 奖励页

视图 `view.pending_reward`（RunService 的 offer 视图：`items[].candidates` 已冻结）。
一次点击 = 一条 `claim_reward`/`skip_reward`；饰品槽满（`relics.size() >= relic_slots`）时先选要替换的旧饰品，
没选之前 `preview` 会要求 `replace_relic_id`，领取按钮自动禁用。
`offer.complete == true` 才出现「处理完毕，继续」（`leave_node`）。

## 7. 商店页

视图 `view.shop`：`stocks[]`（sold/price 冻结）、`removal{available,used,max,price,money,minimum_deck_size,deck_size}`。
购买与删牌各是一次点击一条草稿；买不起 / 已卖出 / 删牌次数用完 / 牌组触底都由门控禁用。

## 8. 事件页（含真事件事件池）

视图 `view.event.options[]` 带 `cost / effects / candidates / enabled / blocking`。
页面按 `effects[].op` **决定画哪种选择控件**（`upgrade_card|remove_card` → 逐张牌；`gain_card|gain_relic`
无显式 ID 且候选 >1 → 逐候选；`gain_relic` 且槽满 → 先选替换目标）。这是展示逻辑，不是规则判断：
提交时 `preview(choose_event)` 会整项校验（成本 + 全部收益），不合法就禁用。
事件必须先选一项才能离开：未解决时 `event:leave` 被 `preview(leave_node)` 禁用。

## 9. 休息页

视图 `view.rest.options[]`（四选一，`enabled/blocking/needs_card`）。带目标的选项把整副牌都画成按钮，
非法目标（已满级 / 非负担 / 非合作牌）由 `preview(take_rest)` 禁用并给出原因；
`rest:leave` 在「还没休息」时被禁用。

## 10. 战斗入口与战斗界面交接（t1 契约）

```gdscript
# GameShell 暴露：
signal battle_requested(battle_input: Dictionary)   # 新战斗：直接给 BattleEngine.begin
signal battle_resumed(battle_state)                 # 读档恢复的进行中战斗（可选支持）
func take_battle_input() -> Dictionary
func attach_battle_state(state) -> void             # 战斗界面回填，使 save_now() 能把战斗写进快照
func apply_battle_outcome(outcome: Dictionary) -> Dictionary  # 战斗界面打完回填
```

战斗界面按以下约定接入（`main.gd` 自动探测 `res://src/ui/battle_screen.tscn`、`battle.tscn`、`page_battle.tscn`）：
详细契约见 `docs/项目设计/战斗界面契约.md`（t1 维护）。

1. `start_battle(battle_input: Dictionary)`：接到 shell 交出的 `battle_input`；
2. `signal battle_finished(outcome: Dictionary)`：打出 `BattleOutcome` 后发出，shell 调 `RunService.settle_battle`。

### 战斗交接的三个入口都必须 attach(state + rng)

壳与战斗界面之间只有两句话：`battle_requested(battle_input)` 出去、`battle_finished(outcome)` 回来。
但**状态与随机快照要回填给 session 的入口有三个**，任何一个漏掉都会出真 bug：

| 入口 | 谁调 | 必须做的事 |
|---|---|---|
| 新开战 | `_start_battle()` → `battle_requested` → 战斗界面 | 界面侧每次 `action_applied(step)` 都回填 `current_state()` + `current_rng_state()`（`_on_host_action_applied`） |
| 读档续战 | `_resume_battle()` → `battle_resumed` → 战斗界面 | `resume_battle(battle_state, shell.battle_rng_snapshot())`——随机流必须一起交出去 |
| 开发回退（无战斗界面） | `_dev_play_battle()` → `DevAutoBattle.play(engine, begin, on_step)` | 代打的**每一步**都回调 `attach_battle_state(state, rng_snapshot)`，所以在产出 `BattleOutcome` 之前 `battle_id` 与 `battle` 流一定已经在 session 上 |

为什么必须三个都做：
- `RunService.settle_battle` 靠 `BattleOutcome.battle_id`（= 节点 ID）定位节点；漏了回填/回填的是空 state →
  `error.run.missing_battle_id`，战斗结算不了（t15 修的就是 dev 代打这条）。
- `battle` 流只有战斗在用；不回填 → 抽牌退化成零种子，读档续战与原局不一致（架构 §8）。t15 的回归断言里
  直接比较「战斗前后 `session.random_snapshot.streams.battle` 是否变化」来盯这一条。

接线只在**一处**实现：`GameShell.attach_battle_host(screen)`（main.gd 与测试都走它），并且它用
**局的 catalog** 新建 `BattleEngine` 交给界面——所以真实对局永远用「局自己的清单」。
界面自带的默认清单（t1 的 `50b78cc` 起是 `mvp`，回落 `battle_mvp`）只在独立运行/冒烟测试时生效；
历史上界面默认过冻结的 `battle_mvp`（12 张牌），遇到出厂 mvp 独有的牌（K05/K10/…）会在 `engine.begin`
直接 `unknown_card`、战斗根本开不起来——注入局的 catalog 就是为了让它从结构上不可能再发生。
`attach_battle_host` 在挂载时新建一个 engine 交给界面；**不要在对局中途替换 engine**
（session 里已持有的 BattleState 会与旧 catalog 脱节），要换 catalog 只能走 `resume_battle` 那条路。

真实闭环覆盖（`tests/suites/test_ui_shell_run.gd` 的「真实战斗闭环」小节）：
① 真实 RunService 局 + 真实 BattleEngine（经 `battle_requested` 交接）→ settle → 精力一次性写回 → 奖励可领；
② 开发回退路径（shell 自己的引擎 + 逐步回填）→ settle → `battle` 流确实变化；
③ 真实 `battle_screen.tscn`（`attach_battle_host` 接线 + 界面 API 驱动 `select_card/select_target/confirm_choice/end_turn`）→ `battle_finished` → settle。
三条都在牌组里塞了 mvp 独有的牌（K10 / K05），把「用错清单」这件事钉死在断言里。

**读档续战（结果一致性）**：`resume_battle(battle_state, rng_ref)` 的第二个参数必须是**该战斗的随机快照**（`BattleScreen.current_rng_state()` 的同一形状：`{algorithm_version, streams{map,reward,event,battle}}`）。`main.gd` 做三件事保证它拿得到：

1. 读档续战：`resume_battle(battle_state, shell.battle_rng_snapshot())`；
2. 战斗界面每次 `action_applied(step)` 后，`main.gd` 把 `current_state()` + `current_rng_state()` 推给 `shell.attach_battle_state(state, rng)`；
3. `attach_battle_state` 把战斗的 `battle` 流合并回 `session.random_snapshot`（`battle` 流只有战斗在用），于是「存档 → 退出 → 继续 → 续战」与原局逐步一致（架构 §8）。缺了这份快照，续战抽牌会退化成零种子。
有监听者时 `view.battle_input` 非空、`view.dev_fallback=false`，按钮文案为「进入战斗」；
**没有战斗界面**时 shell 用 `dev_auto_battle.gd`（只调 BattleEngine 的 `begin/preview/apply`）代打，
按钮文案写明「开发回退」，保证局流程界面在 t1 落地前后都能整局试玩。

## 11. 学期结算 / 结局 / 摘要

- 学期结算：`view.settlement`（步骤顺序、可跳过、当前步骤）；`direction_reward` → 逐候选 + 跳过；
  `career_track` → 三轨；完成后规则层自动进入下一学期（界面不需要「下一学期」按钮）。
- 结局：`view.eligible_endings` 逐项一个按钮，发 `choose_ending`。
- 摘要：`view.run_summary`（result/reason/stats/unlocked_ids）；本页只发 `ui.retry` / `ui.menu`。
  **失败重开** = 同人物同难度、种子 +1（避免一模一样的一局）。

## 12. 存档入口（只走 SaveStore）

| 入口 | 行为 |
|---|---|
| 主菜单「继续」 | `SaveStore.load(current_run)` → `SnapshotCodec.decode_session`；正式档不可用时**自动退回备份档**并在状态栏说明 |
| 新局 | `RunService.create` 成功后立刻自动存档（`autosave=true` 时） |
| 局内每一步 | `_commit_step()` → `revision += 1` → `session.random_snapshot = step.rng_states` → 自动存档 |
| 局终 | 存档带上 `RunCodec.encode_summary(run.pending_profile_summary)`，随后 `SaveStore.commit_pending_profile()` 走结局三步提交 |
| 设置 | `SnapshotCodec.encode_document` → `SaveStore.save(settings)` |
| 恢复备份 | `SaveStore.load_backup` → 解码 → 继续（正式档保持不动，下一步操作覆盖它） |

**战斗进行中不写档**：`pending_battle_input` 非空且没有 `battle_state` 时 `_autosave()` 直接跳过，
避免留下「`active_battle_id` 非空但快照里没有战斗」的死档（这种档读回来会被 `_gate_error` 全锁死）。
战斗界面若要在战斗中存档，先 `attach_battle_state(state)`。

## 13. 测试与验证

| 套件 | 覆盖 |
|---|---|
| `tests/suites/test_ui_shell_run.gd` | 只用 `press(uid)`（真实 `Button.pressed`）走完一个学期 6 个节点，含商店交易与休息；第 1 层战斗用**真实 BattleEngine** 打通（`battle_input` → `BattleOutcome` → `settle_battle`），其余战斗注入规则层胜利结局；存档/继续/失败重开；出厂 `mvp` 清单下首领可达 |
| `tests/suites/test_ui_shell_pages.gd` | 12 个页面逐个冒烟：按钮可用性 = `reachable_node_ids` / `preview`，禁用按钮点不动、无副作用；离线视图渲染（事件选项分类、履历方向三轨、结局、摘要）；重渲染不残留旧按钮 |

口径：

- `press(uid)` 走真实信号路径，等价鼠标点击；断言必须带按钮 uid 与禁用原因，失败时可直接定位。
- 「界面不得放行非法操作」用**结构**证明：非法按钮本身就 disabled，且 `press` 返回 false。
- 战斗数值平衡不是界面验收的依赖：除清单里注明的那一场真实战斗外，其余战斗用 `settle_battle` 的合法胜利结局。
