# 《交大四年：DDL战争》接口文档

版本：v0.1｜日期：2026-10-13｜状态：待实现的模块调用契约

依据：[初步架构设计](初步架构设计.md)。本文描述Godot进程内接口，签名为类型化伪代码；参数和返回结构在实现时落为GDScript数据类。玩法数值继续引用统一设计文档。

接口标识及规则数值入口见[常量与规则配置](常量与规则配置.md)，操作名与错误码使用GameConstants中的同名常量值。

内部方法和实体行为见[类与方法设计](类与方法设计.md)，保存布局与关系约束见[数据库与实体关系设计](数据库与实体关系设计.md)。

## 1. 公共约定

- UI只调用GameSession；BattleEngine、RunService、ContentDB和SaveStore由会话层协调。
- 查询返回只读视图或副本。外部不得直接修改内部状态。
- 所有规则写操作同步执行至稳定边界或需要玩家选择的位置；动画不推进规则。
- ID使用字符串：定义ID如K01；卡、单位、任务使用各自唯一实例ID。目标参数必须传实例ID，不能传名称。
- 可空字段用`null`，集合无内容用`[]`或`{}`。金额、费用、次数、精力和DDL使用整数。
- 本局所有写操作共用一个会话`revision`，由GameSession管理；每次接受的命令递增1，拒绝、预览和保存不递增。

### 1.1 写操作上下文

`CommandContext`由UI随每次写请求传入：

| 字段 | 类型 | 说明 |
|---|---|---|
| run_id | String | 必须等于当前局 |
| expected_revision | int | 必须等于当前视图版本 |

旧版本请求返回`STALE_STATE`，不再次执行。UI刷新视图后由玩家重新操作，不自动重发购买或出牌。战斗结算与奖励另用业务ID/领取标记保证只执行一次。

### 1.2 返回结构

普通查询和存储使用`Result<T>`：`{ok: bool, data: T或null, error: ApiError或null}`。

规则写操作使用`ActionResult`：

| 字段 | 类型 | 说明 |
|---|---|---|
| accepted | bool | 是否已接受并改变会话状态 |
| revision | int | 当前版本；失败时仍返回原版本 |
| view | SessionView | 操作后的只读视图 |
| events | Array<RuleEvent> | 本次增量事件，拒绝时为空 |
| pending_choice | ChoiceRequest或null | 效果内选择，存在时只能确认该选择 |
| error | ApiError或null | 规则拒绝原因；接受时为null |
| persistence | String | `not_attempted / saved / failed` |
| save_error | ApiError或null | 保存失败原因，与规则错误分开 |

规则成功但自动保存失败时，`accepted=true`、`persistence=failed`；保留内存结果，只重试保存，不重做原操作。

`ApiError = {code: String, message_key: String, details: Dictionary}`。`details`可包含字段名、缺少资源、当前版本等诊断数据。

## 2. GameSession：UI入口

| 方法 | 参数 | 返回 | 前置条件/行为 |
|---|---|---|---|
| start_run(request) | StartRunRequest | Result<SessionView> | 无进行中局；校验人物、难度和内容清单后开局 |
| continue_run() | 无 | Result<SessionView> | 无进行中内存局；读取有效存档并恢复 |
| get_view() | 无 | SessionView | 只读；未开局返回主菜单视图 |
| preview_action(draft) | ActionDraft | Result<ActionPreview> | 不改状态、不消费随机 |
| submit(context, action) | CommandContext、GameAction | ActionResult | 校验当前局、版本与阶段后路由 |
| save_current() | 无 | Result<SaveReceipt> | 仅稳定边界；待选状态返回`CHOICE_PENDING` |
| save_and_exit() | 无 | Result<SaveReceipt> | 保存成功才释放会话并回主菜单；失败保留会话 |
| get_profile() | 无 | ProfileView | 只读解锁、教学记录与设置 |
| update_settings(settings) | SettingsPatch | Result<ProfileView> | 校验已支持字段后保存，不改变局revision |

`StartRunRequest = {character_id, difficulty, manifest_id, seed}`。difficulty为`relaxed / normal / hard`；manifest_id为`mvp / full`，以实际启用配置为准；seed为十进制整数的字符串。已有进行中局时返回`RUN_ACTIVE`，须先通过放弃操作结束，不能静默覆盖。

### SessionView

```text
run_id: String或null
revision: int
screen: menu / map / battle / reward / shop / event / rest / term / ending / summary
run: RunView或null
battle: BattleView或null
node: 当前节点视图或null
pending_choice: ChoiceRequest或null
can_save: bool
```

BattleView包含当前精力、专注、DDL、手牌及有效卡面、单位、任务、意图、场景和牌堆数量。默认不暴露抽牌堆顺序和未公开随机状态；查看牌堆时展示规则允许的信息。`zones_public` 字段提供弃牌堆与耗尽堆的卡面（与 `hand` 同构），抽牌堆与结算区只给计数。

## 3. GameAction：写操作清单

`GameAction = {type: String, payload: Dictionary}`。除标明可空的字段外，表内字段均必填。

### 3.1 战斗操作

| type | payload | 规则 |
|---|---|---|
| play_card | card_instance_id、target_ids、replace_unit_id（可空） | 玩家行动阶段；先解析考试卡面，再校验目标、费用和换班 |
| confirm_choice | choice_id、selected_ids | 仅处理当前ChoiceRequest，不能选择不在候选中的ID |
| set_ally_target | unit_instance_id、task_instance_id | 玩家行动阶段；双方实例必须仍有效 |
| end_turn | retained_card_ids | 玩家行动且无待选项；保留数量须符合当前规则，可为空数组 |

出牌前取消选牌、目标或换班属于UI本地操作，无需提交。K03抽后弃牌等效果已经开始时返回ChoiceRequest，必须完成选择；不能调用取消整张牌的接口。

`ChoiceRequest`字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| choice_id | String | 本次选择唯一ID，完成后失效 |
| kind | String | 如discard、cleanse、optional_cost |
| prompt_key | String | 提示文本键 |
| candidates | Array<ChoiceOption> | 每项为`{id, label_key, preview}` |
| min_count / max_count | int | 数量限制；可选效果允许min_count=0 |

无合法候选时由引擎按“尽量执行”等牌义自动处理，不返回无法完成的强制选择。确认选择若仍产生后续选择，返回新的choice_id。错误选择不清除原待选状态。

### 3.2 局流程操作

| type | payload | 规则 |
|---|---|---|
| enter_node | node_id | 只能进入地图当前可达节点 |
| claim_reward | offer_id、item_id、candidate_id（可空）、replace_relic_id（可空） | 领取指定奖励项；直接收益无需candidate_id；满槽须提供替换对象 |
| skip_reward | offer_id、item_id | 跳过尚未处理且允许跳过的奖励项 |
| buy_item | shop_id、stock_id、replace_relic_id（可空） | 按库存实际价格校验、支付、发放；不接受UI自报价格 |
| remove_card | shop_id、card_instance_id | 校验余额、删牌次数和至少保留5张 |
| choose_event | event_instance_id、option_id、selection_ids、replace_relic_id（可空） | 一次收齐升级/删牌等目标及替换选择后提交 |
| take_rest | node_id、option_id、card_instance_id（可空） | 恢复无需卡目标；升级、训练和删负担需合法卡 |
| leave_node | node_id | 商店离开、事件无变化离开或所有必处理项完成后退出 |
| choose_term_option | settlement_id、step_id、option_id、candidate_id（可空） | 处理学期路线、履历或方向奖励的当前步骤 |
| choose_ending | ending_id | 只能选当前满足条件的结局 |
| abandon_run | confirmed | confirmed必须为true；稳定边界结束当前局，不给战胜奖励 |

候选ID、option_id及step_id由当前节点视图提供，UI不自行构造规则条件。已领取奖励、已售库存、已完成节点不能再次提交。取消交易预选不发送命令。

### 3.3 预览

`ActionDraft`与GameAction字段相同，但允许缺少尚未选择的目标。

`ActionPreview = {revision, can_submit, required_selections, costs, known_effects, unknown_effects, effective_card, blocking_errors}`。

缺目标等正常预选情况通过required_selections和blocking_errors描述；未知操作类型等请求格式错误才返回Result失败。费用与有效卡面使用执行时同一解析函数，提交仍重新校验。预览不预测隐藏抽牌或抽取消耗随机结果。

## 4. BattleEngine：规则接口

以下接口由GameSession调用；只读内容与随机源构造能力注入引擎。每次执行从输入随机快照创建工作随机源，成功时与状态共同提交，不共享可被失败命令污染的随机实例。内部执行返回新状态，只有会话层发布后才成为当前状态。

| 方法 | 输入 | 输出 |
|---|---|---|
| begin(input) | BattleInput | Result<BattleStep> |
| preview(state, draft) | BattleState、战斗操作草稿 | Result<ActionPreview> |
| apply(state, action, rng_state) | BattleState、战斗操作、当前战斗随机快照 | Result<BattleStep> |
| make_view(state) | BattleState | BattleView |

`BattleInput`：battle_id、encounter_id、人物定义ID、难度规则ID、入场精力、永久牌实例快照、已装备饰品及战斗随机状态。

`BattleStep`：state、events、pending_choice、outcome、stable、rng_state。stable表示规则队列为空且无效果内选择；若有outcome则战斗已经结束。

`BattleOutcome`：battle_id、result（won/lost/abandoned）、reason、remaining_vitality、summary。正常失败原因含`vitality_depleted`与`deadline_expired`；内部结算异常返回`RESOLUTION_ERROR`，不伪装成玩家失败。

引擎处理效果内选择时保留结算游标与工作状态。规则异常不得提交部分结果，GameSession保留上一稳定快照供恢复和诊断。随机状态与规则状态共同提交或共同回滚。

## 5. RunService：局流程接口

| 方法 | 输入 | 输出与行为 |
|---|---|---|
| create(request, profile) | StartRunRequest、Profile只读数据 | Result<RunStep>，校验解锁并初始化 |
| preview(state, draft) | RunState、局流程草稿 | Result<ActionPreview> |
| apply(state, action, rng_states) | RunState、局流程操作、当前局流程随机快照 | Result<RunStep> |
| settle_battle(state, outcome, rng_states) | RunState、BattleOutcome、当前局流程随机快照 | Result<RunStep>，匹配当前battle_id并仅结算一次 |
| make_view(state) | RunState | RunView及当前节点视图 |

`RunStep = {state, events, battle_input, run_summary, rng_states}`；无须开战或结局时对应字段为null。

create从request.seed初始化随机流；其余写调用由GameSession显式传入当前快照。RunService只推进map/reward/event流，BattleEngine只推进battle流；所有返回快照统一合并进SessionState。preview不接收可变随机源。

交易使用工作副本：校验所有目标、支付条件和槽位→整体应用→返回新状态。校验失败保留原状态。内容抽取错误返回`CONTENT_INVALID`，不扣钱后再报告无法发放。

战斗结算、创建奖励和写回精力是同一次会话提交；奖励选择是后续独立命令。结局摘要以run_id去重写入Profile，存档失败重试也不得重复记录通关。

## 6. ContentDB与RandomSource

### ContentDB

| 方法 | 参数 | 返回 |
|---|---|---|
| load(manifest_id) | 内容清单ID | Result<ContentInfo>，包含content_version/hash |
| get_definition(kind, id) | 类别、定义ID | Result<只读定义> |
| get_candidates(query) | kind、rarity（可空）、tags、excluded_ids、term（可空） | Array<String>，按ID稳定排序，可为空 |

kind限定为character/card/unit/scene/relic/status/task/encounter/event/ruleset。load校验失败时保留原可用索引，不发布半套内容。get_candidates只过滤，不随机抽取；池为空时由调用者执行既定回退规则。

### RandomSource

| 方法 | 参数 | 返回/副作用 |
|---|---|---|
| draw_int(stream, min_value, max_value) | 流名称和闭区间 | Result<int>，成功推进该流 |
| shuffle(stream, ids) | 流名称、ID数组 | Result<Array<String>>，返回新数组并推进该流 |
| export_state() | 无 | RandomSnapshot副本 |
| restore_state(snapshot) | RandomSnapshot | Result，校验成功后整体恢复 |

stream限定map/reward/event/battle；min大于max返回`INVALID_ARGUMENT`且不推进。RandomSnapshot包含算法版本和各流seed/state；JSON中64位整数用十进制字符串存储。restore不兼容算法版本返回`VERSION_MISMATCH`。

## 7. SaveStore：文件存储接口

| 方法 | 输入 | 返回 |
|---|---|---|
| inspect(slot) | current_run/profile/settings | Result<SaveMetadata>，不存在返回`SAVE_NOT_FOUND` |
| save(slot, snapshot) | 槽位、对应快照 | Result<SaveReceipt> |
| load(slot) | 槽位 | Result<SaveSnapshot>，读取并校验正式档 |
| load_backup(slot) | 槽位 | Result<SaveSnapshot>，显式读取有效备份 |

SaveSnapshot外层：schema_version、content_version、content_hash、manifest_id、run_id（可空）、revision（可空）、payload、random_state（可空）、checksum。Profile/settings可不含局相关值。当前局payload包含run、battle（可空）和pending_profile_summary（可空）；revision和random_state只在外层保存，恢复时重建SessionState。

SaveReceipt：slot、saved_at、revision（可空）、checksum。SaveMetadata额外包含schema_version、content_version和valid标记。

SaveStore负责结构、校验和与文件完整性；GameSession结合ContentDB检查内容兼容和状态引用。正式档失败时，会话层可调用load_backup并向玩家说明恢复来源。保存先写临时文件、验证、保留旧备份，再替换；失败保留至少一份有效旧档。

结局跨文件保存：先保存current_run中的pending_profile_summary，再按run_id幂等合并并保存Profile，最后清除pending并保存current_run。未完成时恢复后重试该流程，不能覆盖旧局；保存失败不重新执行结局收益。

## 8. 规则事件与UI通知

`RuleEvent = {index, type, source_id, target_ids, data}`。index是本次结果内从0递增的序号；source_id可空。常见type：card_played、focus_changed、work_completed、pressure_applied、status_changed、unit_entered、unit_left、scene_changed、phase_changed、battle_finished、reward_claimed。

事件只描述已经发生的变化，data包含动画所需前后数值；不能通过动画结束回调再次施加效果。

GameSession可暴露三个Godot信号：`view_changed(view)`、`events_emitted(revision, events)`、`save_failed(error)`。返回值用于操作反馈，UI只选一条事件消费通道，避免既消费返回events又监听信号造成重复动画。

## 9. 错误码

| code | 含义 | 调用方处理 |
|---|---|---|
| INVALID_ARGUMENT | 格式、枚举或数量非法 | 修正请求 |
| RUN_ACTIVE / RUN_NOT_FOUND | 局状态不符合操作要求 | 返回对应页面 |
| STALE_STATE | 视图版本过期 | 刷新视图，不自动重发写操作 |
| WRONG_PHASE | 当前阶段不允许 | 更新按钮状态 |
| INVALID_TARGET | 实例不存在或目标类型不符 | 重新选择 |
| INSUFFICIENT_RESOURCE | 钱、专注、精力或状态资源不足 | 显示缺少项 |
| LIMIT_REACHED | 本回合/本战限次、容量或删牌下限 | 显示限制 |
| CHOICE_PENDING | 必须先完成效果内选择 | 聚焦选择界面 |
| ALREADY_RESOLVED | 节点、奖励、库存或战斗已结算 | 刷新，不重复执行 |
| CONTENT_INVALID | 定义或引用不合法 | 阻止进入，报告具体ID |
| SAVE_NOT_FOUND / SAVE_CORRUPT | 无存档或内容损坏 | 新局或恢复备份 |
| VERSION_MISMATCH | 格式、内容或随机算法不兼容 | 保护原档并提示 |
| SAVE_IO_ERROR | 写入或读取失败 | 保存可重试，不重做游戏操作 |
| RESOLUTION_ERROR | 内部规则异常 | 保留稳定状态和诊断信息 |

## 10. 调用示例与验收

### 打出K01对应的手牌实例

```json
{
  "context": {"run_id": "run_001", "expected_revision": 12},
  "action": {
    "type": "play_card",
    "payload": {
      "card_instance_id": "card_017",
      "target_ids": ["task_001"],
      "replace_unit_id": null
    }
  }
}
```

合法提交后revision变为13；重复发送上述revision=12请求返回STALE_STATE，费用只扣一次。若这次操作需要后续选择，UI读取pending_choice，再用新revision提交confirm_choice；期间save_current返回CHOICE_PENDING。

### 商店购买饰品

先preview_action获取实际成本和所需替换对象→玩家确认→submit buy_item。取消预选不调用submit；提交成功但保存失败，只调用save_current重试。库存已售再次购买返回ALREADY_RESOLVED。

### 接口验收要点

1. 查询、预览与取消不改revision或随机状态。
2. 旧revision、非法目标、资源不足均无副作用。
3. 备考/回忆卡面在预览与执行中完全一致。
4. 效果内选择不能被其他写操作绕过。
5. 战斗结算、奖励领取和Profile摘要不会重复应用。
6. 存档错误与规则错误分开，读档恢复触发次数与随机结果。
