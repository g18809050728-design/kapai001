# 内容层契约（data/）

> 模块：内容数据（`data/definitions/**`、`data/manifests/**`）+ 内容验收套件
> （`tests/suites/test_content_*.gd`）。规则层（src/battle、src/storage、src/run）
> 与 ContentDB 实现（src/content）不在本模块写权内。

## 1. 文件布局与职责

| 路径 | 作用 |
|---|---|
| `data/definitions/cards.json` | 卡牌定义（含 `upgrade`） |
| `data/definitions/tasks.json` | 任务与首领阶段（`phases[].intents[]`） |
| `data/definitions/encounters.json` | 遭遇（`kind` 必须等于地图节点类型 normal/elite/boss） |
| `data/definitions/characters.json` | 人物（`starter_cards` 2 张 + `starter_relic_id` + `passive`） |
| `data/definitions/relics.json` | 饰品（`availability=starter` 不进掉落池） |
| `data/definitions/units.json` / `scenes.json` | 单位 / 场景 |
| `data/definitions/events.json` | 随机事件（schema 见 §5；**需要 ContentDB 把 event 映射进 KIND_FILES 才会被加载**） |
| `data/manifests/mvp.json` | 首个可玩切片的真实清单（《项目计划书》§3.1） |
| `data/manifests/test_minimal.json` | **冻结测试夹具**：run-service 行为断言只准依赖它 |
| `data/manifests/battle_mvp.json` | 战斗引擎夹具（单位/场景/B01） |
| `data/manifests/content_deferred.json` | 缺口账本：已点名但引擎没有对应 op 的条目（机器可读，见 §4） |

清单的语义：**只有 `enabled` 里列出的定义会被发布**。文件里存在但未启用的定义会被
`_build_indexes` 过滤掉，`ContentDB.definition()` 读不到（测试要读未启用定义时直接读 JSON）。
`enabled` 里的每个 id 必须同时在对应 definitions 文件里存在——否则 `_apply_manifest` 直接
失败，**整个内容库加载不进来，所有套件全红**。因此新增内容的落盘顺序是：
**先写 definitions，再把这个 id 加进 manifest**，绝不要反过来。

## 2. 硬约定（违反会让全队白干）

1. 只写引擎已实现的 op。`ContentDB._validate_effect_list` 遇到未登记 op 会判 `CONTENT_INVALID`，
   而它校验的是**文件里的全部定义**（与是否启用无关），所以一张牌写错 op 会让全量测试直接中止。
   当前战斗 op 见 `src/common/game_constants.gd` 的 `OP_*` 与 `ContentDB.KNOWN_OPS`；事件 op 见
   `RunService.EVENT_OPS`。
2. **缺 op 就不写近似效果**。短板记进 `content_deferred.json` 并报队长，由引擎增量任务补齐
   （绝不用「差不多」的 op 代替）。
3. 数值逐条抄《交大四年_DDL战争_统一设计文档.md》，不按手感调平衡。
4. JSON 数字一律是 float：读整数走 `ContentDB.run_int/battle_int/status_int`，测试里用 `int()`。
5. `upgrade` 内的字段是**整体替换**：升级只改文档「升级」栏明确写出的项目，其余字段必须在
   `upgrade.effects` 里原样重复一遍（例：K08 升级只改恢复量，`remove_status` 要重写）。
6. 事件定义必须带一个 `effects: []` 的「离开，无变化」选项；事件引用校验必须**只对启用的
   event 生效**（与其它 kind 一致），否则未落地的引用（如 V03 的 K05、V10 的 A15）会让整个内容库加载失败。

## 4. 缺口账本格式（content_deferred.json）

```json
{
  "card": [{"id": "K05", "name_key": "card.k05.name", "doc": "§5.1",
            "doc_line": "细心写 | 2·工作·白 | 完成14；本回合打过K04则额外完成4，合并为同一段 | 基础18",
            "missing": "缺什么能力", "proposed": {"op": "...", "字段": "..."},
            "trigger": "结算时点", "upgrade": {"effects": []}, "blocking": ["..."]}],
  "character": [], "relic": [], "event": [],
  "manifest_holdback": {"card": ["K05"], "task": [], "encounter": [], "character": [], "relic": [], "event": []},
  "manifest_enable_after_mapping": {"event": ["V01"]}
}
```

`proposed` 就是给引擎增量任务的接口提案；e1/e2 按它实现后，把条目从 `manifest_holdback`
移到对应 manifest 的 `enabled`，同时更新 `test_content_mvp.gd` 的清单断言（这是唯一允许的扩容路径）。
## 5. events.json schema（由 RunService / EventState 的注释定义）

```json
{"id": "V01", "name_key": "event.v01.name", "terms": [1, 8], "once_per_run": true,
 "options": [
   {"option_id": "home", "label_key": "event.v01.home", "cost": {},
    "effects": [{"op": "gain_relic", "rarity": "white", "count": 1, "fallback_money": 20}]},
   {"option_id": "leave", "label_key": "event.common.leave", "cost": {}, "effects": []}
 ]}
```

- `terms` 或 `allowed_terms`（`[lo, hi]` 或 `[n]`）；没有该字段表示不限学期。
- `cost`: `{"money": n, "vitality": n}`；支付后精力必须 ≥ 1（引擎校验）。
- events op（`RunService.EVENT_OPS`）：`gain_money` / `heal` / `lose_vitality` / `gain_card` /
  `gain_relic` / `upgrade_card` / `remove_card` / `career`。
- `gain_card`：`card_id`（单张直发）或 `rarity` + `candidate_count`（进入节点时冻结候选）。
- `gain_relic`：`relic_id` 或 `rarity` + `count`；已持有/池空按 `fallback_money` 折算
  （内容必须显式给出 `fallback_money`，否则 `CONTENT_INVALID`）。
- `career`：`{"track": "research|competition|internship|grad_exam", "amount": n}`。
- MVP 的 V03 需要「显式卡池三选一」（`gain_card.card_pool` + `selection_count`）、
  「删 1 张基础牌」（`remove_card.tag_filter`）、V04 需要「升级 1 张工作牌」
  （`upgrade_card.type_filter`）——这三个字段由引擎增量 e2 实现，提案见 `content_deferred.json`。
  未实现前这些事件不进任何 manifest。

### 两条容易踩的因果

1. **事件组会改变地图行为**：启用后第 2 层的事件节点不再走 `empty_event_pool` 回退成普通战斗，
   所以「地图路线」类回归必须从数据派生期望（t19 已完成），不能把「内容事实」写死成「行为事实」。
   事件 op 的行为套件可用冻结夹具 `data/manifests/test_events.json` 单独跑。
2. **引用必须与引用者在同一份清单里启用**：`_require` 判的是 `is_enabled`，所以 V10 → A15 这种
   引用，缺定义或「有定义但该清单没启用」都会在 `_apply_manifest` 阶段响亮失败（ERR_INVALID_DATA）。

### MVP 范围外仍缺的引擎能力

查重护盾 `plagiarism_shield` 的「屏障吸收」尚未接线：ContentDB 会在加载期以 `CONTENT_INVALID`
+ 缺口说明拒绝引用它的定义（受影响的是 N06「查重护盾8」等学期 3 起的任务）。这条记在
`data/manifests/content_deferred.json` 的 `outside_mvp`，不影响一学期 MVP。

### 账本（content_deferred.json）的读法

- `landed`：曾经阻塞、现已实现并启用的条目，保留卡面原文与当时的缺口描述，供考古；
- `manifest_holdback`：**仍未启用**的条目 + 每类写明原因（当前为空）；
- `manifest_next_segment`：下一段要做的清单变更（当前为空，第②段已完成）；
- `outside_mvp`：不影响 MVP 的已知缺口。

判据（`test_content_mvp.gd` 固化）：每个类别「出厂已启用 ∪ holdback」必须等于《项目计划书》§3.1
的精确清单，holdback 与出厂清单不得有交集。
