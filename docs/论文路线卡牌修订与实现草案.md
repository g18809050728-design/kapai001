# 论文路线卡牌修订与实现草案（W16/W17/W22/W23）

版本：v0.1｜日期：2026-10-24｜状态：设计草案；未接入生产内容、未改规则代码、未运行测试，不构成 G8 验收证据。

## 0. 范围与前提

- 本文只固化 W16、W17、W22、W23 的规则化描述与实现映射；论文路线其余 31 张牌保持上一版设计不变。
- 论文路线的公共规则保持不变：
  - 开题后，首次打出一个牌名：论文进度 +1，上限 10。
  - 重复同名：引用 +1，上限 5；获得第 3/4/5 层引用时额外支付 1/2/3 专注。
  - 完成度 = `进度×7 + 引用×6 + 完成度修正`，最后限制在 0～100。
  - 同一名牌每回合最多打出 1 次。
  - 六张章节牌可进入论文区并重复使用；重复打出只结算基础效果并产生引用。
  - 开题后获得固有的“解题发表”；中间牌不直接造成完成量。
- 本文中的“失去精力”指效果导致的生命值减少，不是压力，不先扣放松，可以降到 0 并触发终局检查。
- 本文中的“完成度修正”不是任务完成量，不直接减少任务未完成量，只在解题发表结算时影响完成度。

## 1. 变更摘要

| 卡牌 | 原效果 | 本次修订 |
|---|---|---|
| W16 赶工 | 抽 2；本回合下一张牌费用 +1 | 抽 2；失去 2 精力 |
| W17 通宵 | 获得 2 专注；本回合下一张牌费用 +1 | 获得 2 专注；失去 3 精力 |
| W22 换题 | 将一个已用牌名改为未用；抽 1；耗尽 | 保留重置；成功重置时完成度修正 -1；抽 1；耗尽 |
| W23 文献综述 | 抽 2；本战下一次同名也计为新名字；耗尽 | 抽 2；获得 1 层“增幅”；耗尽 |

实现解释：

- W16/W17 的加费负面效果被“失去精力”替换，卡面不再改变后续卡牌费用。
- W22 按“换题的代价改为完成度 -1”处理：重置效果保留，完成度修正只在成功重置时发生；无已用牌名时只抽 1。若最终决定完全删除重置，只需移除 `paper_swap_topic` 中的重置步骤。
- W23 不再让同名计为新名字；改为强化下一张牌的非完成度正向数值效果。

## 2. 规则化卡牌描述

### 2.1 W16 赶工

| 字段 | 值 |
|---|---|
| 编号 | W16 |
| 名称 | 赶工 |
| 费用 | 0 专注 |
| 类型 | 策略 |
| 品质 | 白 |
| 目标 | 自身 |
| 关键词 | 无 |
| 耗尽 | 否 |

打出时序：

1. 支付 0 专注。
2. 抽 2 张牌。
3. 失去 2 精力。
4. 若本战论文已开始，按牌名记录论文进度/引用。

升级：抽 3 张牌；失去 2 精力不变。

边界：

- 失去精力绕过放松，不属于压力；不能由护卫改向。
- 精力降到 0 时按现有规则检查失败；不能治疗已经失败的主角。
- 本牌不再增加下一张牌费用；可以与加费牌同时存在，但两者无关。
- 同一牌名每回合最多打出 1 次。

### 2.2 W17 通宵

| 字段 | 值 |
|---|---|
| 编号 | W17 |
| 名称 | 通宵 |
| 费用 | 0 专注 |
| 类型 | 策略 |
| 品质 | 蓝 |
| 目标 | 自身 |
| 关键词 | 无 |
| 耗尽 | 否 |

打出时序：

1. 支付 0 专注。
2. 获得 2 专注，受当前专注上限限制。
3. 失去 3 精力。
4. 若本战论文已开始，按牌名记录论文进度/引用。

升级：获得 3 专注；失去 3 精力不变。

边界：

- 失去精力绕过放松，不是压力；可以降到 0 并触发终局检查。
- 专注上限仍为规则书规定的上限；超出的专注不保留。
- 本牌不再增加下一张牌费用。
- 同一牌名每回合最多打出 1 次。

### 2.3 W22 换题

| 字段 | 值 |
|---|---|
| 编号 | W22 |
| 名称 | 换题 |
| 费用 | 1 专注 |
| 类型 | 策略 |
| 品质 | 紫 |
| 目标 | 自身 |
| 关键词 | 完成度修正 |
| 耗尽 | 是 |

打出时序：

1. 若论文中已有“已用牌名”，选择其中一个，将其改为未用；随后完成度修正 -1。
2. 若没有已用牌名，跳过重置和完成度修正，只执行抽牌。
3. 抽 1 张牌。
4. 若本战论文已开始，按本牌牌名记录论文进度/引用。

升级：费用 0；其他不变。

边界：

- 重置只影响该牌名今后能否再次提供论文进度；不返还已获得的引用，也不清除文献管理、实验记录等来源的已用记录。
- 完成度修正持续到本篇论文结算；可以叠加；结算时与进度、引用一起计算，最低为 0。
- 完成度修正不改变论文进度、引用、已用牌名或牌区。
- 无已用牌名时没有完成度修正，只抽 1；这是一次可打出的低价值循环，不产生负面完成度。
- 同一牌名每回合最多打出 1 次；耗尽后本战不能再打出。

### 2.4 W23 文献综述

| 字段 | 值 |
|---|---|
| 编号 | W23 |
| 名称 | 文献综述 |
| 费用 | 1 专注 |
| 类型 | 策略 |
| 品质 | 紫 |
| 目标 | 自身 |
| 关键词 | 增幅 |
| 耗尽 | 是 |

打出时序：

1. 支付 1 专注。
2. 抽 2 张牌。
3. 获得 1 层“增幅”。
4. 若本战论文已开始，按本牌牌名记录论文进度/引用。

升级：费用 0；其他不变。

“增幅”规则：

- 本战下一次由卡牌产生的**正向数值效果** +1。
- 增幅不增强完成度，也不增强完成度修正。
- 增幅可叠加；多层增幅在下一次符合条件的数值效果上合并为 +N，并一次性消耗。
- 一次结算只作用于一个数值效果；同一张牌有多个数值效果时，作用于第一个符合条件的效果。
- 若下一张牌只有完成度、负面数值或没有数值效果，增幅不消耗，继续保留到下一次符合条件的牌。
- 增幅不强化本牌自身的抽 2，因为本牌先抽牌，再获得增幅。
- 允许强化的 op：`draw`、`relax`、`heal`、`gain_focus`、`paper_progress`、`paper_citation`。
- 不强化：`complete`、`paper_settle`、完成度修正、`lose_vitality`、`pressure`、`discard`、加费、状态层数。
- 同一牌名每回合最多打出 1 次；耗尽后本战不能再打出。

| 场景 | 结果 |
|---|---|
| 72 精力打出 W16 | 抽 2；精力 70 |
| 72 精力打出 W17 | 获得 2 专注；精力 69 |
| W23 后打出 W16 | 抽 3；失去 2 精力 |
| W23 后打出 W17 | 获得 3 专注；失去 3 精力 |

| 70 完成度打出 W22 并成功重置 | 完成度修正 -1；本次论文结算按 69 起算 |
| 无已用牌名打出 W22 | 只抽 1；不产生完成度修正 |

## 4. 实现映射

### 4.1 领域状态

在 `BattleState` 增加论文状态。它只在该场战斗内存在，随 BattleState 保存和恢复。

```gdscript
var paper: Dictionary

paper = values.get("paper", {
	"progress": 0,
	"citations": 0,
	"used_names": [],
	"completion_offset": 0,
	"next_effect_bonus": 0,
	"submitted": false,
}).duplicate(true)
```

`to_dictionary()` 必须原样写出 `paper`；`BattleCodec` 增加对应映射。`validate()` 至少检查：

- `progress` 在 0～10。
- `citations` 在 0～5。
- `used_names` 无重复字符串。
- `next_effect_bonus` 不小于 0。
- `submitted` 后不再接受论文牌效果。

完成度使用派生函数，不单独存储：

```gdscript
func paper_completion(state: BattleState) -> int:
	var paper: Dictionary = state.paper
	var raw := (
		int(paper.get("progress", 0)) * 7
		+ int(paper.get("citations", 0)) * 6
		+ int(paper.get("completion_offset", 0))
	)
	return clampi(raw, 0, 100)
```

### 4.3 效果执行草图

以下只示意新增分支；接入时应合并进现有 `_execute_card_effect` 的 `match`，保留原有 `complete`、`draw`、`discard`、`recall_from_discard`、`remove_status`、`summon_unit`、`establish_scene`、`gain_status` 等分支。

```gdscript
const PAPER_AMPLIFY_OPS := [
	"draw",
	"relax",
	"heal",
	"gain_focus",
	"paper_progress",
	"paper_citation",
]


func _execute_card_effect(
	state: BattleState, effect: Dictionary, rng: RandomSource, events: Array[RuleEvent]
) -> GameResult:
	var op := str(effect.get("op", ""))
	var amount := int(effect.get("amount", effect.get("stacks", 0)))
	if op in PAPER_AMPLIFY_OPS:
		amount += _consume_paper_amplify(state, events)
	match op:
		"draw":
			_draw_cards(state, maxi(0, amount), rng, events)
			return GameResult.success(null)
		"relax":
			state.player.relax = int(state.player.get("relax", 0)) + maxi(0, amount)
			return GameResult.success(null)
		"heal":
			var cap := int(state.player.get("max_vitality", 0))
			state.player.vitality = mini(cap, int(state.player.vitality) + maxi(0, amount))
			return GameResult.success(null)
		"gain_focus":
			var ruleset := _loaded_ruleset()
			if not ruleset.ok:
				return ruleset
			var focus_cap := int(ruleset.data.battle.focus_cap)
			state.player.focus = mini(focus_cap, int(state.player.focus) + maxi(0, amount))
			return GameResult.success(null)
		"paper_swap_topic":
			return _start_paper_swap_choice(state, effect, rng, events)
		"paper_amplify_next":
			state.paper.next_effect_bonus = int(state.paper.get("next_effect_bonus", 0)) + maxi(0, amount)
			_add_event(events, "paper_amplified", "", [], {"stacks": state.paper.next_effect_bonus})
			return GameResult.success(null)
		"paper_progress":
			_gain_paper_progress(state, amount, events)
			return GameResult.success(null)
		"paper_citation":
			for index in maxi(0, amount):
				_gain_paper_citation(state, rng, events)
			return GameResult.success(null)
		"paper_settle":
			return _settle_paper(state, events)
		_:
			return GameResult.fail(
				GameConstants.ERROR_ENGINE_NOT_READY,
				"battle.effect.not_ready",
				{"op": op}
			)
```

`_consume_paper_amplify` 只在白名单 op 上调用，因此完成度、完成度修正、失去精力、压力、弃牌、加费都不会被增幅：

```gdscript
func _consume_paper_amplify(state: BattleState, events: Array[RuleEvent]) -> int:
	var bonus := int(state.paper.get("next_effect_bonus", 0))
	if bonus <= 0:
		return 0
	state.paper.next_effect_bonus = 0
	_add_event(events, "paper_amplified", "", [], {"consumed": bonus})
	return bonus
```

### 4.4 论文牌名记账

卡牌效果队列完成后，再按牌名记账，保证 W23 不会强化自己的抽 2，W22 也不会把自身重置。接入时在 `_play_card` 的效果队列稳定返回后调用 `_record_paper_play`，不要放在效果执行前。

```gdscript
func _gain_paper_progress(state: BattleState, amount: int, events: Array[RuleEvent]) -> void:
	var before := int(state.paper.progress)
	state.paper.progress = clampi(before + maxi(0, amount), 0, 10)
	if int(state.paper.progress) != before:
		_add_event(events, "paper_progress_changed", "", [], {
			"before": before,
			"after": state.paper.progress,
		})


func _record_paper_play(
	state: BattleState, card_id: String, rng: RandomSource, events: Array[RuleEvent]
) -> void:
	var card: Dictionary = state.card_by_id[card_id]
	var definition_id := str(card.get("definition_id", ""))
	var definition_result := _catalog.get_definition("card", definition_id)
	if not definition_result.ok:
		return
	var tags: Array = definition_result.data.get("tags", [])
	if "paper_finisher" in tags or "paper_start" in tags:
		return
	var used: Array = state.paper.used_names
	if definition_id in used:
		_gain_paper_citation(state, rng, events)
		return
	used.append(definition_id)
	if int(state.paper.progress) < 10:
		state.paper.progress = int(state.paper.progress) + 1
		_add_event(events, "paper_progress_changed", card_id, [], {
			"progress": state.paper.progress,
			"name": definition_id,
		})
```

引用获取使用数量曲线；付不起额外专注时改为抽 1：

```gdscript
func _gain_paper_citation(
	state: BattleState, rng: RandomSource, events: Array[RuleEvent]
) -> void:
	var current := int(state.paper.citations)
	if current >= 5:
		return
	var next := current + 1
	var extra := 0
	if next == 3:
		extra = 1
	elif next == 4:
		extra = 2
	elif next == 5:
		extra = 3
	if int(state.player.focus) < extra:
		_draw_cards(state, 1, rng, events)
		return
	state.player.focus -= extra
	state.paper.citations = next
	_add_event(events, "paper_citation_changed", "", [], {
		"citations": next,
		"focus_paid": extra,
	})
```

### 4.5 W22 的选择与结算

`paper_swap_topic` 需要一个新的待选 kind。没有已用牌名时不进入待选，直接抽牌。

```gdscript
func _start_paper_swap_choice(
	state: BattleState, effect: Dictionary, rng: RandomSource, events: Array[RuleEvent]
) -> GameResult:
	var used: Array = state.paper.get("used_names", [])
	if used.is_empty():
		_draw_cards(state, int(effect.get("draw", 1)), rng, events)
		return GameResult.success(null)
	var candidates: Array = []
	for name in used:
		candidates.append({"id": str(name), "label_key": "paper.name.%s" % str(name)})
	return GameResult.success({
		"choice_id": _new_instance_id(state, "ch"),
		"kind": "paper_name",
		"prompt_key": "choice.paper.swap_topic",
		"candidates": candidates,
		"min_count": 1,
		"max_count": 1,
		"source_card_id": str(state.resolution.get("card_instance_id", "")),
		"effect_amount": int(effect.get("draw", 1)),
		"paper_completion_offset": int(effect.get("completion_offset", -1)),
	})
```

确认待选时，从 `used_names` 移除所选名字，应用完成度修正并抽牌。待选失败不改变状态；`paper_swap_topic` 的待选与其他待选一样，未完成前不能保存为稳定档。

```gdscript
func _confirm_paper_swap(
	state: BattleState, selected_id: String, rng: RandomSource, events: Array[RuleEvent]
) -> void:
	state.paper.used_names.erase(selected_id)
	state.paper.completion_offset = int(state.paper.get("completion_offset", 0)) - 1
	_add_event(events, "paper_name_reset", "", [], {
		"name": selected_id,
		"completion_offset": state.paper.completion_offset,
	})
	_draw_cards(state, 1, rng, events)
```

### 4.6 解题发表结算草图

```gdscript
func _settle_paper(state: BattleState, events: Array[RuleEvent]) -> GameResult:
	var completion := paper_completion(state)
	var main_amount := completion + 10
	var other_amount := completion / 2
	if completion == 100:
		main_amount += 20
		other_amount += 20
	var main_target := str(state.resolution.get("main_target_id", ""))
	for task in state.tasks:
		var amount := main_amount if str(task.task_id) == main_target else other_amount
		_apply_paper_completion_to_task(state, task, amount, events)
	state.paper = {
		"progress": 0,
		"citations": 0,
		"used_names": [],
		"completion_offset": 0,
		"next_effect_bonus": 0,
		"submitted": true,
	}
	return GameResult.success(null)
```

`_apply_paper_completion_to_task` 应复用现有的屏障、阶段、离场和终局检查逻辑，不在论文模块另写一套伤害规则。

### 4.9 存档与恢复

- `paper` 必须进入 BattleCodec；`used_names` 的顺序不影响语义，但保存顺序应稳定。
- W22 的 `paper_name` 待选属于效果内待选，未完成前不能写稳定档。
