# 战斗模块契约

版本：v2.0｜日期：2026-10-29｜状态：新版行为目标；引擎与测试仍为v1。

## 1. 入口与职责

BattleEngine承接begin、preview、apply、make_view、resolve_face、calculate_cost这类现有职责；精确v1签名/DTO可从Git 历史恢复。新版资源/选择字段与返回schema待G0，不能把本契约视为现有接口已经支持。

输入须绑定人物、内容版本/hash、永久牌来源、遭遇、精力与完整四流随机快照。begin验证全部有效引用与人物资格，再创建战斗副本；只推进battle流，其他流原样返回。preview/视图/费用查询不改状态和随机。输出需共同返回状态、事件、唯一待选、终局、稳定标记与随机快照。

## 2. 相位与稳定边界

```text
准备 → 基础抽牌 → 玩家行动 → 合作行动 → 弃牌
 → 任务准备 → 全部非压力技能 → 全部压力 → 完整轮末
 → DDL检查 → 下轮准备
```

每条命令在已发布状态/RNG深副本执行，成功整体发布；异常或失败不改变输入。待选时发布内存工作区，只接受匹配确认，确认失败保留最近工作区；队列完成才稳定并允许保存。revision只由GameSession管理。动画不能推进相位或队列。

## 3. 人物资源与被动

| 人物 | 被动与上限 |
|---|---|
| P01 | 第3工作牌结算后+1编译，每回合1次；编译上限5 |
| P02 | 首次主动弃牌事件结算后+1数据；数据上限6 |
| P03 | 首次实际消耗引用后+3放松；引用6、稿件24 |
| P04 | 首合作牌结算后+1协同、2放松，考试面也触发；协同上限6 |

资源初始0、战后清零，先加后裁切。主动弃牌仅卡面选择弃手牌，一次多张为1事件；轮末/满手/耗尽不算。实际消费正数才触发；必须消费不足拒绝，可选消费允许0，清空x在支付瞬间固定。精确事件窗口遵守角色设计R2-RES/TRG；付款事件与主效果的队列映射须G0冻结。

## 4. 有效卡面与结算

先应用升级和考试标签，得到唯一有效面，再校验目标、换班、资源选值、费用和限次；预览与执行使用同一解析结果。选择取消/失败不支付。费用与状态/RNG共同提交，抽后选择不能撤销已揭示信息。

正文按顺序执行，每个不可拆分效果后检查归零、暂离与强制阶段。旧阶段目标失效则跳过后续锁定段，其他合法效果继续。人物被动先于同事件能力，能力按打出顺序；不递归制造同类主动弃牌/出牌事件。新能力从下回合生效，同名第二份不可打，实例限次不因回收/换区刷新。

P02四种重复牌记录各自战斗实例成功打出次数，第2次起固定增强，跨阶段与回收不清零；正在结算的牌计入次数，拒绝命令不计次。有限回收按卡面过滤类型/费用/永久资格，草稿只接受明确针对R2-T31的回收。临时保留的到期及召入精力负修正遵守角色设计R2-LIM-04和§6.3，保存/恢复不得丢失。

完成先扣屏障，压力先扣放松；主动精力支付后至少1，直接失去精力可能失败。主角同时归零优先失败；最后任务胜利后停止无关续航/压力/DDL。阶段不重置回合、人物资源、能力、牌区、单位、场景或DDL，超额完成不结转。

## 5. 唯一草稿、伙伴与场景

P03首次基础抽5之后生成唯一R2-T31，满手入弃牌；2费、保留、清稿件m完成8+m，正常弃牌可循环。不允许升级/复制/变化/耗尽/删除，任何通用候选也须排除；战后销毁。稿件是人物资源，卡片暂时不在手中不会丢失稿件。

最多3伙伴，满槽预选换班。合作阶段开始快照，入场序行动，支援→协作最早未完成任务→自身失去1精力；归零暂离，无牺牲收益。护卫只承接默认单体压力，多段重检，不溢出。v2不增加手动协作目标命令。

R2-S01后续两次准备各3放松，升级5，第二次移除；替换重计2。场景与能力同窗口完整优先序待新版G0，不照搬旧随机场景规则。

## 6. 考试、视图与错误

独立作答转换七合作+轮换排班及轮值支援，固定考场转换公共场景，共10个逐牌双面；保留主类型与费用，使用完整升级考试文本，不执行普通面或单位/场景待选。P04被动和识别合作类型的能力继续识别原类型。

BattleView公开资源/上限、限次、当前费用与禁用原因、有效面、草稿位置、单位精力、场景计次、阶段进度、意图及公开牌区；隐藏牌序不公开。新事件字段待冻结。未知op或未支持机制明确报错，不吞掉效果、不发布部分状态。
