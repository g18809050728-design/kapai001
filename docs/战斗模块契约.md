# 战斗模块契约

版本：v3.1｜日期：2026-10-30｜状态：目标行为；引擎和测试仍v1，未来用例未执行。

## 1. 入口与事务

BattleEngine承接begin、preview、apply、make_view、resolve_face、calculate_cost这类职责；精确新签名/DTO待G0，本文不是现有可调用API。输入绑定人物、内容版本/hash、永久来源、遭遇、精力和完整四流快照；begin先验证有效引用及人物资格，只推进battle流。预览/费用/视图不改状态与RNG。

每条命令在已发布状态/RNG副本执行，成功一次发布；拒绝或异常不改输入。效果内待选只发布内存工作区与唯一pending_choice，接受当前choice_id确认；失败保留最近工作区，续算完成才稳定可保存。revision归GameSession管理，动画不推进规则。

## 2. 时间顺序

```text
准备：清旧放松/重置回合 → 自然专注/焦虑 → 首次开战效果
 → 已生效章节按槽运行 → 能力/场景共同创建顺序 → 基础抽牌/拖延 → 抽后效果
玩家：出牌或手动使用章节（正文/被动/能力后结算原诱发快照）
 → 行动结束清诱发/检索连锁 → 正常合作 → 弃牌
任务：清旧屏障 → 侵蚀自然结算 → 其他准备触发
 → 全部非压力技能 → 全部压力（固定加值→乏力→虚弱）及脆化/虚弱/易伤窗口到期
轮末：强制效果 → DDL检查 → 公开下轮意图 → 下轮准备
```

P02开题固有占首次基础抽5的一格，发表只在开题后生成。新部署能力、场景、章节下回合起效。任务阶段新生成任务本轮不行动；玩家阶段产生新阶段可参加随后任务阶段。每个不可拆分效果后检查归零、阶段与终局，主角归零失败优先。旧目标失效跳过对应剩余段，完成量不溢出到新阶段。

## 3. 被动与出牌结算

| 人物 | 快照、触发与限次 |
|---|---|
| 林序·步骤复用 | 工作开始前读取前一实际出牌类型；相邻策略→工作结算后可取回前一合法永久策略，每回合一次。无合法前策略不耗机会；满足条件后放弃或满手仍消耗。回收不减费、不刷新限次 |
| 许知微·论文记录 | 已开题时正文前固定新/旧名字，正文后首次名进度+1/重复名引用+1；进度10、引用5，同名每回合最多实际打一次 |
| 沈见章·复合反应 | 正文逐项施加前已有另一种负面，且从0实际建立一种新负面才候选；正文后按任务生成序/效果序选仍合法的新状态+1，成功才耗本回合一次，不递归；自动/检索连锁不发动 |
| 唐以宁·分工默契 | 首合作正文后得1协同2放松，协同上限6；不能倒付正文先前消费，考试保留合作类型 |

先解析升级/考试面，收齐付款前目标、选值、换班/换章，校验限次/费用，整体支付后记录实际出牌；正文→必要阶段→人物被动→同事件能力→出牌开始时已有诱发的原目标快照→正常归区。能力按入场序、下回合起效、同名不叠。抽后选择不能取消整牌回滚信息。

自动结算不制造实际出牌、牌名记账或连携；被动强化、侵蚀结算与诱发不递归制造正文施加事件。换区/换序不清限次。全体效果使用原目标快照，不补打新阶段。精力主动支付后至少1，直接失精力可失败。胜利后停止无关续航和DDL，发表关闭本篇及撤章仍属同一效果必要收尾。

## 4. 林序与论文

林序工作首段准备加值合并上限12，群体只给选定主目标；本回合下一基础费用≥2工作减费合计上限1，未用轮末清。重用增强按同战斗实例成功使用次数，第2次起固定增强；正在结算计入次数，拒绝不计，回收不清。0费衔接保留各自限次/耗尽。

论文公式、分层支付、增幅、换题、唯一发表全部按[角色设计§4](角色与专属卡池重设计_v3.md)。引用第3/4/5层付1/2/3专注，主体后余额不足则不加层改抽1，多层遇首次不足停止。完成度C=clamp(7进度+6引用+修正,0,100)，发表主C+10、其他floor(C/2)，满100全体再+20。

发表关闭本篇、清记录及增幅、章节全部退弃牌。之后须重新合法开题并取回同一个R3-T201，不能复制发表。回合同名集合不因发表/重开清空。换题不退已有进度/引用、不重置回合同名限次。增幅只强化正文首个白名单正向数值，不增强自动/被动、完成量或修正。

最多3个有序章节槽；满槽预选替换旧章退弃牌，同名不可叠。下回合按槽序自动运行；基础效果与常驻分开，手动付费仅基础+记账。额外章节窗口单独记此前运行章数，每实例每回合最多一次额外激活；撤回、重部署或换序不刷新，重部署仍下回合生效。章节可直接输出，不是单位或场景。

## 5. 负面状态、伙伴、场景与考试

六负面依角色设计§5：侵蚀20自然按当前层输出再减1，加速剖析每目标最多2/3次并逐次减；提前验算额外一次不减。诱发3按出牌开始层数，在正文/被动/同事件能力后结算存活原实例；新施不触发自身，二次追问正文额外按当时层，默认/额外合计每目标每回合最多4次，行动结束清。状态完成量过屏障，不吃易伤或工作加值。

脆化3使新屏障减半；乏力4逐段先减压力至最低0，实例内保持；虚弱3再乘0.75；易伤3只使工作直接完成量乘1.25。脆化/虚弱/易伤各任务压力窗口后减1，无压力也到期，新生本轮不行动任务不扣。六种类数不计任务强化或主角负面，阶段替换全部清除。易伤与虚弱全角色通用。

检索连锁正文后前3/4张实际抽牌逐张群施侵蚀1，生成/取回/满手未抽不计，行动末清；同名本回合不可重复。循证爆发下回合起记录正文或检索连锁合格施毒批次，群施一次算一批，至少一目标实际增层；第3批后群体状态完成4/6，每回合一次，按正文记事件、被动后兑现，不由被动额外层或追踪记录自动施毒递归计数。

最多3伙伴，满槽预选换班不退卡。正常合作阶段快照存活实例，按入场序支援→自动协作最早任务→自身失1精力，归零暂离；卡文额外行动每实例每回合最多一次，也耗续航，不能刷新旧实例记录。短驻场按实例上限恢复。护卫只承接默认单体压力，逐段重检、不溢出，不拦全体或点名。

最多1场景，R3-S01后两次准备放松3/5，R3-S02后两次抽1、升级再放松3；建立不立即触发、替换重计、第二次后移除。能力与场景同窗口按共同创建顺序。

14种完整考试面先转换后校验：7合作+5伙伴依赖策略转独立作答，2场景转固定考场，保留费用/主类型/升级。不执行普通召入/单位/换班/场景选择；论文区、负面和其他能力不被考试禁用。

## 6. 视图、错误与验证

## 8. v1 精英遭遇补充（2026-11-01）

下列条目是 v1 程序的已实现行为，用于承载两份精英草稿，**不是 v3.1/新版冻结语义**；与 §1–§6 冲突时以本记录的"v1 现状"为准，待新版 G0 再统一。

- 开局只实例化 `encounter.initial_members`；其余成员通过意图 `summon_tasks` 入场，召唤发生在压力结算之后，因此当回合不行动，且每个任务实例只召唤一次。
- 意图 `transform_task` 以目标定义首阶段替换自身：保留剩余未完成量并按新上限裁切、清除自身状态、从目标首意图开始；`ddl_bonus` 与之同回合结算时先加 DDL 再转换。
- 意图 `intent_loop: "clamp"` 表示推进到最后一个意图后停留，"仅第一回合"用 `[首段, 循环段]` 表达。
- 压力叠加顺序：意图基础值 → `extra_requirements` → `brainstorm` → 单位数缩放（`pressure_per_unit`，按 `pressure_per_unit_cap` 裁切）→ 按 `pressure_times` 分段重检目标。
- 任务屏障获得同样计入 `confusion` 加成；轮末预置下回合意图的屏障也计入。
- 任务定义 `victory_required: false` 时，该任务存活不阻止胜利；胜负判定为"不存在必需的存活任务"。
- `self_destruct` 在压力结算后移除任务并重新判定结局；`absorb_cooperation` 在首次准备后把合作牌移入消耗堆并按配置换抽牌与专注（专注受上限裁切）。
- 相关测试为 `tests/suites/test_elite_encounters.gd`，2026-11-01 已在本机 Godot 4.7.2 通过；首期名单、试玩数据与未完成项见[精英敌人实现记录](精英敌人实现记录_20261101.md)§6–§7。

## 9. v1 饰品 A25–A48 规则补充（2026-11-03）

仅适用于[根计划 §0.3](../实施计划与验收基线.md#03-2026-11-03-饰品-a25a48-扩充v1-程序待实测)的 v1 扩充，未改变 §1–§6 的 v3.1 目标。战斗入场接收按运行装备槽位升序排列的饰品定义 ID；同一窗口先按槽位、再按定义内 hook 顺序结算。战斗计次保存在 `BattleState.counters`，每回合计次只在新回合重置，每战计次在新战斗建立；预览、拒绝、重绘与存档续玩不重置。来源定义缺失、非法 hook 或效果执行失败必须拒绝写命令并保持已发布状态/RNG/revision。

| 饰品 | 窗口与判定 | 可观察结果 |
|---|---|---|
| A25/A26/A30/A36/A42/A43/A47 | 自然专注结算后、基础抽牌前的 `round_start`；A36/A42/A47 再于基础抽牌后的 `draw` | 指定回合的放松、专注、精力与额外抽牌；专注/精力/手牌按上限裁切 |
| A27–A29/A32–A35/A37/A41/A46 | `card_resolved`，先于 v1 人物被动；考试面保留原主类型 | 按牌型与战/回合次数获得抽牌、放松或专注；A46 五种主类型分别限本战一次 |
| A31/A44 | `cost_quote.require_actual_discount: true`，报价和执行共用同一解析结果 | 折扣最低到零；只有本饰品实际减免至少 1 专注才消耗限次，0 费与被前序折扣抵消的报价均不消耗；未设置该字段的旧 A04/A08 保持原有计次语义 |
| A38 | `before_status_gain`，仅主角将获得困倦且可实际抵消时 | 本战第一次将获得的困倦减 1 层，不产生负层或空触发 |
| A39 | `work_segment`，当前 DDL≤3 且本回合首张工作牌的 `segment_index=0` | 该段直接完成量 +2；其他段、伙伴与状态输出不加值 |
| A40 | `unit_action_completed`，每回合首次单位实际完成协作行动后 | 主角放松 +2；单位在行动前离场不触发，常规行动因本次耗尽离场仍触发；若单位完成最后一个必需任务，即使可选任务仍在，事件顺序也是 `task_completed` → `relic_triggered`/收益 → `battle_won`，终局即时停止后续单位精力消耗 |
| A45/A48 | `stage_entered`，任务完成并建立下一阶段后，每战一次 | A45 抽 2、放松 +3；A48 专注 +2、抽 2；直接战斗胜利不触发 |

同窗多件折扣按槽位逐个分配可实际减免的费用，场景先按现有时序修正报价；结算后收益不能倒付刚打出的牌。A38 抵消发生在状态实际入栈前，A39 的加值进入该段原有完成/屏障计算。A45/A48 先建立新阶段、再发收益，不反向改变旧阶段的胜负判定。以上用例及代码位置须在本轮实现记录中与实测证据逐项对应；旧 G3/G7 记录不构成本轮通过。
