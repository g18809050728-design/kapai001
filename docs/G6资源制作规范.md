# G6 资源制作规范

日期：2026-10-15｜状态：6 张 3840×2160 源图及 46 个素材已完成 AI 视觉核对与选定交接，G7 界面实施中；人工签字未记录。

本规范服务于[需求台账](../动作或者图片描述/需求台账.md)和[VIS-013 战斗图片需求](../动作或者图片描述/VIS-013-战斗画面与图片需求.md)中的本期资源，由[实施计划与验收基线](../实施计划与验收基线.md)规定阶段出口。用户要求针对**按生成次数收费**优化，本规范保留制作、补图与派生处理约定。实际选定图片、来源和版本以 [selection.json](../assets/g6/selection.json) 为准；观察结果见[G6记录](G6资源准备执行记录.md)，布局与交互见[G7设计](../动作或者图片描述/G7界面与交互设计.md)。批次、格数、像素和文件名由资源清单登记，本规范不另维护一份批次表。

当前选定素材统一使用实底校园手绘插画。44 张原样复制，K05/K06 通过记录过的 8 像素居中内裁消除顶边残线；F03/F04/A05 等少量边缘问题保留记录。全部为 RGB、不透明图片，G7 采用完整插画卡展示。外部平台、模型和计费次数未知，不能将收到六张源图等同于只发生六次付费。

## 1. 生成方式与成本

优先生成**可自动裁切的网格插画**：把同一画风、相近尺寸的资源排在一张大图中，每格只放一个明确主体。人物、物品、卡图、背景分批，避免一张图中同时要求不同画风和不同分辨率。

| 方式 | 适用情况 | 代价与选择 |
|---|---|---|
| 一次生成一项 | 首轮建立人物参考、重要背景、无法稳定合图的复杂主体 | 单项可控；调用数高，作为必要时的补救 |
| 同类资源规则网格 | 卡牌插画、饰品、单位肖像、同构场景 | **默认方式**；整张成本低，必须保证每格像素与主体独立 |
| 一张整界面或自由拼贴 | 风格参考或讨论材料 | 不作为生产资源源图；难以稳定拆分、替换和适应实时数据 |

每次生成前先确认工具的**实际输出尺寸、是否支持参考图、是否每张计次**。设置里写了 4K 不等于下载文件就是 4K；以下载文件像素为准。不使用多个输出变体的参数来假设只计一次费用。

`预计调用数 = 各批 ceil(资源数 / 每次可用格数) 之和 + 风格样图调用数 + 实际返工数`。

不承诺固定费用或一次全部合格。以每次产出的**合格可用格数**衡量效率；首轮样图合格的格子可转为正式候选，避免仅为展示再花一次。局部失败时只重排失败主体与尚缺资源，不连带重生已经通过的全部格子。

## 2. 文件和命名

原始合图、独立裁片和游戏选定资源分开保存，避免误用未审核图片。建议目录：

```text
原始合图目录/                    下载原图；保留原始文件，不覆盖
独立裁片目录/                    自动裁切的候选 PNG
视觉核对目录/                    核对记录和对比图；注明AI或人工核对
游戏选定资源目录/                经过核对并选定的游戏资源
许可目录/                        字体、图标等外部资源的许可与来源
```

实际目录以资源清单及切图命令的输出目录为准。出现目录或清单行不等于图片已经存在。

- 原图：`<batch_id>_v1.png`，例如 `G6-01_v1.png`；返工递增源图版本，不覆盖旧图。
- 裁片：使用清单 `output_name`，例如 `portraits/P01_v1.png`，每批每次导出放在独立候选目录（如 `candidates/G6-01_v2/`）。候选目录版本标识本次导出；文件名中的 v1 是当前资源定义版本，不自动等同于源图版本。
- 选定文件：首次可保留 `<asset_id>_v1.png`；替换正式资源时递增版本，在 `selection.json` 记录最终文件、候选目录、源图和裁切记录。目录与示例见[制作包入口](../assets/g6/README.md)。
- 内容 ID（如 `P01`）与资源 ID 分开登记。一个资源可映射多个内容或多个 VIS 需求；一个内容也可以使用头像、立绘等不同资源。
- 牌名、费用、说明、数值、稀有度、升级标记和状态文案均由 G7 的 Godot 控件排版，不能烘焙进插画。卡图升级版默认复用原插画，仅由界面标识升级。

## 3. 画风参考与首轮核对

首轮制作方向为**校园生活二维手绘插画、深青墨线、柔和水粉铺色与轻微纸张颗粒；米白、深青、鼠尾草绿为主，少量暖黄与砖红点缀**，当前选定图片已按这一方向完成 AI 视觉核对。纸纹只做轻微质感，不能降低小图可辨识性；人物和物件保持干净实底。新补图不生成学校真实徽标、可识别个人或现成作品角色，不新增人物性别、外貌或剧情设定；具体人物依据内容清单已有设定填写，缺失项记录为待确认。

统一参考分两部分：

1. 一小组通过核对的插画决定线条、色彩、材质和光照；后续批次附同一组参考，提示词保留同一风格前缀。
2. 每个重复出现的人物使用相同角色描述和选定人物参考；卡图与场景中再次出现时继续引用。种子或文字相同不能保证人物一致，需要实际对照。

首轮使用制作包中的人物批和第一批卡图，生产候选同时承担画风试样，不额外生成风格海报。先核对人物和至少三种不同主体的卡图，再推进剩余批次；物件和环境在其对应批次补充核对。首轮不为每种 UI 状态生成一张图。

## 4. 网格规格与像素预算

坐标原点位于左上角，按行优先编号：`r1c1`、`r1c2`，再到下一行。网格内不出现编号、文字、边框、阴影跨格或连接装饰；编号只写在外部清单。模型可能无法准确遵守网格，裁切前要人工观察实际边界。

实际像素使用资源清单每个批次的 `variants.standard` / `variants.high`，同一批次两档共用格位。先计算 `单格宽 = 原图宽 / 列数`、`单格高 = 原图高 / 行数`，再扣除内边距与比例裁切的损失。不要先塞满再用放大来补像素。

2K 标准档适合先核图、制作小尺寸卡面和图标。相同网格在高分辨率档中有更多单格像素，但仍须确认下载文件的实际尺寸；同样的高分辨率不能弥补主体生成错误。以方图为计算示例：2048 图排 4 × 4 时单格只有 512，而 4096 图同排法为 1024，内缩和改变长宽比后还会变小。该示例不是要求某批使用此格数。

人物需要完整的半身构图和较细边缘，场景需要兼顾宽画幅与可阅读区域，优先减少这两类的每图格数。物件图可以较密，但以缩小后能分辨为准。模型无法稳定完成密集网格时，下一次减少格数或把失败主体与缺失项重新合批。不能整除时采用切图工具明确记录的取整边界，不使用人工估计坐标。

不另设未经实际窗口验证的硬像素门槛；先按清单目标尺寸制作，再在 G7 实际展示大小下核对。资源只在小尺寸使用时可降低制作尺寸并登记原因，不把插值放大当成达到原始细节要求。

## 5. 留白、主体与裁切

合图的第一目标是每格能独立使用。格与格之间不要绘制明显分割线，使用同色干净背景，通过主体内缩形成缓冲。

- 主体必须完整位于提示词指定的中央最终裁切框内，并在框内留少量空间；仅满足 `crop.inset_ratio` 不够，非方格裁成方图还会丢失左右边缘。人物为半身像，头顶、手部、腰部均完整；物品的链条、绳带与投影不得伸入相邻格。格位示意图的虚线表示中央裁切区，仅作定位，不应出现在生成图片中。
- 卡图重点放在中心约 70% 范围；角落不放唯一识别信息。不要在插画内预留写着费用或牌名的空标签，后续卡框来自控件。
- 背景允许延伸到格边，但主要物件仍内缩；明确指定 UI 信息区低细节、低对比，不画文字框或按钮。具体控件落点在 G7 确定。
- 人物与物品尽量使用单色平底、无大范围投影；是否需要透明版在选定后决定。RGB 平底不等于透明 PNG；不对复杂头发、白色衣物或近似底色的主体承诺自动抠图无损。
- 若必须抠图，先保留原始实色底版本，再制作透明副本；在深色和浅色底上查看边缘，拒绝白边、孔洞和被误删部分。
- 自动裁切按登记的矩形截取，不偷偷拉伸、不跨格借图、不自动把不同主体拼到一起。需要再裁、缩放、去底或补绘时记录派生步骤和来源。

优先以独立 PNG 交付。G7 可以使用 `AtlasTexture` 或 Godot 的纹理导入设置，但不要求游戏直接使用整张 AI 合图，避免相邻格采样串色和整张显存常驻。

## 6. 复用与非生成资源

| 对象 | 本期处理 |
|---|---|
| 普通/升级卡图 | 同一基础内容复用一张插画；变化由控件和文字呈现 |
| task / encounter | 相同任务主题优先共用插画；encounter 是编组/阶段标识，不因此另生一张敌人图。确有独立场景或首领识别需求时才新增，并在清单写明 |
| 奖励、商店、牌组、待选列表的同一物品 | 复用同一资源 ID，避免为每个页面生成重复图 |
| 任务阶段、节点可达/完成/禁用、存档成功/失败 | 优先用形状、描边、图标和文字组合；不生成为整张状态图片 |
| 菜单、摘要、奖励页的校园氛围 | 使用已核对背景的不同裁切或控件覆盖；仅确有识别需要时新增背景 |
| 按钮、卡框、弹窗、进度条、连接线、简单高亮与粒子 | G7 使用 Godot 控件/绘制，避免占用生图次数 |
| 设置、返回、存档等通用图标 | 选择同一许可明确的 SVG 图标集；项目中登记来源、许可和版本后使用 |
| 中文字体 | 优先一种许可明确、覆盖简体中文的字体；保留字体文件与许可，不从截图抠字 |
| 完整版本中间学期结算、毕业选择 | VIS-010/VIS-011 在本期 MVP 不适用；不为了占满网格提前制作 |

候选来源：

| 资源 | 官方来源与许可入口 | 接入记录 |
|---|---|---|
| 通用 SVG 图标 | [Lucide](https://lucide.dev/)、[官方仓库许可](https://github.com/lucide-icons/lucide/blob/main/LICENSE)，候选许可为 ISC | 保存所用版本、来源及许可；若文件还附带其他声明，一并保留 |
| 中文字体 | [思源黑体官方仓库](https://github.com/adobe-fonts/source-han-sans)、[官方许可](https://github.com/adobe-fonts/source-han-sans/blob/master/LICENSE.txt)，候选许可为 SIL OFL 1.1 | 保存具体字重/版本和许可，打包时保留声明；优先只用必要字重 |

这些外部图标和字体仍是候选，当前 G7 设计使用原生控件、文字及系统中文字体回退，不把系统字体文件复制进仓库。本规范不表示已下载或核对候选文件授权；后续接入时以下载版本随附许可为准。其他网站下载的同名字体或图标不能仅凭名称沿用上述许可判断。

## 7. 每批核对与资源状态

每批仅做能直接减少返工的检查：

1. 文件能打开，实际像素与清单一致，格子数量/顺序正确，主体没有跨格。
2. 每格内容确实对应登记的内容 ID；人物没有换人、物品没有混在一起，卡图一眼能区分主要动作。
3. 独立裁片完整，缩小到目标使用尺寸仍能辨认；在文字区覆盖一块中性面板时仍能读清 UI 内容。
4. 若制作透明版，检查边缘；实底版保持底色与画风一致。记录观察到的文字、水印或品牌问题，不把未观察到表述为绝对不存在。
5. 更新候选状态、采用理由/退回原因、选定版本、源图与裁切坐标；没有实际观察的项保持“待核对”。

建议候选状态为 `planned → generated → cropped → reviewed → selected`；失败可记 `rejected`，本期不适用记 `not_applicable`。状态之间不能仅因脚本执行成功自动跳转：裁切成功并不等于人工核对通过，图片选定也不等于 UI 已实现。

当前 G6 已将 46 个选定素材连接到需求 ID、实际文件、来源及版本，见 [selection.json](../assets/g6/selection.json) 和 [AI 核对报告](../artifacts/g6-review/review.json)。这份规范不替代观察证据；人工签字未记录，最终视觉与来源许可在 G8 发布前补齐。G7 已进入界面实施与验证，实际显示、交互和动画通过状态见[G7执行记录](G7界面执行记录.md)，不能因资源齐全就认定 G7 通过。
