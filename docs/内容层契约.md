# 内容层契约（data/）

> 模块：内容数据（`data/definitions/**`、`data/manifests/**`）+ 内容验收套件
> （`tests/suites/test_content_*.gd`）。规则层（src/battle、src/storage、src/run）
> 与 ContentDB 实现（src/content）不在本模块写权内。
> 2026-10-15：G2 已实现并通过整包验收，生产清单启用全部 66 个冻结 ID，holdback 为 0。证据见 [G2 执行记录](G2内容与基础状态执行记录.md)。具体玩法执行及逐项行为验证属于 G3/G4。

## 1. 文件布局与职责

| 路径 | 作用 |
|---|---|
| `data/definitions/cards.json` | 卡牌定义（含 `upgrade`） |
| `data/definitions/tasks.json` | 任务与首领阶段（`phases[].intents[]`） |
| `data/definitions/encounters.json` | 遭遇（`kind` 必须等于地图节点类型 normal/elite/boss） |
| `data/definitions/characters.json` | 人物（`starter_cards` 2 张 + `starter_relic_id` + `passive`） |
| `data/definitions/relics.json` | 饰品（`availability=starter` 不进掉落池） |
| `data/definitions/units.json` / `scenes.json` | 单位 / 场景 |
| `data/definitions/events.json` | 随机事件（schema 见 §5；G2 加载器必须显式登记 event 类型与文件映射） |
| `data/manifests/<approved-production>.json` | G2 按 G0 批准的名称和内容 ID 清单实现的生产 allowlist；当前没有可核对文件 |
| `data/manifests/test_*.json` | 隔离测试 fixture；具体文件名在 G1/G2 登记，只验证机制，不代表生产内容，也不出现在玩家清单选择器 |
| `data/manifests/content_deferred.json` | 候选范围、实现阻塞和范围外缺口账本；状态须由代码/测试证据更新 |

清单的语义：**只有 `enabled` 里列出的定义会被发布**。文件里存在但未启用的定义会被
`_build_indexes` 过滤掉，公共 `ContentDB.get_definition(kind, id)` 应返回 `CONTENT_INVALID`，不能读到未启用定义（测试要读未启用定义时直接读 JSON）。
`enabled` 里的每个 id 必须同时在对应 definitions 文件里存在；缺失时整次加载必须失败，原有效索引保持不变。新增内容按定义文件、引用闭包、schema/op 校验和清单启用的顺序提交；以加载结果、错误定位和索引前后比较作为验收证据。

## 2. 严格约定

1. 只允许使用已登记 schema/op；加载必须验证生产包的 schema、唯一 ID、引用闭包和启用清单。校验失败时整包不发布，并报告文件、定义 ID、字段和错误码。
2. **缺能力就不写近似效果**。缺口记入 `content_deferred.json`，并阻止依赖该能力的定义进入生产 allowlist。
3. 玩法数值以 G0 核对并冻结的上游基线为准；规则文档、ruleset 与测试样例必须追踪到同一规则 ID。
4. 数值 JSON 类型由 schema 明确规定，禁止依赖引擎隐式转换；整数只接受整数，浮点只用于明确允许的小数配置。
5. 升级固定为显式 patch：只写变化字段；对象按键递归合并，数组整体替换，禁止 null 删除键。合并后验证完整卡面；不接受全量替换模式或隐式别名。精确允许键见 §8。
6. 每个事件必须有可离开的无变化选项；被启用事件的所有效果与引用都必须可执行且在同一生产清单中满足引用闭包。
7. 测试 fixture 与生产 allowlist 必须使用独立 manifest ID 和独立测试入口，fixture 永不暴露给玩家。

## 4. 缺口账本格式（content_deferred.json）

```json
{
  "card": [{"id": "K05", "name_key": "card.k05.name", "doc": "§5.1",
            "doc_line": "细心写 | 2·工作·白 | 完成14；本回合打过K04则额外完成4，合并为同一段 | 基础18",
            "missing": "缺什么能力", "proposed": {"op": "...", "字段": "..."},
            "trigger": "结算时点", "upgrade": {"effects": []}, "blocking": ["..."]}],
  "character": [], "relic": [], "event": [],
  "manifest_holdback": {"card": ["K05"], "task": [], "encounter": [], "character": [], "relic": [], "event": []},
  "manifest_enable_after_mapping": {"event": ["V01"]}
}
```

`proposed`是给引擎增量任务的接口提案；所需能力、规则来源与测试全部确认后，才能把条目从`manifest_holdback`移到获批生产manifest的`enabled`，同时更新生产内容契约套件的清单断言。每次扩容都须保留范围决策和验证证据。
## 5. 事件定义与执行

事件精确 JSON 键唯一见 §8.1/§8.5，行为见[局流程 §8](局流程契约.md)。terms 是显式学期集合，例如 [1,2,3,4,5,6,7,8] 表示所有学期，[1,8] 仅表示第一和第八学期；不接受 allowed_terms 别名或区间简写。每个事件至少一项 cost={}、effects=[] 的无变化离开选项。

主动支付只使用 cost.money/cost.vitality，支付后精力至少1；lose_vitality 是绕过放松的非压力损失，不能代替成本。gain_card 三种模式互斥：card_id、rarity、card_pool；进入节点时冻结所有候选，合法目标、容量、引用和全部收益均先预检，再原子支付和发放。升级按 type_filter 与未满级过滤，删除按 tag_filter 与牌组下限过滤。

## 6. Manifest 冻结与发布门槛

G0 文档已冻结生产目标 campus_mvp 与逐类 ID，见[登记](baselines/g0.json)及项目计划 §3.1。B01/Q01/V01/V03/V04/V10 均属目标范围；V03 与 N04 使用版本化 MVP override，完整定义保留。没有实际 data/，不能称为已启用或已加载。

G2 创建 schema、definitions、ruleset 与生产 manifest，并在副本完成 upgrade/override 合并、完整字段验证、启用引用闭包及 op 接线检查后一次发布；实际内容 hash 由规范化的最终有效定义和清单计算。adopted_sha256 仅为文档采用 hash，不能充当游戏 content_hash。test_ 清单隔离且不进入玩家入口。开发中暂缺能力可以登记 holdback，但 G8 全部本期定义必须启用且 holdback 为空。

## 7. 配置、标识与效果格式

### 7.1 唯一来源与工程状态

| 文件 | 内容 | 使用方式 |
|---|---|---|
| `src/common/game_constants.gd`（规划路径） | 类型、阶段、操作、错误码、随机流等稳定标识 | 实现后由 `GameConstants.ACTION_PLAY_CARD` 等命名常量提供 |
| `data/definitions/rulesets.json`（规划路径） | 初始值、上限、考试替代、状态系数、难度、经济 | 实现后由 ContentDB 加载、校验，并以只读配置注入规则模块 |

上述是目标来源与目标路径；当前工作区没有这些工程文件；四份上游已提供，因此不能声称配置已经落盘或已接入运行。角色与卡牌的专属数值留给各自内容定义，不重复写在 GDScript 常量中。规则改动必须先在 G0 记录批准来源，再同步契约、配置和测试。

### 7.3 配置解释规则

- `_percent`为整数百分比，100表示原值；不得把115当115倍。
- 难度配置在开局覆盖基础配置：starting_vitality同时设置当前与最大精力；DDL偏移施加一次，结果不低于minimum_ddl；压力按倍率向上取整。
- 双任务先按遭遇缩放工作量与压力并向上取整，再应用难度压力倍率并向上取整；DDL先取任务较大值加组合奖励，再应用难度偏移。此先后顺序为实现约定，屏障不参与缩放。
- 学期和休息恢复按最大精力乘百分比后向下取整。卡牌/饰品恢复修正继续按各自规则执行。
- `cooperation_exam_relax`与`scene_exam_relax`的数组索引0/1分别代表未升级/已升级。类型与耗尽标记沿用原牌。
- 奖励权重是非负相对权重，当前完整池每组总和100；过滤空品质后按剩余权重重新归一化，零权重品质不会被抽中。
- `normal_money_by_term`索引为学期编号减1；最终首领不使用nonfinal_boss_money。
- `statuses`只存已确定的层数上限与数值系数。护卫为存在标记，查重护盾为任务屏障值，不人为设置未定义上限。
- 普通初始精力在run和normal/hard中均为72，校验保持一致；后续调基础值时同步对应难度项。

### 7.4 标识约定

协议与存档存字符串值，不保存枚举数字或常量变量名。稳定值改变会影响兼容性，不能只重命名一处。

- 卡牌类型：work、strategy、ability、cooperation、scene。
- 品质：white、blue、purple、gold；基础/特殊/临时是标签，初始饰品是获取限制，不新增随机品质。
- 战斗阶段独立于页面和结局：phase=finished之后由outcome=won/lost/abandoned说明结果。
- 操作名、错误码和保存状态与[接口文档](接口文档.md)一致；所有调用方引用常量，避免散落字符串。
- schema_version当前仅描述规则配置结构；不提前假定尚未实现的存档格式和随机算法版本。

当前内容数量、目标通关率、开发周期与预算是计划/验收数据，不是游戏引擎硬上限。

### 7.5 效果 op 目录（内容 JSON 的唯一写法）

来源应为 G0 核对后的统一设计文档卡面原文；实现目标是 `src/battle/battle_engine.gd`，内容侧白名单目标是
`src/content/content_db.gd` 的 `KNOWN_OPS`。当前这些文件不存在，不能称为权威实现或已接线。实现后，**没实现的 op 不许写近似效果**：定义落不进去就返回 `CONTENT_INVALID`。引擎落点和测试证据分别登记在[战斗模块契约](战斗模块契约.md)§19及 G5/G8 输出中。

#### 7.5.1 `complete`：完成量（条件加值）

```json
{"op": "complete", "amount": 14,
 "bonus_if": {"played_definition": "K04", "scope": "round", "amount": 4}}
{"op": "complete", "amount": 12, "bonus_if": {"ddl_lte": 3, "amount": 10}}
{"op": "complete", "amount": 5, "bonus_if": {"status": "compile", "min_stacks": 1, "amount": 3}}
```

- `amount` 是基础完成量（≥ 0）。
- `bonus_if` 是可选的**同段加值**：满足条件时直接加进同一次完成结算，**不新增一段**
  （「合并为同一段」——灵感/心流/困倦与场景加值都作用在合并后的总量上，只有一条 `completion_applied` 事件）。
- 条件键（同一条 `bonus_if` 里写多个表示全部满足才加值）：
  | 键 | 语义 |
  |---|---|
  | `status` + `min_stacks` | 主角该状态层数 ≥ min_stacks（默认 1） |
  | `played_definition` + `scope` | 本回合打出过该定义（`scope` 只支持 `"round"`，可省略） |
  | `ddl_lte` | 当前战斗共享 DDL ≤ 该值 |
- `amount` ≥ 1；至少写一个条件键。
- 「本回合打出过某定义」的计数按**卡定义**记（升级前后同一张牌算同一份记录），回合作用域，跨回合清零；
  换场与回收不改变本回合的记录。

#### 7.5.2 `discard` / `draw`：弃牌与抽牌

```json
{"op": "discard", "amount": 2, "up_to": true}
{"op": "draw", "amount": 1, "per_discarded": 1}
```

- `discard` 固定张数（K03「弃 1」）：`min_count = max_count = min(amount, 手牌数)`。
- `discard.up_to: true`（K12「弃至多 2 张」）：`min_count = 0`、`max_count = min(amount, 手牌数)`——
  玩家可以选 0 张，待选照样挂起（有牌可弃时一定给选择权）。
- `draw.per_discarded`：额外抽 `per_discarded × 本张牌最近一次弃牌选择实际弃置的张数`
  （K12「抽实际弃牌数+1」= `amount: 1` + `per_discarded: 1`）。实际弃置数记在
  `ResolutionState.choice_counts["discard"]`，不是「本来打算弃几张」。

#### 7.5.3 `recall_from_discard`：从弃牌堆取回

```json
{"op": "recall_from_discard", "amount": 1, "zone_from": "discard", "zone_to": "hand"}
```

- 出牌时开一次效果内选择，候选 = **弃牌堆**（公开信息，不含抽牌堆顺序），`min_count = max_count = amount`。
- K07「无目标不可用」：弃牌堆张数 < amount 时**整张牌不可用**，预检返回 `INVALID_TARGET`
  （`error.play.no_recall_target`），不扣费、不移牌。
- 目前只支持 `zone_from=discard` / `zone_to=hand`，其它组合被内容校验拒绝。

#### 7.5.4 `remove_status`：移除状态

```json
{"op": "remove_status", "status": "extra_requirements", "target": "task", "amount": 1}
{"op": "remove_status", "category": "negative", "amount": 2}
```

- `status` 形式：按状态 id 移除指定层数（现有 K08/K60 用法）。
- `category: "negative"`（K16「净化 2 层负面」）：`《统一设计文档》§3.6` 约定——
  「净化未指定状态时由**玩家选**焦虑/拖延/困倦**之一**，移除指定层数」。候选 = 主角身上层数 > 0
  的可净化状态（`GameConstants.NEGATIVE_STATUS_IDS`），`min_count = max_count = 1`，从选中的那一个移除
  `amount` 层（层数不足就移除实际有的层数）。**不跨状态累计**（选焦虑就给焦虑，困倦原样保留）。
  一个可净化状态都没有时不挂起待选，卡牌其余部分照常结算。

#### 7.5.5 `retain_hand_card`：保留手牌

```json
{"op": "retain_hand_card", "amount": 1}
```

- K19 执行时从其他手牌选择并标记 amount 张，kind=retain；候选不足时取 min(amount, 可选张数)，无候选则不挂起。标记不是轮末任意选牌额度。
- 标记牌离手立即失效；弃牌阶段仍有效则跳过弃置，然后消费标记。未消费标记随 BattleCodec 保存。end_turn.retained_card_ids 只使用其他来源授予的普通保留额度（基础为0）。

#### 7.5.6 `unplayable`：不可打出（卡定义字段，不是 op）

```json
{"id": "X01", "type": "strategy", "rarity": null, "tags": ["special", "temporary"],
 "cost": 0, "target": "self", "exhaust": false, "unplayable": true, "effects": []}
```

- `unplayable: true` 的牌**不能打出**：预检 `validate_play` 返回 `UNPLAYABLE`
  （`error.play.unplayable`），`make_view.hand[].playable = false`，`preview.can_submit = false`。
- 它仍然是正常的战斗牌：可以被意图加进手牌/弃牌堆、回合末正常弃置、不产生被动扣费。
  `unplayable` 的牌允许 `effects: []`（其余牌必须非空，防止半张牌）。
- `rarity: null` 是「不进随机品质池」的显式标记：奖励/商店池按品质过滤
  （《游戏规则书》「基础/特殊牌不进普通随机池」），所以 `rarity: null` 的牌不会被抽到，也不需要另写排除逻辑。

#### 7.5.7 效果内选择的位置约束

需要挂起待选的效果（`discard`、`recall_from_discard`、`remove_status{category}`、`retain_hand_card`）**只能写在卡牌的
`effects` / `pre_effects` / `upgrade.effects` / `upgrade.pre_effects` 里**。写进场景 / 饰品 / 人物被动 / 单位支援会被
内容校验直接拒绝——这些触发点没有「挂起再回来」的上下文，写进去只会变成静默不生效。

#### 7.5.8 `pre_effects`：整张牌结算前的效果

```json
{"upgrade": {"pre_effects": [{"op": "relax", "amount": 2}]}}
```

- 基础定义与 `upgrade` 都可以写 `pre_effects`；在**整张牌的队列之前**执行一次
  （K52/K53「建立前获得放松」= 建立场景之前，K12 升级「获得 2 放松后再执行」）。
- 考试替代面（`independent_answer` / `fixed_exam_room`）会清空 `pre_effects`，不与替代正文叠加。

### 7.6 主动支付精力（卡定义字段 `vitality_cost`）

来源：规则书 [ENG-003]/[DMG-003]、统一设计 §5.1 K10/§8 A08，以及 RB-03/RB-04/T03/T04。主动支付后至少保留1精力，绕过放松；与伤害分开。

```json
{"id": "K10", "type": "strategy", "cost": 0, "vitality_cost": 4, "exhaust": true,
 "effects": [{"op": "gain_focus", "amount": 2}],
 "upgrade": {"vitality_cost": 3}}
```

- `cost` 仍是**专注**费用（卡面「0·策略」的那个 0）；`vitality_cost` 是**精力**代价，两张账分开算。
- 升级只覆盖 `vitality_cost` 时，`effects` 继承基础面（K10 升级=支付3、仍获得2专注）。
- **不要用 `lose_vitality` 表达主动支付**：`lose_vitality` 是伤害语义（场景 L06 轮末失去精力、
  非压力损失），可以把精力打到 0 并立即判负；主动支付必须留下 `battle.minimum_vitality_after_payment`
  层精力，不足就**不允许打出**。两者混用会让 A08「免除本战首次 K10 精力代价」无物可免。
- 预检（`validate_play`）：`精力 - vitality_cost >= minimum_vitality_after_payment`，否则
  `INSUFFICIENT_RESOURCE` / `error.play.not_enough_vitality`（`details` 带 required / available / must_keep），
  **零副作用**：不扣精力、不扣专注、不移牌、不消费随机、不加触发计数。
- 支付时点：先按减免后的费用和完整目标预检；同一步扣专注与精力、消费相应优惠，再进效果队列。规则拒绝不消费优惠或随机。
- 对外可见代价：`CostQuote = {base, added, discount, cost, sources, vitality_base, vitality_discount,
  vitality_cost}`；`preview.costs.vitality` 与 `make_view.hand[].effective_vitality_cost` 都是同一个数。
- 减免源（A08「每战首张 K10 免除精力支付」）接在 `BattleCardRules.cost_quote` 的
  `vitality_discount` 上——判定用的是**减免后**的代价；具体规则用例 ID 在 G0 追踪表冻结。

### 7.7 状态与敌方意图字段的目标校验契约

「宁可加载失败，也不要静默无效」在这一层的两条落地规则。红线：**任何引擎还不会结算的东西，
内容里写不进去**。

#### 7.7.1 允许写入的状态（待实现 `GameConstants.WIRED_STATUS_IDS`）

| 状态 | 目标结算语义（需由实现与测试证明） |
|---|---|
| inspiration | 工作牌第一段每层 +`completion_per_stack`；打出工作牌/轮末清空 |
| compile / experiment_data / citation / review | `bonus_if.status` 可读；本战保留（牌面显式读取/消耗） |
| flow | 工作第一段每层 +`completion_per_stack`；有层数时回合回能 +`focus_bonus_when_present` |
| anxiety | 玩家准备每层少回 `focus_penalty_per_stack` 专注，随后清除；可被净化 |
| procrastination | 抽牌每层少抽 `draw_penalty_per_stack`，随后清除；可被净化 |
| drowsiness | 工作牌第一段每层 -`completion_penalty_per_stack`，行动结束清除；可被净化 |
| extra_requirements | 任务每层压力 +`pressure_per_stack`；可被指定效果移除 |
| guard | 改向默认单体压力（单位） |

- 写 `gain_status` / `remove_status` / `bonus_if.status` 引用表外状态，加载必须返回 `CONTENT_INVALID`，并指出缺失的状态或接线；当前缺口数量不能在本文件预先声称。
- `guard` 的运行真相仅为不叠加 StatusState；UnitDef.guard 只初始化入场状态。查重护盾沿用任务屏障数值，但与普通屏障共存的消耗顺序 Q-007 属完整版本待决，MVP 不包含该组合。
- 新增状态时必须同时补领域结算、允许清单、ruleset/schema（如需要）和行为测试，否则内容侧不能写入。

#### 7.7.2 敌方意图的允许字段（待实现 `ContentDB.INTENT_KNOWN_FIELDS`）

| 字段 | 含义 |
|---|---|
| index | 意图序号（≥1，同阶段内唯一） |
| text_key | 文案键（界面用；引擎不读） |
| pressure / pressure_times | 单体压力 / 压力段数（默认 1） |
| pressure_all | 全体压力 |
| shield | 任务屏障 |
| work_restore | 恢复未完成量 |
| extra_requirements | 任务额外要求层数 |
| gain_status | 施加状态：`{status, stacks, target=player/unit/task}` |
| add_card | 加入特殊牌：`{card, count, zone=draw/hand/discard/exhaust}` |

- intent 或它的 `gain_status` / `add_card` 子对象出现未知键 → 加载期报错，不得静默忽略。
- 数值字段必须 ≥ 1；`gain_status.status` 走 §7.7.1 的接线闸门；`add_card.card` 走引用校验
  （必须已在清单里启用）。
- 未列出的字段必须在加载期报错，而不是静默忽略。若未来需要 `pressure_target` 等能力，先更新 schema、规则实现和测试，再扩大允许字段集合。

### 7.8 饰品 hook（`relics.json` 的 `hooks[]`）

目标来源：《统一设计文档》§8「默认被动生效；所有『首次』都有明确周期；同名唯一」；本期内容已在 G0 对照并登记；接线在 G2/G3 实现。
一个饰品可以只有 `hooks`、只有 `effects`（例如通用工作加成），或两者都有；**纯 hook 饰品允许不写 `effects`**。本次没有旧运行 JSON，禁止别名和占位 effect；未来迁移须显式登记版本。

```json
{"id": "A04", "availability": "starter", "rarity": null, "tags": ["starter"],
 "hooks": [{"at": "cost_quote", "card_type": "cooperation", "discount": 1,
            "limit": {"per": "battle", "times": 1}}]}

{"id": "A05", "rarity": "white", "tags": [],
 "hooks": [{"at": "round_start", "rounds": [3, 6], "effects": [{"op": "heal", "amount": 3}]}]}

{"id": "A07", "rarity": "blue", "tags": [],
 "hooks": [{"at": "draw", "rounds": [1], "effects": [{"op": "draw", "amount": 2}]}]}

{"id": "A08", "rarity": "white", "tags": [],
 "hooks": [{"at": "cost_quote", "definition_id": "K10", "skip_vitality_cost": true,
            "limit": {"per": "battle", "times": 1}}]}

{"id": "A11", "rarity": "white", "tags": [],
 "hooks": [{"at": "card_resolved", "card_type": "strategy",
            "limit": {"per": "round", "times": 1}, "effects": [{"op": "relax", "amount": 2}]}]}

{"id": "A15", "rarity": "white", "tags": [],
 "hooks": [{"at": "shop_price", "kinds": ["card", "relic"], "multiplier_percent": 80, "rounding": "ceil"}]}

{"id": "A18", "rarity": "white", "tags": [],
 "hooks": [{"at": "round_start", "rounds": [1, 2, 3], "effects": [{"op": "heal", "amount": 1}]}]}
```

#### 7.8.1 `at`：目标支持的五个时点

| at | 触发时机 | 该写什么 |
|---|---|---|
| `round_start` | 玩家准备（清放松、算完专注之后，场景/饰品开始效果阶段） | `rounds`（可选）+ `effects` |
| `draw` | 抽牌阶段基础抽牌之后（手牌上限在 `_draw_cards` 内裁切） | `rounds`（可选）+ `effects` |
| `card_resolved` | 一张牌结算完成（进弃牌/消耗堆、按原始实例记限次之后） | `card_type`/`definition_id`（可选）+ `limit`（可选）+ `effects` |
| `cost_quote` | 出牌费用报价（预检与预览都会调用，**不消费限次**） | `card_type`/`definition_id` + `discount` 或 `skip_vitality_cost` + `limit`（必填） |
| `shop_price` | 商店报价（界面标价与购买校验用同一个函数） | `kinds` + `multiplier_percent` + `rounding` |

- 未列出的 `at`、以及某时点用不到的字段（例如 `shop_price` 里写 `effects`）→ 加载期 `CONTENT_INVALID`，
  不静默忽略。
- `rounds` 只对 `round_start` / `draw` 有效，写的是**回合序号**（`[3, 6]` = 每战第 3、6 回合）。
  加载器验证数值为整数后规范化为 int，避免解析器的浮点表示影响整数比较。
- `card_type` 按卡面类型过滤（`work/strategy/ability/cooperation/scene`）；考试备考面只换正文、
  不换类型，所以「备考面同样适用」用类型过滤天然成立，不需要额外开关。
- `limit`：`{"per": "round" | "instance_round" | "battle", "times": N}`，走 TriggerCounter 组合键
  `(per, "relic_hook:<饰品ID>:<hook序号>", "hook")`——换场、回收、重开界面都不会刷新。
- `cost_quote` 的 `discount` 减专注费、`skip_vitality_cost` 免精力支付（必须同时写 `definition_id`，
  写清是哪张牌）；两者都要求写 `limit`（《统一设计文档》§8「所有『首次』都有明确周期」）。
- `shop_price` 只影响 `card` / `relic` 两种库存，餐食与删牌费不动（§8 A15 原文）。
  `multiplier_percent: 80` = ×0.8，`rounding: "ceil"` 向上取整。
- 同名唯一与 6 槽上限由 `RunState`（`has_relic_definition` / `equip_relic`）负责；
  A01～A04 是 `availability: starter`，只随人物获得，不进掉落池。

### 7.9 人物被动 trigger 与事件目标过滤

#### 7.9.1 `characters[].passive.trigger`（目标 schema）

```json
{"id": "P04", "starter_relic_id": "A04",
 "passive": {"id": "p04_first_cooperation_relax", "trigger": "cooperation_card_resolved",
             "count": 1, "limit": {"per": "round", "times": 1},
             "effects": [{"op": "relax", "amount": 2}]}}
```

| trigger | 语义 | 计数键 |
|---|---|---|
| `work_card_resolved` | 每回合第 N 张**工作牌**结算后（P01：N=3） | `(round, passive.id, "work_resolved")` |
| `cooperation_card_resolved` | 每回合第 N 张**合作牌**结算后（P04：N=1） | `(round, passive.id, "cooperation_resolved")` |

- `count` 是「第几张」；`limit` 是「每周期触发几次」。达到 count 且未超过 limit 才跑 `effects`。
- 未列出的 trigger → 加载期 `CONTENT_INVALID`，不得静默跳过。
- 备考面：`independent_answer` 只替换合作牌正文（`relax`），类型仍是合作 → 照样计入一次合作牌结算。

#### 7.9.2 事件效果的目标过滤与显式卡池

```json
{"option_id": "consult", "label_key": "event.v03.consult", "cost": {},
 "effects": [{"op": "gain_card", "card_pool": ["K14", "K05", "K60"],
              "selection_count": 1, "fallback_money": 20}]}

{"option_id": "drop", "label_key": "event.v03.drop", "cost": {"vitality": 5},
 "effects": [{"op": "remove_card", "tag_filter": "basic"}]}

{"option_id": "pay", "label_key": "event.v04.pay", "cost": {"vitality": 6},
 "effects": [{"op": "upgrade_card", "type_filter": "work"}]}
```

- `gain_card.card_pool`：**显式候选池**（进入事件节点时冻结，不抽随机），与 `rarity` 互斥、与 `card_id` 互斥。
  `selection_count` 目前只支持 1（本版只发 1 张，写 >1 会加载报错而不是悄悄只发一张）。
  池为空时按 `fallback_money` 折算；没有 `fallback_money` 就报 `CONTENT_INVALID`，**不扣任何成本**。
- `remove_card.tag_filter`：只能选带该 tag 的牌（`basic` / `special` / `temporary`）。
- `upgrade_card.type_filter`：只能选该类型的牌（`work/strategy/ability/cooperation/scene`）。
- 三个过滤都遵循「先校验、后提交」：选择不合法时整次选项在**扣成本之前**失败，
  精力/生活费/牌组都不变；视图的 `options[].selection_candidates` 只列出合法目标（卡实例 ID），
  没有合法目标时该选项 `enabled=false` 并在 `blocking` 里写明原因。

## 8. 精确 JSON 字段基线（G2 实现 schema）

本节是MVP及已列明基础扩展的内容文件键名唯一基线，不表示 JSON/schema 或加载器已经存在。完整版本中尚未列明的被动、持续能力及其他效果先扩充注册再加载；T15等完整用例保留规则预期，不承诺当前格式已经能表达全部完整内容。§7示例为局部字段说明，不是完整定义文件。definitions 每个文件顶层均为对应定义对象数组；manifest 为对象。每一层对象都拒绝未知键，不接受 base_cost、target_spec、upgrade_patch、enabled_ids、allowed_terms、params 等别名。表中“必填”之外只能使用该行列出的可选键；未列出的能力先修改契约再实现。整数不接受 bool、字符串或小数；资源/系数 ≥0，次数/容量/DDL ≥1，百分比使用整数，不隐式夹取非法内容。所有 ID/文案键非空，数组顺序有意义，集合字段无重复。

### 8.1 逐类键与引用

| 对象/文件 | 必填键 | 可选键与约束 |
|---|---|---|
| CardDef/cards | id,name_key,type,rarity,tags,cost,target,exhaust,effects | vitality_cost=0,unplayable=false,pre_effects=[],upgrade={},limit,art_key；type/rarity见§7.4；target=self/task/unit/all_tasks；可打牌 effects 非空，只有 unplayable=true 时才允许 effects=[]；target 与效果一致 |

| SceneDef/scenes | id,name_key | prepare_effects=[],prepare_random,modifiers={},round_end_effects=[],battle_limit,anxiety_after_every,art_key；至少一个非空行为；prepare_random 与 prepare_effects 互斥 |
| RelicDef/relics | id,name_key,availability,rarity,tags | effects=[],hooks=[],modifiers={},limit,art_key；至少一个非空行为；availability=starter/drop，starter的rarity=null，其余为§7.4品质 |
| StatusDef/statuses | id,name_key,target,stack_policy,duration_policy,dispel_policy | numeric_rule_key,art_key；target=player/unit/task，层数参数只引用 ruleset.statuses 对应键，不复制数值；guard是存在标记 |
| TaskDef/tasks | id,name_key,kind,phases | art_key；kind=normal/elite/boss；phases按顺序非空 |
| TaskPhaseDef | phase_key,work_max,intents | name_key；work_max≥1；phase_key在任务内唯一；intents见§7.7.2与§8.2 |
| EncounterDef/encounters | id,name_key,kind,members,base_ddl,terms,exam_flags | scaling,art_key；members为TaskDef ID数组，可重复；kind与任务/节点一致；terms是显式1..8集合；exam_flags只含independent_answer/fixed_exam_room |
| EventDef/events | id,name_key,terms,once_per_run,options | art_key；terms显式1..8集合，options非空并有无成本无变化出口；option_id唯一 |

| RulesetDef/rulesets | id,schema_version,run,battle,statuses,difficulty_overrides,rewards,shop | 无；id=campus_v1，schema_version=1为内容结构版本，字段见§8.6 |

正式24牌均必须有非空 upgrade patch；patch只接受 cost,vitality_cost,exhaust,target,effects,pre_effects,limit，不能改id/name/type/rarity/tags/unplayable。`cost` 与 `vitality_cost` patch 均须为非负整数。对象递归合并、数组整体替换，合并后按完整CardDef校验，基础和升级引用均检查。summon_unit 的升级加值属于效果字段，不能修改全局单位定义。

### 8.8 卡牌定义与牌组配置边界

- 每个卡牌定义 ID 对应 `data/definitions/cards.json` 中的独立 `CardDef`；费用、类型、目标、基础效果和升级 patch 都归该定义维护。卡牌专属数值不复制到 Ruleset 或 GDScript 分支中。
- 卡牌效果只组合 §8.3 已注册的 op。基础效果和升级效果通过同一 `CardDef` 的数组表达；升级数组整体替换基础数组，便于单独调整升级版。
- 牌组组成只保存卡牌定义 ID：公共初始牌组及其数量由 `Ruleset.run.common_starter_cards` 的数组表达，角色专属牌由 `CharacterDef.starter_cards` 表达。数组中的重复 ID 表示张数；改配比时只改牌组配置，不复制或改写卡牌定义。
- manifest 负责选择发布哪些定义，Ruleset/CharacterDef 只引用 ID。定义、牌组引用和 manifest 启用状态分别校验，未启用或不存在的引用拒绝发布。
- 本批 K01–K04 的 G0 来源为统一设计文档 §5.1；实现定义与逐卡核对见 G2 执行记录。新增或修改数值仍须先核对冻结来源，并同步静态验收和执行记录。

### 8.2 嵌套对象

| 对象 | 唯一允许键/约束 |
|---|---|
| limit | per,times均必填；per=round/instance_round/battle，times≥1；卡实例限次优先origin_card_id，没有origin才用战斗card_id |
| passive | id,trigger,count,limit,effects均必填；本期trigger只支持work_card_resolved/cooperation_card_resolved，count≥1，effects非空；完整P02/P03须以后扩展注册 |
| support | kind必填；kind=none时无其他键；relax/self_relax/heal用amount；cleanse_or_relax用status,amount,fallback_relax；gain_status_on_actions用status,stacks,every；目标分别主角/自身，次数按单位actions_taken，不允许选择型op |
| scene.prepare_random | options必填，为非空的效果数组列表，每项同等概率；建立及每次触发后只预抽下一结果，公开并保存；非选择型效果 |
| scene.modifiers | 可选first_work_cost_discount,work_first_segment_bonus,heal_percent；值均整数，首次减费随round计数；heal_percent是恢复倍率，不是每轮自动治疗 |
| relic.modifiers | 可选work_flat_bonus；若出现，必须配limit={per:round,times:1}，只增强首张工作牌第一段（A01），不占用card_resolved时点 |
| relic.hooks[] | at必填；按下文逐时点键集校验，不允许一个hook混用费用、收益与商店字段；数组顺序保存为effect_index |
| scaling | work_percent,pressure_percent,ddl_bonus均必填；双任务完整版本为65/65/+2，屏障不缩放；MVP单任务省略此对象 |
| IntentSpec | index,text_key必填；可选pressure,pressure_times,pressure_all,shield,work_restore,extra_requirements,gain_status,add_card；数值≥1，pressure_times依赖pressure；其他精确键见§7.7.2 |
| intent.gain_status | status,stacks,target均必填；target=player/unit/task，状态目标一致；MVP没有点名单位意图，unit目标行为须扩展注册后方可加载 |
| intent.add_card | card,count,zone均必填；zone=draw/hand/discard/exhaust；card必须启用，count≥1；按生成牌规则处理手牌上限，不触发主动弃牌 |

StatusDef.stack_policy只支持capped/presence，duration_policy只支持battle/next_prepare/next_draw/next_player_action_end/work_or_round_end/unit_departure，dispel_policy只支持negative/explicit/none。具体状态映射见§8.4；同一状态不允许作者自选相反生命周期。

hook逐时点允许键：round_start/draw为at,effects必填，rounds,limit可选；card_resolved为at,effects必填，card_type,definition_id,limit可选；cost_quote为at,limit必填，至少一个card_type/definition_id过滤器，discount或skip_vitality_cost二选一，免支付必须明确definition_id；shop_price为at,kinds,multiplier_percent,rounding必填且无其他键。effects非空且不含选择型op；rounds为不重复的正整数数组，card_type取合法卡类，definition_id必须启用，discount≥1，skip_vitality_cost只能true。shop_price.kinds为card/relic的非空无重复数组，multiplier_percent为1..100整数，rounding只支持ceil。未列出的at或不属于该时点的键一律拒绝；§7.8只提供语义与局部示例。

### 8.3 战斗 EffectSpec 白名单

全部是平铺对象 {op,该行字段}。op必填，表中方括号标可选字段。目标省略时按卡面合法目标和来源上下文解析：完成默认选定任务，无显式锁定目标的场景/单位效果才回退最前任务；主角资源默认player，单位entry/support中的self指该单位。不允许对不匹配持有者施加状态。选择型op只允许卡牌effects/pre_effects及升级后的对应数组。

| op | 该op字段 | 目标/上下文与限制 |
|---|---|---|
| complete | amount,[bonus_if],[target] | target=task/all_tasks；amount≥0，bonus_if见§7.5.1，主角工作牌第一段才读灵感/心流/困倦；非卡完成不套工作牌加值 |
| relax / heal / lose_vitality | amount,[target] | target=player/self/unit；amount≥1；heal裁上限，lose_vitality绕过放松，可归零，不作支付；场景/饰品默认player |
| gain_focus / draw | amount；draw另可选per_discarded | 主角；amount≥1，draw可在per_discarded≥1时amount=0；per_discarded只用于有前序discard的同张牌队列 |
| discard | amount,[up_to] | 主角手牌；amount≥1；up_to默认false；候选不足按实际数量，0候选不挂起 |
| recall_from_discard | amount,zone_from,zone_to | amount≥1，discard→hand；候选不足整牌不可用 |
| retain_hand_card | amount | 主角其他手牌，amount≥1；执行时选择并标记，不增加轮末任选额度 |
| gain_status | status,stacks,[target] | target=player/self/unit/task，默认player；stacks≥1；目标须符合StatusDef；guard只允许单位、按存在标记不叠加 |
| remove_status | amount及二选一：status+[target]，或category=negative | amount≥1；category形式不允许target，仅主角选一种负面；指定形式默认player，可target=task/unit/self |
| summon_unit | unit,[vitality_bonus],[cooperation_bonus] | unit引用已启用UnitDef；加值≥0，仅本次新单位；满槽走支付前换班；独立作答替代正文后不执行 |
| establish_scene | scene | scene引用已启用SceneDef；固定考场替代正文后不执行 |
| restore_work | amount,[target] | target=task，amount≥1，裁work_max；只在任务/明确敌方上下文合法，不在MVP玩家牌中使用 |
| pressure | amount,[target],[times] | target=default/all/player/unit，默认default；times≥1默认1；每段重查护卫，all/显式点名不改向；MVP敌方意图使用IntentSpec |

bonus_if只允许amount,status,min_stacks,played_definition,scope,ddl_lte；amount≥1，至少一个条件；min_stacks依赖status，scope依赖played_definition且只能round。多个条件为AND；bonus_if引用的状态/牌必须启用。单位/场景/饰品/被动不允许per_discarded或选择型op。G2 整包校验 op 名称和字段是否已注册；具体处理器接线及其行为在 G3/G4 验证，不要求 G2 逐 ID 重复行为审计。

### 8.7 Manifest 与版本覆盖

enabled仅接受character/card/relic/task/encounter/unit/scene/event/status/ruleset十种键，每种均为无重复ID数组；MVP精确集合见登记。task与encounter使用相同策划ID但各有定义对象，不是共享实体。overrides为数组，各项严格为{kind,id,scope_version,source,patch}，source={path,section}；只覆盖已启用定义。MVP只允许两项：V03的consult选项gain_card.card_pool改为K14/K05/K60；N04 EncounterDef.terms改为[1]。scope_version=campus_mvp.v1，source指向项目计划§3.1。事件options数组整体替换，必须保留未改变选项及离开出口；基础定义合法性先独立校验，有效启用引用闭包在override之后校验。

完整V03.card_pool保留K14/K24/K34，完整N04.terms保留[2,3]。不以删除未启用完整定义来实现MVP覆盖，也不因此要求把K24/K34加入MVP。ContentInfo公开{id,content_version,content_hash,ruleset_id,enabled}，hash覆盖最终有效定义和清单的规范化内容；加载失败原ContentInfo及索引不变。
