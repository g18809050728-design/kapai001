# 内容层契约

版本：v2.0｜日期：2026-10-29｜状态：新版语义目标，schema/op/API尚未实现。

## 1. 范围与版本

ContentDB负责校验只读定义并原子发布索引，不执行战斗、发奖励或修改玩家存档。当前data与加载器仍为v1；旧精确JSON白名单、示例及签名见Git 历史。本契约已移除与新版冲突的旧卡表和ruleset数值，下面是未来必须表达的语义，不能直接当作当前可加载JSON。

规则来源为[规则书](交大四年_DDL战争_游戏规则书.md)、[角色设计](角色与专属卡池重设计_v2.md)及[逐张卡表](校园卡牌设计表_v2.md)。研究Excel和artifacts中的设计JSON只供文档，不是运行包。

## 2. 目录与引用闭包

| 对象 | v2目标 |
|---|---|
| 人物 | P01～P04四人，归属、资源、被动和两张专属起手 |
| 永久卡 | R2-C-01～08及四人各01～40，合计168 |
| 衍生卡 | 唯一R2-T31；标记不可永久获得/升级/复制/变化/耗尽/删除 |
| 单位 | R2-U01～03，精力、协作、支援和护卫 |

| 遭遇 | N01～N04/Q01/B01原型，含X01遭遇负担，数值重新评估 |

每种定义ID唯一，实例在领域层生成。所有引用必须在有效启用集合内闭包；草稿与负担不混入奖励统计。四人各40种按三流派各10种、通用衔接10种组织，每人普通20/进阶15/稀有5；通用衔接仍归本人物，不是第四流派。v2不要求初始饰品关系，不启用旧物件投放。

## 3. CardDef与人物机制的必需语义

卡牌须完整表达：归属、流派、主类型、稀有度、基础费用/效果、完整升级面、标签对应的完整考试面、目标、支付与选择、生命周期、实例/同名限次、引用单位/场景。不能只给升级差值让UI推算，也不能以全局考试常量覆盖逐牌文本。

人物资源上限：编译5、数据6、引用6、稿件24、协同6，初始0、战后清零、溢出裁切。资源读写仅限所属人物；公共牌不隐含跨角色资源。被动必须有事件、周期与触发上限，不能只存描述文本。

能力从下回合起生效、同名不叠加；主动弃牌事件、实际资源消费事件和类型出牌事件区分；同一牌只产生一次合作出牌事件。x取支付瞬间快照，0消费不触发。草稿目标限制必须进入领域资格校验。

重复使用计次按战斗实例持久化并在战后清零；一次性保留须有到期窗口。召入可携带只作用于本实例的精力/协作修正，允许明确的负修正，但新精力上限必须大于0。临时补位复用R2-U02，不复制单位定义。七张合作、两张单位目标策略和一张场景均有完整基础/升级考试面，合计10个双面ID；逐牌枚举以卡表为准。

## 4. 奖励资格与随机边界

奖励/商店/事件/变化/永久生成统一使用当前人物+公共资格。基础R2-C-01/02与R2-T31排除，每人奖励可见40专属+6公共=46种。流派标签不限制同人物混搭。

ContentDB查询只返回确定的候选集合；RunService按角色设计§8的权重及固定空池回退生成候选，使用reward流并冻结。不能在内容查询或页面渲染中随机。过滤和白名单在业务入口全部适用，不仅控制显示。

## 5. 整包校验与错误

先解析schema、类型、白名单、唯一ID与数值范围，再应用明确版本覆盖，最后校验有效引用闭包、人物归属、考试面与生命周期约束。所有op和触发必须注册；未知字段/操作/引用返回可定位文件、ID与字段的错误，保留旧有效索引，禁止发布半套内容或静默忽略。

注册与静态校验通过只说明内容能被识别，不说明处理器行为正确。G2检验装包与失败回滚，G3/G4分别验证效果和获取；候选数据不能冒充生产内容。

## 6. 新版G0必须冻结的结构

资源定义的物理位置与枚举、消费与条件表达式、升级/考试面结构、能力事件、实例计数键、唯一草稿标志、场景剩余次数、人物资格查询字段、事件服务与经济配置、manifest/content/schema版本和存档映射。明确范围后再扩充实际白名单及处理器，不能由本文自动启用。

当前运行数值仍在v1 JSON；旧机器基线只用于历史复核。新版文档一致性核查脚本和报告留在本地；旧G0核验使用Git历史中的v1文档并在隔离目录执行。
