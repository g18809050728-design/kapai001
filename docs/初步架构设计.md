# 《交大四年：DDL战争》架构设计基线

版本：v3.1｜日期：2026-10-30｜状态：新版目标架构；现有代码仍为v1。

## 1. 范围与实现边界

Godot 4 / GDScript、本地单机、JSON内容、本地聚合存档。首期为第一学期四人专属卡池方案，见[项目计划](交大四年_DDL战争_项目计划书.md)。本轮只更新文档，不修改schema、方法签名、代码或存档。本文描述承接v3的目标与不变量，不能据此向当前API传入新字段。

旧精确签名、DTO和实现阶段记录保存在Git 历史，实际v1验证入口见G1～G7记录。新版先回到G0冻结，再逐阶段实现，不能使用旧通过记录证明新能力可用。

## 2. 模块与依赖

```text
UI → GameSession → RunService / BattleEngine
                   ↓           ↓
                ContentDB + RandomSource
GameSession → SnapshotCodec → SaveStore
```

| 模块 | 责任 | 边界 |
|---|---|---|
| GameSession | 唯一公共入口，命令路由、revision、状态/RNG共同发布、稳定保存 | 不把规则交给UI |
| BattleEngine | 有效卡面、费用、效果队列、资源/被动/能力、单位/场景、阶段与DDL | 只推进battle流，不写永久牌组 |
| RunService | 选人起手、地图、资格过滤、奖励、商店、事件、终局摘要 | 只推进map/reward/event流，不直接结算战斗 |
| ContentDB | 完整内容验证后原子发布只读索引 | 不在查询时随机抽卡，不解释存档兼容策略 |
| RandomSource | 版本化种子、四流状态、导出恢复与重放 | 不允许各模块自行调用系统随机改变玩法 |
| SnapshotCodec | 领域快照编码/解码及不变量 | 不读写磁盘 |
| SaveStore | 文件外壳、checksum、原子替换、备份和原样归档 | 不注入内容、不解释新卡规则 |
| UI | 展示只读View、提交命令、播放已发生事件 | 不改领域状态、不推进规则、不重抽候选 |

## 3. 数据归属

定义ID如R3-C-01表示卡种，永久实例与战斗实例各自唯一。人物叙事ID保留P01～P04，不能据此跨内容版本读取同一被动。永久卡升级保持永久实例ID，战斗卡记录来源；论文衍生没有永久来源。

RunState持有人物、精力、生活费、永久牌组、地图、冻结候选与节点记录。BattleState持有牌区、前牌及实例次数、论文两集合/进度/引用/修正/增幅/唯一发表、章节顺序及激活记录、六种任务负面、诱发次数/首次记录、检索连锁剩余抽牌、侵蚀施加批次和复合反应记录、被动/能力限次、伙伴与额外行动、场景计次和DDL。SessionState持有唯一revision、活动局/战斗、终局摘要与Profile提交标记。Profile持有长期解锁和去重结果，Settings单独保存。

## 4. 命令、待选与随机

命令携带run_id与expected_revision。先在已发布状态及RNG的深副本中校验与执行，成功整体发布；失败或取消预选不改变状态、revision、随机与优惠计数。每条接受并改变视图或待选工作区的命令递增一次revision。

效果内待选发布唯一pending_choice与只读工作区，只接受匹配确认。错误确认保留最近工作区，完成队列后才稳定；中途进程退出恢复最近成功保存的稳定快照。动画回调不能继续队列。预览与执行复用卡面/费用解析，预览不执行隐藏抽牌。

四流仍为map、battle、reward、event。种子/算法版本、内容hash与完整状态快照是重放输入；候选和已公开结果只生成一次并持久化。不可用缺省零种子补缺失输入。

## 5. v3内容承接

内容层要表达人物归属/语义牌名键、完整升级/14考试面、论文分层付款和唯一发表、章节基础/常驻及顺序、任务负面结算、伙伴额外行动、能力生效时点、实例/同名限次和有限场景；这些是待冻结的语义，当前v1 JSON白名单并不接受它们。详见[内容契约](内容层契约.md)。

所有永久牌来源共用一个资格判断；不能只在UI隐藏跨角色牌。战斗只接收该人物可用卡与遭遇注入负担。新建包版本与新卡ID，保留v1数据；旧概念映射不参与自动迁移。

## 6. 存储与失败恢复

领域发布成功与磁盘写入成功分别报告；保存失败不重做业务操作。临时文件写完校验再原子替换，保留可显式恢复的备份。当前局终局摘要先稳定写盘，再按run_id幂等合并Profile，最后清待提交标记。部分失败可重试，不能重复发奖励。

兼容性失败保留原件与诊断；损坏旧档经明确重开确认后先原样归档并校验再替换。不得静默初始化覆盖损坏档，不将归档旧局记为通关。详细责任见[存储设计](数据库与实体关系设计.md)。
