## 1. UI 设计

### 1.1 视觉语言

| 项 | 现状 |
|---|---|
| 主题 | 米白纸面 + 深青文字 + 校园插画；战斗页使用教室全景加深色遮罩 |
| 主色 | `PAPER #f4eedf`、`INK #243e4a`、`MUTED #637871`、`GREEN #78978e`、`GOLD #dda957`、`RED #bd6b64` |
| 战斗深色 | `#192f35`；悬停小窗金色边框 `#d8ba7c` |
| 字体 | 系统中文字体回退：`Microsoft YaHei UI` → `Microsoft YaHei` → `Noto Sans CJK SC`；默认 18px |
| 圆角/间距 | 控件圆角 10px，内容边距 16/12px；按钮有 normal/hover/pressed/disabled/focus 五态 |
| 舞台 | 1280×800 固定视口，`canvas_items` 拉伸；960×640 窗口实际渲染约 960×600 |
| 素材 | G6 已核对 46 张 RGB 实底插画，按比例显示，不冒充透明立绘 |

实现：`src/ui/ui_style.gd`、`src/ui/ui_page.gd`、`project.godot`。

### 1.2 页面与路由

| 页面 | 内容 |
|---|---|
| 主菜单 | 新学期、继续、设置；区分内存局与磁盘存档 |
| 选人/新局 | P01/P04 原画、初始内容、难度、十进制 seed；旧局需确认替换，取消保旧 |
| 设置 | 自动保存、当前局只读难度/seed、存档与备份状态、音效开关 |
| 地图 | 当前可达下一站 + 完整路线、节点状态、牌组/饰品详情、保存/菜单/放弃 |
| 战斗 | 独立全屏战场，见 §1.3 |
| 奖励 | 冻结候选、费用/完整效果、领取/跳过、饰品满槽替换 |
| 商店 | 商品/删牌/餐食真实效果与价格，购买后留页，主动离开 |
| 事件 | 成本/效果/候选、升级前后对比，处理完自动回地图 |
| 休息 | 恢复/升级/移除/训练四类，先选方式再显示对应面板 |
| 摘要 | 第一学期完成/失败/放弃；重开先配置再确认 |

路由入口：`src/ui/game_shell.gd`；局流程：`src/ui/page_flow.gd`。所有规则操作经 `GameShell` → `GameSession`，UI 不持有可写领域状态（ARCH-001）。

### 1.3 战斗界面

战斗由 `src/ui/battle_layout.gd`、`battle_screen.gd`、`battle_card.gd`、`battle_aim.gd` 组成：

| 区域 | 布局与行为 |
|---|---|
| 顶栏 | 标题/副标题、回合、阶段、DDL；牌组、规则、记录、速度、动画开关 |
| 左侧 | 角色肖像、精力/放松、玩家状态 chip；玩家状态悬停可看摘要 |
| 中央偏右 | 任务卡、阶段 n/m、未完成量/屏障、公开意图；任务状态挂在任务卡上 |
| 左侧协作区 | 伙伴/单位卡，显示精力、协作、放松、护卫 |
| 底部手牌 | 扇形叠放竖版卡，基础卡面 168×244；显示插画、名称、费用角标、效果、专注/精力代价 |
| 右下 | 结束回合；取消选择 |
| 底角 | 抽牌堆、弃牌堆、消耗堆；抽牌堆只显示数量 |
| 覆盖面板 | 牌组、规则、事件记录；完整牌组与饰品查看 |
| 待选 | 居中遮罩 + 卡面候选 + 固定确认；后台输入与保存锁定 |

交互细节：

- 悬停抬起约 60px、放大 1.16、置前；提示条显示摘要。
- 按住移动超过 10px 进入拖拽，显示拖动副本、弯曲瞄准线与合法目标高亮。
- 合法目标松手提交；无目标牌拖入战场松手提交；拖回手牌、非法位置、右键或 Esc 只清本地草稿。
- 点击出牌路径仍可用；数字键 1–9 选牌，无目标牌直接使用。
- `I` 打开/关闭详情；右键/`Esc` 逐层取消或关闭；待选期间屏蔽出牌快捷键。
- 动画约 0.12 秒/事件，可关闭或 ×1/×1.5/×2；动画开关 A/B 终态、日志与 RNG 一致。

### 1.4 悬停详情与名词显示（v1 G7 P0）

已实现范围：

| 层级 | 载体 | 内容 |
|---|---|---|
| L1 摘要 | 战斗悬停小窗 360×168 | 名称/类型/费用/效果首段/禁用原因；任务/单位/玩家状态摘要 |
| L2 详情 | 既有 `_info_panel` 1080×520 | 完整效果、升级差异、限制、来源 |
| L3 关键词 chip | 详情底部 | 由结构化 ID 生成，如 `effect.op`、`status_id`、`definition_id` |
| L4 词条浮层 | chip 旁 | 定义、数值、窗口、易误解、来源 |
| L5 手册 | 后续 `G`/帮助入口 | 分类、搜索、完整规则（未实现） |

- 小窗深色底 `#192f35`、金色边框 2px、12px 阴影；标题 19px、元信息 13px、正文 14px、最多 4 行。
- 摘要按目标上方/下方/左侧/右侧避让，并 clamp 在舞台内。
- 卡牌/任务/单位接入摘要后关闭原生 `tooltip_text`，避免双提示。
- 词条暂为 `src/ui/ui_glossary.gd` 常量，未迁 JSON；正文仍由 `UiContentText`/`UiStyle.describe_effects` 生成。
- 悬停只读，不改变状态、RNG 或 revision；待选/保存/切页/revision 变化关闭详情。

术语固定用法：完成量（非伤害）、屏障（非护盾）、压力（非攻击力）、精力（非生命）、专注（非费用/能量）、放松（非护甲）、DDL（非回合数）。完整术语表见[视听与名词草案 §8.5](../动作或者图片描述/视听辅助与名词显示设计_v3.md)。

### 1.5 辅助交互与无障碍（现状/目标）

- 已实现：1–9、Esc、右键、`I`；稳定 UID、preview 门控、禁用原因、焦点样式、960×600 可读。

## 2. 音效设计

### 2.1 已实现基础（v1 G7）

`src/ui/audio_manager.gd` 已接入：

| 项 | 现状 |
|---|---|
| 总线 | Master / Music / Ambience / SFX / UI；Music 70%、Ambience 50%、SFX 80%、UI 70% |
| 播放池 | UI 单播放器 + 8 个 SFX 轮换播放器 |
| 静音 | `set_muted` 静音 Master；设置页提供“音效：开启/静音” |
| 缓存 | 按 ID 缓存已加载 `AudioStream` |
| 资源缺失 | 返回 `false` 并静默，不阻塞规则、不崩溃 |
| 资源 | 18 个程序化占位 WAV，44.1kHz、16-bit、单声道；由 `tools/generate_sfx.py` 生成，无外部采样或第三方旋律 |
| 边界 | 占位音效，不是正式混音或人工视听签收；音乐未制作 |

### 2.2 18 个占位音效与事件映射

| SFX ID | 触发/用途 |
|---|---|
| `ui_hover` | 悬停/焦点 |
| `ui_click` | 点击/确认 |
| `ui_back` | 返回/取消 |
| `detail_open` | 打开详情 |
| `error` | 禁用/错误 |
| `choice` | 待选打开/确认 |
| `card_draw` | 抽牌 |
| `card_play` | 出牌 |
| `card_discard` | 弃牌 |
| `card_exhaust` | 耗尽 |
| `status` | 状态获得/变化/移除 |
| `task_hit` | 任务推进/压力/召唤/转换/自爆 |
| `task_done` | 任务完成 |
| `ddl` | DDL 减少/到期 |
| `paper` | 论文进度/引用/发表 |
| `chapter` | 章节部署/运行/退回/换序 |
| `victory` | 战斗胜利结束 |
| `defeat` | 战斗失败 |

事件映射以 `AudioManager.event_sfx()` 为准；未映射的事件（如伙伴召入/行动/撤回、部分 v3 事件）目前静默，待后续接线。

### 2.3 设计目标（P1/P2）

- 总线与响度：音乐约 -16 LUFS、真峰值 ≤ -1 dBTP；音效峰值 ≤ -3 dBFS；同时播放上限 8，同音效 40–80ms 防重复，轻微音高 ±5%。
- 音效规模：约 35–45 条战斗/UI 音效；环境音约 8 条（菜单、地图、普通战斗、精英、Boss、商店、休息、事件）。
- 角色音色：P01 马林巴/拨弦；P02 钢琴/纸张/印章；P03 预置钢琴/玻璃琴/滴管；P04 尤克里里/拍手/椅子。公共牌由角色主音色覆盖。
- 音乐：12 首候选。音频内部 P0 为 BGM-01 主菜单、02 选人、03 地图、04 普通战斗、10 胜利、11 失败；精英/Boss/事件/商店/休息/摘要为 P1/P2。
- 动态分层：战斗基础层常驻；DDL ≤3 加钟表/低音层，≤1 再加低脉冲；Boss 按阶段 n/3 加层；关键节点可 duck -6dB，不突然切断。
- 资源规格：正式资源目标 OGG Vorbis 44.1kHz；音乐立体声 160–192kbps，音效单声道 96–128kbps；逐文件登记来源、授权、循环点、响度与版本。

### 2.4 未完成与风险

- 音乐、环境音、正式音效资源、完整音量滑杆、设置持久化、正式混音与授权记录均未完成。
- 音频是否纳入 v3 本期、放在 G6 还是单列阶段，尚未由新版 G0 裁决；未裁决前不得写成基线强制项。
- 占位音效不得写入发布包；未授权素材只能临时使用。
- 静音/播放不得改变规则、RNG、revision 或存档。

需求与证据：R3-AUD-001（占位基础已实现）、R3-AUD-002（仅文字）；证据 `artifacts/verification/audio-p1-20261104-013112/`。

## 3. 地图设计

### 3.1 现行第一学期地图（v1 已实现）

`src/run/run_map.gd` 固定 6 层 8 个候选节点：

| 层 | 候选节点 | 数量 | 下一层 |
|---|---|---:|---|
| 1 | 普通作业 | 1 | 第 2 层全部 |
| 2 | 突发事件 / 普通作业 | 2 | 第 3 层全部 |
| 3 | 商店 | 1 | 第 4 层全部 |
| 4 | 普通作业 / 精英作业 | 2 | 第 5 层全部 |
| 5 | 休息 | 1 | 第 6 层全部 |
| 6 | 期末大作业（Boss） | 1 | 学期结算 |

合计 8 个候选节点，每条路线经过 6 个节点；每层最多二选一，第 4 层保留不打精英的通路。节点 ID 形如 `<run_id>|t1l4_normal`。

规则与交互：

- 只能进入相邻下一层的可达节点；不能跳层、回退或重进已完成节点（MAP-001/002、RUN-001）。
- 完成节点后自动收尾回地图；所有下一站（含唯一节点）都由玩家点击进入；商店购买后留页，由玩家主动离开。
- 地图首屏先显示当前可进入的下一站，再展示完整路线；不可达节点 disabled，点击不改 revision。
- 节点状态：已完成 / 当前 / 可进入 / 不可达；显示真实 `next_ids` 对应的下一站名称。
- 地图页提供保存进度、主菜单、放弃本学期（需确认），以及牌组/饰品详情覆盖面板。
- 节点类型文案：普通作业、精英作业、期末大作业、商店、突发事件、休息；Boss 固定三阶段，进入前提示留意精力与牌组。
- 经济基线（`rulesets.json`）：初始精力 72、生活费 60；普通奖励 3 选 1；休息恢复 25%；商店删牌 1 次、首次 60、每次 +20。

实现：`src/run/run_map.gd`、`src/ui/page_flow.gd` 的 `_render_map()`、`src/ui/game_shell.gd`；内容基线 `data/definitions/rulesets.json`、`data/manifests/campus_mvp.json`。

### 3.2 四大地图候选（v0.4，未冻结）

[四大地图复杂化设计方案](四大地图复杂化设计方案.md)把“四个大地图”定义为大一至大四四个学年地图，每张含上下两个学期区段，共 8 学期：

| 学年 | 主题 | 层数 | 候选节点 | 单学年路线 | 学年机制 | 核心决策 |
|---|---|---:|---:|---:|---|---|
| 大一 | 适应与基础 | 12 | 20 | 12 | 探索度 | 稳妥上课，还是用社团/图书馆换广度 |
| 大二 | 分流与专业 | 12 | 28 | 12 | 学习方向 | 理论/工程/竞赛/实践四选一 |
| 大三 | 冲刺与选择 | 14 | 36 | 14 | 履历值 | 保研/就业/考研三条线 |
| 大四 | 收束与毕业 | 14 | 40 | 14 | 毕设进度 + 去向 | 论文、求职、考研、出国如何收束 |

合计 124 个候选节点、完整四年单局 52 个地图层。首期仍只验证第一学期，完整四年是后续范围开关，不在本文宣称已实现。

设计约束：

- 每学期 6–7 层、每层最多 3 个候选；复杂度来自“选择质量”，不是单纯增加层数。
- 每层最多两个危险战斗节点（精英/竞赛合计），且必须提供普通替代；同层最多一个商店类节点。
- 每个学期至少一条无精英通路、一个商店、一个事件、一个休息；安全通路上至少一个 Boss 前恢复节点。
- 新节点优先替换同层普通节点，不额外加层；不改变至少两个路线决策的新节点应删除。
- 跨学期保留永久牌组、生活费、饰品和已解锁内容；战斗资源、临时负担和地图标记按规则清空或重置。
- 学期饰品奖励每学期中点 1 次（每学年 2 次）；学期结束大奖励在每个学期 Boss 后 1 次；两者都不占地图层、不改变路线长度，属范围变更候选，与现行 v3“首期不装备、不投放 v1 饰品”冲突，须新版 G0 裁决。

节点类型库：普通 N、事件 E、商店 S、精英 EL、休息 R、期末 B，以及大二起逐步出现的期中 M、图书馆 L、实验室 LAB、社团 C、导师 T、竞赛 K、实习 I、自习 P、隐藏 H、剧情 ST。当前候选表暂不放置 H/P。

学年机制：

- 大一·探索度 0–6：首次进入新节点类型 +1；阈值 2/4/6 分别解锁信息、事件选项、学年结算选项；不直接加战斗数值。
- 大二·学习方向：理论/工程/竞赛/实践四选一，每学年最多花 30 生活费改一次；只改地图与奖励倾向，不锁卡牌。
- 大三·履历值 0–6：来自实习、招聘会、竞赛、科研、导师项目；阈值 2/4/6 解锁内推、额外精英奖励、优先去向；不进入战斗数值。
- 大四·毕设进度 0–5 + 去向四选一：决定终局 Boss 变体（秋招终面/考研复试/保研答辩/留学面试），未满足条件回退延期答辩。

地图信息需求（文字级，视觉留 G7）：

- 首屏显示学年/学期、当前层、可达节点、节点类型、风险、标签、Boss 标签、学年机制数值。
- 精英考试标签至少提前一层公开；Boss 显示名称、阶段数、考试标签与学期进度。
- 隐藏节点只显示“条件未满足/已发现”，不提前展示奖励；不发现也能正常通关。
- 风险用颜色 + 图标 + 文字中至少两者表达；状态与风险不能只靠颜色。
- 假期/学年结算确认前显示将失去/获得的内容；学期饰品与大奖励显示候选、槽位、替换/转化和跳过收益。

## 4. 三者的共同约束

1. **单一写入口**：UI 只经 `GameSession` 提交命令；音效与动画只消费 `ActionResult.events` 和已发布视图，不回写状态、不推进 RNG、不改变 revision。
2. **可关闭/可降级**：动画关闭、静音、资源缺失时，关键信息仍能从静态视图、日志和 tooltip 获得；不得因表现层失败阻塞规则或存档。
3. **不重复信息**：战斗内只增强被截断或未显示的对象；奖励/商店/牌组/事件/休息已有全文，不再加悬停。
4. **阶段顺序**：P0 战斗信息层已完成（v1 G7）；P1 局流程与音频基础部分完成；P2 与 v3 视图未完成；四大地图、音频范围和 v3 UI 均待新版 G0。
5. **证据边界**：v1 G7 证据不继承给 v3；截图、退出码或资源存在都不能单独替代行为验收与人工视听/视觉签收。
