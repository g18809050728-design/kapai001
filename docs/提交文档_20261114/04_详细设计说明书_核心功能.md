# 《交大四年：DDL战争》详细设计说明书（核心功能）

文档编号：DD-01　版本：1.0　日期：2026-11-14

提交基线：DOC-20261114-1　适用模式：campus_four_year / 人物规则v3.1

## 1. DD-01 开局与生命周期

定位：src/app/game_session.gd、src/common/start_run_request.gd、src/run/run_service.gd。StartRunRequest包含character_id、difficulty、manifest_id、seed；get_setup_options只返回当前四年包、4角色和normal，内部历史包加载能力不作为创建界面选项。种子作为字符串保留，游戏启动后的主种子锁定。

start_run先验证已有局状态、请求与内容，再在候选中构建RunState和四流快照；发布新run_id、revision=0及只读视图。restart_run只有confirmed=true才可替换：验证新局→处理旧终局待提交→必要时原样归档不可读档并校验→新局稳定写盘→激活；失败保留原局。用户取消配置不调用重开提交。

起手从角色定义读取，公共4＋4＋1＋1及2专属。开战由永久实例生成战斗实例和来源映射，P02固有占首次基础抽牌位；衍生不写永久牌组。验证：TC-001～003，生命周期保护同时见DD-08。

## 2. DD-02 内容与资格

定位：src/content/content_db.gd、data/four_year/manifests/campus_four_year.json。加载流程为读取manifest→校验结构/未知键→按启用集合读取定义→校验唯一ID和schema/op→检查引用闭包→计算内容信息→一次发布索引。全部验证完成前不能替换有效目录；失败返回CONTENT_INVALID并定位文件/ID/字段。定义查询返回副本。

本次观察清单：character4、card174、relic16、task60、encounter57、unit7、scene7、event4、status16、ruleset1＝346。卡种数为160专属＋12公共＋2衍生；3种R3伙伴和2种R3场景属于设计种类，运行包7个unit和7个scene还包含历史兼容及升级独立定义，不能把两种计数互换。

永久资格判断按“当前人物或公共→排除基础/衍生/临时→来源稀有度→同次去重”执行；普通奖励75/25角色份额、70/25/5稀有度，精英35/50/15；商店3专属＋1公共，稀有度60/30/10、卡价45/75/120。费用表是既定卡牌获取规则，节点其他经济另依冻结配置/未决项处理。空稀有度按普通→进阶→稀有回退，一侧空转另一侧，全部空缩短候选。验证：TC-004～007。

## 3. DD-03 战斗输入、队列与回合

定位：src/battle/battle_engine.gd、battle_card_rules.gd、battle_phase_flow.gd。出牌链为相位/待选/实例与限次检查→有效升级/考试面→目标与费用统一解析→支付→入结算区→按正文效果序执行→人物被动/能力/事件收尾→卡牌归区→阶段/终局与稳定边界。预览复用解析与合法性检查，不公开未来抽牌或执行隐藏随机。

准备顺序固定为清放松、重置记录、自然专注与焦虑、首回合开战、已生效章节、按共同创建序能力/场景、基础抽牌与拖延、抽后效果。主动结束先清诱发/检索连锁，再按快照伙伴行动，弃非保留原手牌，然后任务阶段及轮末DDL。速查中曾重复写“轮末弃手牌”已修正；不在同一回合再弃第二遍。

任务阶段切换创建新实例，旧状态不继承、超额完成量不结转；未完成强制阶段前不能宣告胜利。终局失败优先遵守同一不可拆分效果规则；胜利后停止无关效果，论文关闭/退章等同效果清理仍完成。错误动作在副本失败后丢弃，不改公开状态。验证：TC-008～012、025。

## 4. DD-04 事务、revision与待选

定位：src/app/game_session.gd的preview_action/submit、src/common/command_context.gd、game_action.gd、action_result.gd。submit(context, action)先验证活动局、非空参数及run_id/expected_revision，再检查pending_choice门控。复制SessionState与RNG；有battle则交BattleEngine，无battle则交RunService。战斗结束还需RunService.settle_battle成功，进入战斗还需BattleEngine.begin成功。最后working.revision加1、共同替换_state并组装ActionResult。

伪流程：校验上下文 → copy_for_write → 路由/执行 → 任一步失败返回原视图 → 更新battle/run/RNG/pending → rev+1 → 原子发布 → 事件/持久化状态。该流程是既有职责描述，不改变当前方法签名。

| 调用 | 当前签名/返回 | 约束 |
|---|---|---|
| start_run | start_run(request: StartRunRequest) → ActionResult | 新run_id，revision=0 |
| restart_run | restart_run(request: StartRunRequest, confirmed: bool=false) → ActionResult | 须明确确认，候选与旧档保护 |
| get_view | get_view() → SessionView | 副本；can_save取决于战斗待选 |
| preview_action | preview_action(draft: ActionDraft) → GameResult | ActionPreview含可提交/阻塞原因与revision；不推进正式状态 |
| submit | submit(context: CommandContext, action: GameAction) → ActionResult | 旧上下文拒绝；改变会话才加1 |
| 保存/继续 | save_current()/save_and_exit()/continue_run()/restore_backup() → GameResult | 规则稳定与持久化分别诊断 |

pending_choice是唯一内存续算工作区，只接受匹配确认。非法确认不回退已公开的上一步工作区，也不继续随机。只有完成队列才允许正式快照；显式确认重开可以替换整局，普通取消保留待选。ActionResult区分accepted、view、events、pending_choice、stable、error、persistence/save_error、profile_merge/profile_error、profile_cleanup/cleanup_error，不能只看accepted就宣称磁盘已保存。验证：TC-013/014/042/043。

## 5. DD-05 四角色与考试核心算法

林序以成功出牌相邻类型识别策略→工作，机会每回合一次，回收沿用原实例费用和限次；正式目标含“可放弃且耗机会”，当前自动取回保留为Q-002。准备加值等细节沿角色设计与逐牌DSL，不能通过回手刷新计数。

许知微保存论文P/R/M、增幅、本篇已用牌名和本回合已用牌名两集合。开题和发表不记账；普通牌以主效果前快照判定新/旧名，主体后记账。引用从2→3、3→4、4→5逐层付1/2/3，付不起则抽1并停止本次后续层，不回滚已成功主效果。完成度派生为clamp(7P+6R+M,0,100)，不单独保存。发表按旧任务集合批量完成：C80为90/40、C99为109/49、C100为130/70；随后清本篇和所有章节，强制阶段不承接余量。

章节最多3槽，记录部署回合、自然/额外激活；下回合起按槽序运行，自动非出牌，手动只基础＋记账；换序/换区不刷新限次。唯一发表的战斗实例跨多次开题保留，满手取回进弃牌；临时章节复印不新增定义，不允许部署。增幅只消费在正文首个白名单数值，自动效果/完成量/费用均排除。

沈见章六负面保存在任务实例，阶段替换清除。压力按固定加值→减乏力至0→乘虚弱向下取整→护卫/放松/精力；易伤只修正工作牌直接完成量。侵蚀自然窗口清旧屏障后结算并减层；诱发以出牌前旧实例/层数快照，最多4次、行动末清除。群体施侵蚀按合格批次记1，复合反应不递归制造施加事件。P03-16同名计数与P03-19事件兑现时点保留Q-003。

唐以宁协同0～6，首合作主体后被动到账；伙伴实例记录精力/上限、入场序和正常/额外行动回合。支援→自动协作最早任务→失1续航；胜利后不扣。最多3槽，正式目标为满槽预选撤下，当前兼容replace_unit_id和缺专用UI按Q-004登记。考试先解析完整14替代面，去掉单位目标/召入流程，保留类型/费用/升级/耗尽；固定考场不禁章节。验证：TC-015～025与044。

## 6. DD-06 年度地图与节点流程

定位：src/run/annual_map_generator.gd、annual_map_generator_v1.gd、campaign_progression.gd、campaign_service.gd、route_forecast.gd。当前AnnualMapGenerator.generate(year:int, seed:String, profile:Dictionary={}, version:int=2)按版本分发；算法2在新局使用，算法1保持原派生域与结果。campaign版本1指旧固定图，campaign版本2指年度记录，不能与map算法版本混为一个字段。

年度输入为主种子、年号、算法版本、已冻结经历及显式选择；种子派生域annual-map-v{map_version}。开局只创建大一，年度奖励解决后冻结摘要，大二方向/大四去向确认后生成当年，大三直接生成。年度记录和RunState节点在同条命令中一起发布，失败不产生半图。生成不读取其他流的推进次数。

生成后校验层数、相邻层边、所有候选可达/无死路、无非法瓶颈、至少3独立节点长支线、无精英/竞赛通路及各完整路线预算。算法2起点3出口、中层3～5且至少半数4～5；每路商店至少1、恢复机会至少2，大四毕设机会至少2。52是每条四年路线层数，124仅是旧固定图候选总数；不为随机图编造固定候选数。

保存年度输入、版本、profile、节点元数据及实际next_ids；恢复按对应版本重生成并精确比对，未知或混合记录拒绝。UI读取冻结节点/边与route_forecast，只做只读三层高亮和可能/必经说明；单击预选，双击通过相同提交门控进入。大四新图毕设≥2走FY_ROUTE_去向挑战，旧图FY_FINAL保持；不足2延期。验证：TC-026～032/040。

## 7. DD-07 奖励、商店和服务事务

定位：src/run/reward_generator.gd、transaction_resolver.gd、run_node_service.gd、campaign_service.gd。奖励/库存只在首次成功生成时消耗对应流，保存offer_id、候选ID、来源节点与已处理记录。提交检查当前阶段/上下文、offer未完成、候选有效、人物资格、替换或升级目标、余额与次数，全部成功才扣款/改实例/记录幂等键。

choose_campaign通过GameSession.submit，payload白名单为offer_id、option_id、可选candidate_id与replace_relic_id。饰品选claim/convert/skip；大奖励card/upgrade/remove/resources/skip，其他服务/方向/去向按当前公开枚举；不接收UI临时报价。战斗待选与campaign稳定待选择是不同状态，后者允许保存。

四年3饰品槽、每年2次沿途奖励＋1次Boss后大奖励；新版大三/四饰品触发层3/10，旧固定图4/11，大一/二均3/9。领奖不增加节点层，必处理offer未解决不能跨年。V04认真复习按实例序升级全部符合work且未升满的永久牌，单次成本6精力；空目标在支付前禁用，多余selection_ids拒绝。节点其他服务经济及全局删牌下限冲突列Q-005，本设计不自行填新定价。验证：TC-033～039。

## 8. DD-08 编解码、文件事务与总结

定位：src/run/run_codec.gd、src/battle/battle_codec.gd、src/storage/snapshot_codec.gd、save_store.gd、profile_merge.gd。RunCodec/BattleCodec分别承担领域字段唯一映射，SnapshotCodec协调外壳版本、元数据、canonical JSON、checksum与领域解码；SaveStore只读写文件及验证外壳，不注入新内容或解释玩法。

快照保留SessionState的run/battle、revision、完整random_snapshot、terminal_summary、profile_merge_pending和有界事件日志；运行图含已公开候选/库存、campaign输入与版本。RNG算法版本、内容hash、schema、campaign/map版本分别维护；64位种子/状态按现有明确编码恢复，不用JSON浮点或默认0替代缺值。P02两集合、唯一发表/章节序、P03窗口和伙伴实例记录须逐字段保留。

文件写入链：编码稳定快照→写临时文件→完整性复核→备份/替换→返回SaveReceipt。失败报告SAVE_IO_ERROR且保留唯一有效档；正式损坏与不兼容分别诊断，continue_run只读正式档，restore_backup必须显式调用。重开前必要原件归档并验证SHA256，不静默覆盖。SaveStore缺省目录user://saves，测试执行用隔离目录。

有限旧hash兼容只接受契约已明示条件：旧内容hash 0936881b5f4eedc6cb63fb51676b1dfaa46000966d04a34aa2382f6ae7d9bbd2只在campaign.version=1、manifest/version及checksum正确、移除精确8项新增后可重算旧hash时进入后续完整解码；version2不能套用。其他未知hash拒绝，不能声称全历史自动迁移。

终局三步：先保存不可变摘要和profile_merge_pending=true；再以run_id合并Profile；最后写局清标记。中断后恢复并重试缺失步骤，不能再打战斗或再领奖。save_and_exit只有局保存、Profile合并和清标记均满足要求才清内存会话。验证：TC-014/029/034/044～048；Q-006仍保留。

## 9. DD-09 随机与可重复验证

定位：src/common/random_source.gd、random_snapshot.gd、game_constants.gd。当前常量登记算法版本1，算法标识godot_pcg32_sha256_stream_v1；以map/reward/event/battle四流隔离内容机会和战斗随机。每条规则命令仅在随机副本推进，成功与领域一起发布；preview/取消/失败/ID生成不改变正式快照。年度生成另按主种子与冻结输入确定派生，不以其他流调用次数为种子。

重放输入必须完整记录内容版本/hash、引擎/算法、seed、初始规范化状态与命令序列，保存继续控制组还要保留磁盘快照。先定义元数据归一化规则，再逐字段比较玩法及随机；发现差异记录最早分叉命令，不用只比最终精力替代。验证：TC-030/041～044。

## 10. DD-10 只读视图、设置与事件

定位：src/ui/game_shell.gd、page_flow.gd、battle_screen.gd、card_display_model.gd、src/ui/battle/battle_presentation.gd。SessionView组装screen、run/battle、pending_choice、can_save、revision、event_log与存储状态；业务对象为深副本，UI仅保留草稿与稳定UID。按钮门控使用同源ActionPreview，规则层仍做二次校验。

RuleEvent保留index/type/source_id/target_ids/data，会话补连续index及离场名称快照；日志与动画分别消费同一事实，表现键为run_id/revision/index。动画只排队、插值和展示已发生结果；最终任务表现结束才切页，关闭/跳过不改终态或RNG。卡面与详情由有效面同源构造，类别图案数字保持费用语义。

设置独立于局/随机：五路音量0～100整数与muted布尔，字号100/125/150，草稿应用后持久化；非法输入不得部分发布。验证覆盖1280×800与960×600，每个页面/字号组合需真实证据。新整体视觉、人物分层/动作仅链接UIR文字需求；P01旧候选已否决，网上候选源格式/许可/实际动作先G6，再G7具体设计。验证：TC-049～055。
