# 界面层契约（src/ui/**）

> 需求来源：《统一设计文档》§10 局流程、《接口文档》§5 RunView、《局流程契约》§2 RunStep、本文 §15。
> 本文是 **界面层（局流程页面）对外契约的唯一说明**：页面与 shell 的分工、页面跳转表、视图字段来源、
> 存档入口、战斗交接与验收口径。本文件定义界面契约；G7 已开始实现，实际验证状态见 [G7执行记录](G7界面执行记录.md)。

## 1. 模块边界

| 文件 | 职责 | 谁可以改 |
|---|---|---|
| `src/ui/ui_page.gd` | 页面基类：`render(view)` / `build_action()` / 按钮 uid / 门控落地 | ui-shell |
| `src/ui/page_*.gd` | 12 个页面（menu/setup/map/reward/shop/event/rest/battle_entry/term/ending/summary/settings） | ui-shell |
| `src/ui/game_shell.gd` | UI 适配器：路由页面、构造命令、渲染 GameSession 返回视图；不直接引用 RunService / SaveStore | ui-shell |
| `src/ui/main.gd` / `main.tscn` | 游戏入口：装配 GameSession、UI shell 与内容库 | app/ui-shell |
| `src/ui/battle_screen.gd` / `battle_screen.tscn` | 战斗界面（class BattleScreen），只消费 BattleView 并发出动作草稿 | ui-battle |
| `src/ui/battle/**` | 战斗界面组件与控制器：`battle_session.gd`、`battle_labels.gd`、`battle_style.gd` 等 | ui-battle |

铁律：

1. **页面不持有规则状态**：页面只有 `view`（只读视图）与本地展示选择；不 import RunService / BattleEngine / SaveStore / RunState / BattleState。
2. **可达性与可用性不自己算**：节点来自 `view.nodes`，可达集合来自 `view.reachable_node_ids`；
   每个规则操作按钮的可用性由 shell 调 `GameSession.preview_action` 统一门控（§2.3）。
3. **存档只走 GameSession**：界面不出现 FileAccess / DirAccess / SaveStore；写盘只能由会话层在稳定边界触发。
4. 只消费 GameSession 提供的视图与预览字段；缺字段先更新公共契约，不在界面里补规则。

## 2. UiPage 契约（页面与 shell 的唯一接口）

```gdscript
func render(view: Dictionary) -> void      # 画出来；重复调用会清空重建（按钮表也重建）
func build_action() -> Dictionary          # 最近一次点击产生的操作草稿 {"type","payload"}，无则 {}
func press(uid: String) -> bool            # 模拟鼠标：按钮不存在或 disabled 时返回 false
func action_uids() -> Array                # 登记为规则操作的按钮 uid
func action_draft(uid: String) -> Dictionary  # 该按钮当前草稿（可以是 Callable 动态算出来）
func apply_gating(results: Dictionary) -> void  # {uid: {"ok": bool, "reason": String}}
func button_disabled/button_reason/button_text/button_uids()
```

| `settings:autosave:<value>` / `settings:save` / `settings:restore_backup` / `settings:back` | 设置 | |

### 2.2 草稿类型

- 规则操作：`enter_node` / `claim_reward` / `skip_reward` / `buy_item` / `remove_card` / `choose_event` /
  `take_rest` / `leave_node` / `choose_term_option` / `choose_ending` / `abandon_run`（规则操作集合由接口契约定义）。
- 界面动作由 shell 映射到 GameSession 公开方法或本地导航：`ui.*`（menu / new_run / settings / continue / save /
  save_settings / restore_backup / start_battle / resume_battle / retry / quit）。开局使用`start_run(StartRunRequest)`，不构造未定义的`create_run`规则命令。
- **依赖页面本地选择的草稿必须是 `Callable`**：例如「休息升级哪张牌」「事件替换哪个饰品」。
  否则 shell 的门控会拿到渲染那一刻的旧选择。

### 2.3 门控（界面不得自行放行非法操作）

`GameShell._regate()` 在**每次渲染后**对页面上的每个规则操作按钮调用一次 `GameSession.preview_action`：

```
can_submit == false  ->  按钮 disabled + tooltip 写明原因（preview.blocking_errors / required_selections）
```

于是「点击不可达节点」「买不起还买」「没休息就离开」「奖励没领完就离开」在界面上**根本点不动**，
`press(uid)` 对 disabled 按钮直接返回 false（与鼠标一致）。

## 3. 页面跳转表

页面由 GameSession 发布的 `view.screen` 决定，局外页面由 shell 的 `_ui_screen` 覆盖：

| screen | 页面 | 触发条件（规则层） |
|---|---|---|
| `menu` | UiMenuPage | shell 处于菜单（无局或从局内返回） |
| `setup` | UiSetupPage | shell 处于选人（`ui.new_run`） |
| `settings` | UiSettingsPage | shell 处于设置（`ui.settings`） |
| `map` | UiMapPage | 没有待决界面（节点可进入 / 节点已结算完） |
| `battle` | UiBattleEntryPage | 当前节点是未结算的战斗节点 |
| `reward` | UiRewardPage | `run.pending_reward != null`（含已领完、等待离开） |
| `shop` | UiShopPage | 当前节点是 active 的商店 |
| `event` | UiEventPage | 当前节点是 active 的事件 |
| `rest` | UiRestPage | 当前节点是 active 的休息 |
| `term` | UiTermPage | `run.settlement != null 且未完成` |
| `ending` | UiEndingPage | 完整版本run.awaiting_ending=true（MVP不进入） |
| `summary` | UiSummaryPage | `run.outcome` 非空（胜利/失败/放弃） |

`ui.menu` 会把 `_ui_screen` 置为 `menu`（局内状态保留在 session 里，可再 `ui.continue` 回局内）；
`ui.save` 走 §12；`map:abandon` 是二次确认（第一次是本地按钮，第二次才发 `abandon_run(confirmed=true)`）。
## 4. 局外页面视图（shell 组装）

### 4.1 主菜单 `menu`

| 字段 | 来源 |
|---|---|
| `has_active_session` / `has_save` / `save_meta` / `save_error` | GameSession 提供的内存局与磁盘存档状态，分别展示，不混为一个布尔值 |
| `profile` | GameSession 提供的只读 profile view |

「继续」优先返回当前内存局；只有无内存局时才调用`GameSession.continue_run()`读取存档。仅当`has_active_session=false`且`has_save=false`时禁用。保存失败但内存局仍存在时，菜单必须允许继续该局并显示未保存状态。

### 4.2 选人 `setup`

`characters: [{id, name_key, starter_cards, starter_relic_id, locked, reason}]`。
`locked` 与 `difficulties` 由 GameSession 提供；页面不试跑创建新局，也不自行重算解锁规则。
开局输入由shell组装为`StartRunRequest = {character_id,difficulty,manifest_id,seed}`并调用`GameSession.start_run()`；`manifest_id`只来自已批准的生产清单选择，不由页面猜测或写死。seed为十进制整数字符串，原样交给规则层。若返回`accepted=true`但`persistence=failed`，仍进入内存局并显示保存失败，可从稳定边界重试。

### 4.3 设置 `settings`

`settings: {autosave}`、`save_meta`、`backup_meta`由GameSession提供；当前局seed/difficulty只读且开局锁定，不能通过设置页改写。未来音量/显示/输入字段先更新SettingsPatch再实现。
`ui.save_settings` 经 GameSession 更新并保存设置；界面不直接调用 SnapshotCodec 或 SaveStore。
`autosave=false` 时局内不自动写进度，手动保存仍受稳定边界约束。

## 5. 地图页（RunView 消费）

- 只画 `view.nodes`（冻结8节点，第2/4层二选一分支，见基线登记）；`next_ids` 原样展示，不自己连线。
- 按钮文案带类型名（普通作业 / 精英作业 / 期末大作业 / 商店 / 突发事件 / 休息）与状态（可进入 / 当前 / 已完成 / 不可达）。
- 可达性完全由 `GameSession.preview_action(enter_node)` 门控：不在 `reachable_node_ids` 里的节点按钮是 disabled。

## 6. 奖励页

视图 `view.pending_reward`（RunService 的 offer 视图：`items[].candidates` 已冻结）。
一次点击 = 一条 `claim_reward`/`skip_reward`；饰品槽满（`relics.size() >= relic_slots`）时先选要替换的旧饰品，
没选之前 `preview_action` 会要求 `replace_relic_id`，领取按钮自动禁用。
`offer.complete == true` 才出现「处理完毕，继续」（`leave_node`）。

## 7. 商店页

视图 `view.shop`：`stocks[]`（sold/price 冻结）、`removal{available,used,max,price,money,minimum_deck_size,deck_size}`。
购买与删牌各是一次点击一条草稿；买不起 / 已卖出 / 删牌次数用完 / 牌组触底都由门控禁用。

## 8. 事件页（含真事件事件池）

视图 `view.event.options[]` 带 `cost / effects / candidates / enabled / blocking`。
页面按 `effects[].op` **决定画哪种选择控件**（`upgrade_card|remove_card` → 逐张牌；`gain_card|gain_relic`
无显式 ID 且候选 >1 → 逐候选；`gain_relic` 且槽满 → 先选替换目标）。这是展示逻辑，不是规则判断：
提交时 `preview_action(choose_event)` 会整项校验（成本 + 全部收益），不合法就禁用。
事件必须先选一项才能离开：未解决时 `event:leave` 被 `preview_action(leave_node)` 禁用。

## 9. 休息页

视图 `view.rest.options[]`（四选一，`enabled/blocking/needs_card`）。带目标的选项把整副牌都画成按钮，
非法目标（已满级 / 非负担 / 非合作牌）由 `preview_action(take_rest)` 禁用并给出原因；
`rest:leave` 在「还没休息」时由 `preview_action` 禁用。

## 10. 战斗入口与战斗界面交接

战斗规则仍由 `GameSession` 协调。进入战斗节点时，会话层调用 `RunService` 准备战斗输入，由自身持有的 `BattleEngine` 创建并推进 `BattleState`；战斗界面不创建或持有 `BattleEngine`、`BattleState`、`RandomSource` 或内容清单。

| 方向 | 契约 |
|---|---|
| 会话层 → 战斗界面 | `SessionView` 包含当前 `BattleView`；开始、继续和重绘均从最新 view 渲染，不传递可写领域对象 |
| 战斗界面 → 会话层 | 牌、目标、待选确认、结束回合等操作构造 `GameAction`，经 `GameShell` 转交 `GameSession.submit(context, action)` |
| 会话层 → 局流程 | 只有战斗终局由 `GameSession` 将 `BattleOutcome` 交给 `RunService.settle_battle`；战斗界面不直接结算局状态 |
| 会话层 → 存档 | BattleState 与 battle 随机流只由会话层合并进 SessionState；UI 不回填状态或随机快照 |

战斗节点进入、读档继续、规则待选确认和终局都沿用相同的命令与 view 流程。恢复战斗時，`GameSession` 先按快照的 `manifest_id`、内容 hash 和 ruleset 校验，再以持久化的 BattleState 与 battle 随机流继续；不兼容时明确报错，不在 UI 层换清单或重建默认战斗。

战斗 UI 的动作门控、`pending_choice` 锁、预览和动画不变性见[界面层契约 §15](界面层契约.md)。实现验收至少覆盖：真实会话进入战斗并结算、稳定边界存档后恢复战斗且命令序列结果一致、伪造/过期动作由会话层拒绝、动画开关不改变规则终态。具体测试路径在 G1 工程骨架建立后登记；不得把建议路径写成已运行证据。

## 11. 学期结算 / 结局 / 摘要

- 学期结算（完整版本中间学期；MVP终点不进入）：`view.settlement`（步骤顺序、可跳过、当前步骤）；`direction_reward` → 逐候选 + 跳过；
  `career_track` → 三轨；完成后规则层自动进入下一学期（界面不需要「下一学期」按钮）。
- 结局（完整版本awaiting_ending）：`view.eligible_endings` 逐项一个按钮，发 `choose_ending`。
- 摘要（MVP胜利显示“第一学期完成”，失败/放弃亦直接总结）：`view.run_summary`（result/reason/stats/unlocked_ids）；本页只发 `ui.retry` / `ui.menu`。
  **失败重开**先回选人页复用人物与难度草稿，seed由玩家或G0批准的随机种子策略决定；不得擅自对十进制种子加1。旧局的待合并Profile摘要未完成时禁止创建新局。

## 12. 存档入口（UI只走 GameSession）

| 入口 | 行为 |
|---|---|
| 主菜单「继续」 | 有内存局时直接返回该局视图；否则`GameSession.continue_run()`加载正式档并校验；正式档无效时可显式选择恢复有效备份，显示恢复来源与错误，不静默切换 |
| 新局 | 新局创建成功时revision为0且进入稳定状态；`autosave=true`时尝试保存该稳定快照，失败时保留内存局并报告 |
| 稳定提交 | 领域命令完整执行、随机状态合并、revision 更新并发布稳定 view 后，`autosave=true` 才触发保存 |
| 待选续算 | `pending_choice` 存在时，`save_current()` 与 `save_and_exit()` 返回 `CHOICE_PENDING`，不写半成品、不释放会话；用户完成选择后再提交保存 |
| 终局 | 终局本身是稳定状态；保存terminal_summary与profile_merge_pending=true后按存档契约幂等合并Profile，再清除待合并标记。autosave关闭时仅在显式保存或save-and-exit时启动该流程 |
| 设置 | 经 `GameSession.update_settings()` 校验并保存，不改变局 revision |
| 恢复备份 | 用户选择后由会话层校验并载入；正式档保持不变，后续成功保存才按 SaveStore 原子替换规则更新 |

自动保存只发生在稳定提交之后，不代表每个 UI 命令都可持久化。手动保存也只能保存稳定快照；关闭进程或系统中断导致内存中的待选续算丢失时，下次启动恢复最近一次有效稳定快照。战斗中稳定边界（例如完整命令结算后）可以保存完整 BattleState 与随机流；只有效果续算处于 `pending_choice` 时才禁止保存。普通页面上的待处理玩家决策（奖励、商店、事件等）若已是稳定 RunState，可以正常保存。

UI必须分别显示当前局保存、Profile合并和标记清理结果：`persistence=saved`且`profile_merge=failed/pending`时显示“本局已保存，长期进度待更新”；`profile_merge=merged`且`profile_cleanup=failed`时显示“长期进度已更新，收尾保存待重试”；只有Profile写入成功后才显示永久解锁。任何步骤未完成时提供重试保存，`save_and_exit()`保留会话并报告原因。读取存档恢复时也要继续待合并步骤；不能只依据当前局写盘成功就提示“全部保存完成”。

## 13. 测试与验证

G0–G5 已完成[UI 图片与动作需求](../动作或者图片描述/README.md)登记，G6 的 46 张选定图已交接。当前 G7 的布局、动作顺序、禁用反馈与可观察验收见[G7设计](../动作或者图片描述/G7界面与交互设计.md)，运行结果统一见[G7记录](G7界面执行记录.md)。新增页面和可见状态同步补入台账。

| 套件 | 覆盖 |
|---|---|
| `tests/run_ui_tests.gd` | G7 统一入口，收集两个真实 UI 套件的失败并返回非零退出码 |
| `tests/suites/test_ui_shell_pages.gd` | MVP 页面、菜单/设置与真实 GameSession/BattleEngine 学期路线，覆盖商店/休息、稳定保存继续、失败重开、按钮门控与重绘；生产开局与首场战斗交接。完整生产路线归 G8 |

口径：

- `press(uid)` 走真实信号路径，等价鼠标点击；断言必须带按钮 uid 与禁用原因，失败时可直接定位。
- 「界面不得放行非法操作」用**结构**证明：非法按钮本身就 disabled，且 `press` 返回 false。
- UI 集成测试的完整路线必须通过 GameSession 和真实战斗命令走到结算；若数值平衡导致固定 seed 路线不可达，应修正批准的测试条件或内容。直接构造 `BattleOutcome` 调 `settle_battle` 只能用于 RunService 单元测试，不能作为 UI 端到端通过证据。

| `src/ui/battle/battle_log_panel.gd` | 结算日志（每行都来自引擎事件或 BattleOutcome） |
| `src/ui/battle/battle_choice_panel.gd` | 效果内选择面板（K03 抽 2 弃 1） |
| `src/ui/battle/battle_deck_viewer.gd` | 牌堆查看弹窗 |
| `src/ui/battle/battle_rules_dialog.gd` | 规则说明弹窗 |
| `src/ui/battle/battle_labels.gd` / `battle_style.gd` | 展示层文案表 / 配色与控件工厂 |

### 15.2 页面入口（只通过 GameSession）

```gdscript
var screen = preload("res://src/ui/battle_screen.tscn").instantiate()
add_child(screen)
screen.action_requested.connect(game_shell.submit_action)
screen.render(session.get_view().battle)
```

| 成员 | 说明 |
|---|---|
| `render(view)` | 消费 GameSession 提供的 BattleView；不载入内容清单，不调用 `BattleEngine` |
| `signal action_requested(action)` | 将 `GameAction` 草稿交给 GameShell/GameSession；命令携带当前 run_id 与 revision |
| `signal local_selection_changed(selection)` | 只报告未提交的目标/换班等 UI 选择；取消只清除本地选择 |
| `is_locked()` | 由最新 `view.pending_choice` 派生控件锁定状态 |
| `view_updated(view)` | 仅由会话层的新视图更新；UI 不构造或合并规则状态 |

### 15.3 界面只消费视图（不得重算规则）

界面只读两类会话层提供的数据：

1. `GameSession.get_view()` 中的 `BattleView`（字段见《战斗模块契约》§8）；
2. `GameSession.preview_action(draft)` 的 `can_submit` / `required_selections` / `blocking_errors`。

卡面费用取 `hand[].effective_cost`，可出性取 `hand[].playable`，效果数值取 `hand[].face.effects`
（已含升级与考试替代面）。界面对任何非法操作只显示 `blocking_errors` 的 message_key，
不自己判断合法性。

日志只消费SessionView.event_log及事件自带source_label/target_labels文本快照；按run_id/revision/index防重，不从当前手牌、任务或单位反查已离场对象名称。当前对象进度仍由BattleView提供。

### 15.4 动作协议

界面内部动作工厂生成 `{type, payload}` 草稿；共享 `build_action()` 无参返回最近一次草稿，操作协议为：

| type | payload | 界面触发点 |
|---|---|---|
| `play_card` | `card_instance_id`、`target_ids`、`replace_unit_id`（无则 null） | 点手牌 → （需要时点任务 / 单位）→ 自动提交 |
| `confirm_choice` | `choice_id`、`selected_ids` | 待选面板的确认按钮 |
| `set_ally_target` | `unit_instance_id`、`task_instance_id` | 点单位 → 点任务 |
| `end_turn` | `retained_card_ids` | 结束回合按钮 |

提交路径唯一：`BattleScreen` → `GameShell` → `GameSession.submit(context, action)` → BattleEngine。
只有会话层可调用规则写入口并发布新状态；界面没有任何一处直接访问 BattleState、随机源、磁盘或领域引擎。

草稿中的实例字段取值来自视图的 `card_id` / `unit_id` / `task_id`，命令键名使用[接口文档 §3.1](接口文档.md)规定的完整名称。

### 15.5 效果内选择（pending_choice）期间的锁

`view.pending_choice != null` 时：

- `build_action` 对除 `confirm_choice` 外的一切类型返回**空字典**（调用方拿不到可提交的动作）；
- 手牌、任务、单位、结束回合、牌堆、规则说明、动画开关、取消选择全部禁用；
- 非法确认（数量不符 / 非候选 / 重复）由引擎拒绝，界面保持待选并显示原因；
- 待选的候选就是引擎给的 `pending_choice.candidates`，界面不自己凑候选。

锁快照可用 `lock_snapshot()` 断言。

### 15.6 动画：只影响观看节奏

`BattleEventAnimator` 只做一件事：把会话层发布的 `ActionResult.events` 按时间播出来（`base_delay` / `speed_scale`）。
它不持有也不需要 BattleState，因此：

- 关闭动画（`animation_enabled = false`）= 事件立即播完；
- 加速（`speed_scale` 变大）= 同样的事件更快播完；
- 两者都不改变视图、日志、结局或随机快照，`test_ui_battle_choice.gd` 用「两组输入序列 + 最终视图 + 日志 + 结局逐项相等」钉死这点。
- 顶栏「动画：开/关」按钮只切 `animation_enabled`；待选期间该按钮同样被锁。

日志不走动画：结算日志在每次 `render(view)` 时整体刷新，避免测试与读档依赖播放进度。

动画和日志共同消费 `RuleEvent = {index, type, source_id, target_ids, data}`；效果载荷读取 `data`，不要求顶层另存同名字段。事件枚举、逐类载荷、标签快照、有界日志与消费键已在[接口§8](接口文档.md)冻结；G1实现类型，G7验证表现。动画消费GameSession合并后的ActionResult.events，不直接接收内部BattleStep。

战斗画面、交互和事件表现已关联[需求台账](../动作或者图片描述/需求台账.md)中的 `VIS-013`、`ACT-002`、`ACT-003`，具体布局、事件提示、时序、关闭/加速表现和异常反馈见[G7 详细设计](../动作或者图片描述/G7界面与交互设计.md)。G0–G5 仅登记需求，G6 资源交接后才实施 G7；实际页面测试、生产 K03 待选、动画开关一致性及截图证据见[G7 记录](G7界面执行记录.md)。表现回调不得推进规则。

### 15.7 牌堆查看的公平性

- 抽牌堆：**只显示数量**，不展示内容与顺序（`draw_pile_card_ids()` 恒为空，供测试钉死）；
- 弃牌堆 / 消耗堆：内容来自 `BattleView.zones_public`（公开信息），卡面与 `hand[]` 同构；
- `draw` 与 `resolving` 不进入 `zones_public`；
- 弹窗不洗牌、不改状态；待选期间不允许打开。

### 15.8 实际验收入口

`tests/suites/test_ui_shell_pages.gd`：通过 GameShell 和隔离的真实 GameSession 走页面与战斗闭环；测试 fixture 与玩家生产入口分离。

`tests/suites/test_ui_battle_choice.gd`：覆盖生产 K03 待选锁与确认、K14 目标预选与取消、公开牌堆、非出牌 preview 及动画不变性。单位槽换班等未在本轮生产 UI 用例逐项穷举，规则层覆盖见 G3。

测试使用锁定 Godot 版本的 headless 入口；启动命令见 README，实际通过结果与覆盖边界见[G7 记录](G7界面执行记录.md)。

### 15.9 内容清单边界

生产清单只由 GameSession 在开局时加载并绑定到当前会话。战斗界面不自行加载清单、不设默认清单，也不允许加载失败后回退到另一份清单。

战斗 UI 接收的 BattleView 已由当前会话 catalog 生成。内容版本不匹配或引用无效时由 GameSession/规则层明确报错；不得让 UI 改用 `battle_mvp`、测试 fixture 或另一版本 catalog 继续运行。测试可单独以 fixture 创建测试会话，但 fixture 加载入口必须与玩家入口隔离。

#### 15.9.1 代价显示：专注与精力

规则视图应提供 `effective_cost` 与 `effective_vitality_cost`；预览的成本字段必须与展示值来自同一解析结果。界面据此显示：

- 卡面必须区分专注费用（`effective_cost`）与精力代价（`effective_vitality_cost`），数值和含义不能混淆；位置、颜色、字号及零值呈现见[G7 详细设计](../动作或者图片描述/G7界面与交互设计.md)；
- 提示词同时列出两种代价，并注明精力是「主动支付，绕过放松」；
- 精力不足时由 `preview` / `apply` 拒绝，界面显示「精力不足：需要 N，且支付后至少留 must_keep」。

界面**不自己判断**精力够不够（那要读 `minimum_vitality_after_payment` 规则）：`hand[].playable`由规则层汇总资源、限次、不可打出与可直接判断的门槛，需要目标时最终以preview.can_submit为准。K19执行时使用kind=retain选择另一张手牌，end_turn只提交普通保留额度选择，两者不混用。


### 15.10 边界（不做什么）

- 不改战斗、存储或局流程规则语义；视图缺字段时通过契约变更补齐并添加对应验收；
- 不实现局流程页面（主菜单 / 地图 / 奖励 / 商店等属 `src/ui/page_*.gd`，由 ui-shell 负责）；
- `project.godot` 的 `main_scene` 仍由 ui-shell 的入口决定；战斗页面只被实例化。


## 16. G7 当前实现适配（2026-10-15）

详细视觉/动作设计见 [G7设计](../动作或者图片描述/G7界面与交互设计.md)。MVP 采用 `page_flow.gd` 按 screen 统一实现局流程页面，入口仍为 `src/app/main.tscn`；战斗入口整合到 `BattleScreen`，进入节点即展示已创建的真实战斗。`term/ending` 属完整版本，不以不可达页面凑数。页面测试入口为 `tests/run_ui_tests.gd`。

- `GameShell` 对每个规则草稿统一 preview 门控。会话的非出牌战斗预览复用 BattleEngine.apply 的状态/RNG副本，只返回合法性，不发布模拟结果或未来抽牌；正式状态/revision/RNG 不变。
- 手牌及公开牌堆保留 `effective_card` 并提供 `face`、`effective_cost`、`effective_vitality_cost`，费用由引擎 calculate_cost 报价。卡片预选允许补目标，最终提交仍以 preview 为准。
- `UiPage.build_action()` 无参返回最近草稿；BattleScreen 用内部动作工厂，避免覆盖成不同签名。local_selection_changed 触发 shell 重新门控。
- `option_id=leave` 的事件选项使用 `event:option:leave`，与离开节点 `event:leave` 区分；`settings:apply` 保存设置，`settings:save` 手动保存当前学期。
- 战斗 UID 为 `card:<id>`、`task:<id>`、`unit:<id>`、`choice:<id>`、`choice:confirm`、`battle:end_turn/cancel/animation/speed/draw/discard/exhaust/rules/save/menu`。日志整体刷新，动画只消费发布事件，不驱动规则。
- 战斗展示合并为 `battle_screen.gd` 与 `battle/battle_event_animator.gd`，组件清单中其余文件是可拆分目标，当前不创建空壳。
